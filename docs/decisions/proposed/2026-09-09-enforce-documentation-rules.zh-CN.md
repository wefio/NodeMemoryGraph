# 让已写明的文档规则真正生效

[English](2026-09-09-enforce-documentation-rules.md)

**Status:** proposed
**Date:** 2026-09-09

## 问题

`skills/doc-maintenance/SKILL.md` **已经**带有 slop 清单，而且**已经**写明本提案要
执行的两条：「implemented 决策或笔记中的规格腔：should / Proposal / Plan /
Acceptance criteria」，以及「当源码或生成器才是权威时，手抄的清单、JSDoc 或测试/
包清单」。两条都没有任何检查，而仓库两条都违反了。

- 三条 `implemented/` 决策带着 `## Acceptance criteria`：可追溯性矩阵、术语索引、
  chaos job 迁移。
- `docs/design/ci-cd-and-quality.md` 的 work order 字段列表里还写着 `禁止项`
  （已删除的 `invariants` 字段）与 `预期产物`（已删除的 `expectedArtifacts`
  字段），而这两个字段已经变更两轮。它在 `c7b450c` 里被手工改正；没有任何检查会
  发现它。
- `docs/decisions/README.md` 重述了每条决策的标题和未完成项。往 `proposed/` 放一条
  探针决策后，`docs:check` 没有报「索引没有列出它」，因此这份副本可以静默地与它所
  复制的决策不一致。

只存在于散文里的规则，是**关于仓库的声明**，不是仓库的属性。缺口不是少一份清单，
而是那份清单**没有被执行**。

## 提案

`docs:check` 执行清单里两条可机械检查的条目。

- 当 `implemented/` 决策出现 `## Proposal`、`## Plan`、`## Acceptance criteria`
  或 `## Risks` 时，检查失败。未完成或未验证的项移到 `## Deferred`，即
  [显式声明「没验证什么」](2026-09-09-declare-what-was-not-verified.zh-CN.md)
  所指向的那一节。本次改动迁移那三条违规决策。
- `docs/decisions/README.md` 删掉三份条目清单，保留生命周期契约。生命周期目录树
  就是清单；仓库搜索、`agent:context` 路由和术语锚点负责发现。`docs:check` 打印
  一行决策摘要——有多少条 implemented、其中多少条带着非空的 `## Deferred`——使清单
  那行「为什么」原本携带的信号得以保留，而无需维护一份副本。

清单里其余的条目继续只靠审阅：「叙述历史」「手抄清单」「推理过程」「强调通胀」都是
关于散文的判断；用 grep 去抓它们，也会抓到合法的写法。

## 考虑过的替代方案

**保留手写清单，并给它的完整性加门禁。** 这道门禁只是为了保护一份副本。清单重述了
每条决策的标题和它的未完成项，而这两者都归决策文件所有；它那行「为什么」还要再用
中英各写一遍。给副本加门禁，只是让副本变得可靠，而不是删掉副本。

**用生成代替手写。** DeepSeek Harness 正是这么做的，并在约两周后把它删掉
（commit `4779d04af8`，净 -490/+210）：删除了 `.agents/notes/INDEX.md`、一个 130 行
生成器、一个 36 行渲染器和对应的 npm script，并把引入索引的那条决策从
`implemented/` 移到 `rejected/`。它的理由原样适用——索引重复了路径已经编码的事实
（生命周期、日期、标题）；每个新增决策的分支都会重写它；生成器、命令和新鲜度检查
都是在为一个「目录树 + 搜索已经覆盖」的发现路径付维护成本。它同样否决了「按需
生成、不入库」的变体。在这里生成索引还会额外引入路径唯一不携带的字段——这条决策
有没有未完成项——而 `rg -l '^## Deferred'` 已经能回答。

**只禁标题、不提供 `## Deferred`。** 只禁不立，会把内容挤进 `## Consequences`，
读者在那里无法区分「我们接受了这个代价」与「我们还没做」。具名小节把两者分开，
而这正是本次改动的要点。

**增加一张带「不该放什么」列的层级表。** 这是 DeepSeek Harness 的形态。同一个
skill 的 Workflow 第 3 步已经把每类事实分配到各自的界面；缺的那一列是阅读辅助，
不是规则，因此这里不加。

**把整份清单机械化。** 只有标题集合与重复清单可机械检查，而其中只有标题集合能在
不误报的前提下检查。

**给决策树加分类轴。** DeepSeek Harness 把生命周期与分类编码进路径
（`{lifecycle}/{class}/`）。NMG 只有 21 条决策，为获得一个筛选维度而重命名全部
文件收益很小。等浏览这棵树不再够用时再议。

## 验收标准

- 当 `implemented/` 决策带有提案期标题时 `docs:check` 失败，且每个被禁标题在
  `tests/scripts/verify-docs.test.ts` 中都有测试。
- `docs:check` 打印决策摘要行，并把带非空 `## Deferred` 的决策计为 open，且有测试。
- 三条被迁移的决策在两种语言里都把未完成项记在 `## Deferred` 之下。
- `docs/decisions/README.md` 不再逐条列出决策，同时仍写明生命周期契约。
- `npm run docs:check` 报 0 错误、且不新增警告。

## 风险

**机械遵从。** 把 `## Acceptance criteria` 改名为 `## Deferred` 就能满足门禁，而
不必移动内容的含义。迁移在本次改动中审阅；门禁只负责不让这个标题回来。

**发现能力。** 删掉清单意味着「有哪些决策？」由目录树和搜索来回答。摘要行与
README 指向目录树的说明是补偿；如果浏览这棵树不再够用，分类轴那个替代方案就该
重新考虑。

**未被执行的剩余部分。** 清单里还有三条只靠散文。这是诚实的状态，不是已解决的
问题：设计文档那处缺陷是靠阅读发现的，以后还会如此。

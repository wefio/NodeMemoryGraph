# AG 可见内容瘦身、共享信息视图与持续状态协议

[English](2026-10-06-ag-state-transitions.md) · [术语](2026-10-06-ag-state-transitions.terms.yaml)

**Status:** proposed
**Relates to:** [Session AG 决策](../implemented/2026-08-29-session-active-graph-runtime.zh-CN.md)、[AG 运行时](../../design/session-active-graph-runtime-design.md)、[任务连续性](../../design/task-unit-semantics/task-continuity.md#长任务的连续性与任务视图-1)

[共享信息输出基础](../implemented/2026-10-07-shared-information-output.zh-CN.md)已实施；剩余状态/输入协议仍为提案，切片 A 尚未全部完成。

## Problem

用户明确偏好：先给现有 AG 显示的内容瘦身，再增加类似 SKILL.state 的协议/规则，持续维护和显示当前状态；动机是过多注入内容会快速耗尽上下文。此处“显示”指模型可见内容，不仅是终端 UI。用户认可 AG 与黑板共用类型化信息视图和显式输出协议，但不认可复用 Pi codemode 编排作为方案依赖，要求保留通用性。具体线上字段、更新时机与预算仍需验证，整体机制尚未实施。

AG 的定位沿用 [design.md Definition](../../design/design.md#definition) 与 [Session AG update and projection revisions](../../design/design/active-graph-activation-and-consolidation/session-ag-and-projection-revisions.md#session-ag-update-and-projection-revisions-1)：私有、会话所属、内存驻留的工作图，不是第三个权威记忆库。当前问题是其对外显示成本，不是图里所有信息都必须删除。

相关实现边界：

- [`renderSessionActiveGraphSurface()`](../../../src/integration/agent-surface.ts) 显示临时 item 的截断列表；列表不是持续维护的当前状态。
- 同文件的候选显示携带 ID、node、type、预览等信息；模板还会显示格式说明与下一步提示。需要按用途精简，不把所有字段视为每次必需。
- [`composeNmgContextMessage()`](../../../.pi/extensions/nmg/index.ts) 组合 recall、runtime AG、nudges 和 status；动态内容作为持久会话消息追加。缓存命中可降低重复计费，但不消除上下文占用。
- [`observe()`](../../../src/core/session-active-graph.ts) 按内容哈希去重，变化后的 statement 仍是另一条 item。仅加入“持续维护”的提示，不能让该接口自动具有替换语义。

## Proposal

### 1. 范围：轻量显示协议，不先建设执行状态引擎

分开推进两项工作：

1. **瘦身**：缩小每次进入模型的 AG/记忆辅助内容，去掉重复、不相关与无需展开的部分。
2. **状态维护**：在既有 AG/task frame 中承载一份短的当前工作状态，按规则更新并显示，而不是不断增加过去状态和工具日志。

不以领域 schema、通用 JSON patch、版本化字段库、依赖失效引擎、新工具或独立 SkillStateStore 为首个切片的前置。若既有承载点缺少“替换当前快照”的能力，只补支撑该显示协议的最小机制，不由此扩张为执行框架。

借鉴 [SKILL.state v3](https://arxiv.org/html/2608.26263v3) 的是“保留未来需要的当前状态、不默认重放历史”的规则。论文的收益没有充分分离人工领域 schema、状态更新与历史移除；本提案不把这些收益直接归给协议，也不承诺完整 prompt 恒定大小。[The Horizon Gap v1](https://arxiv.org/html/2608.06663v1) 的归因与过程证据要求用于验证设计，不要求把历史全部注入模型。

### 2. 默认显示面：当前状态加按需目录

不把整个 AG 序列化进 prompt。默认面只提供：

- **短的当前状态**：仅保留足以继续工作的任务相关信息。
- **按需证据入口**：正文已短且足以继续时直接显示，不额外套摘要、头或引用。当详情很长且暂不需要时才给入口；候选目录中供 `get` 寻址的稳定 ID 仍保留，不把候选预览改写成已验证事实。

候选记忆与工作状态职责不同：候选目录用于发现知识，当前状态用于连续执行。不要把所有命中的记忆自动复制到工作状态，也不要因此取消有需要的显式 `search/get`。

瘦身优先项：

| 内容 | 默认处理 | 必须保留的边界 |
| --- | --- | --- |
| 已展示且未变化的内容 | 不再次完整注入 | 压缩或上下文替换后重新判断是否仍可见 |
| 每次重复的格式说明、长免责声明、操作教学 | 归入既有稳定工具/策略说明；动态面仅保留确需的短提醒 | 不删除来源、有效性与授权规则，只去重复表达 |
| 内部图结构、评分、调试元数据 | 不作为普通上下文展示 | 保留内部 trace 与管理查询能力 |
| node/type/time/scope 等候选属性 | 按任务消歧、有效性判断需要显示 | 时间、范围、撤销、外部来源或假设标签影响解释时不得省略 |
| 长工具输出、旧状态、已解决的过程描述 | 不作为默认工作状态显示 | 必要来源仍可按既有权限和保留规则访问 |
| 证据原文 | 默认短入口，按需展开 | 用户或 Agent 明确请求 exact evidence 时，不用显示瘦身偷偷截断证据 |
| 反馈 nudges | 仅有可评反馈机会时给短提示，避免每轮重复教学 | 不将沉默、检索或状态更新当正向反馈 |

同一动态面不重复给出状态、召回与证据中相同的内容。删字段比把每条记录任意截短更优先；精简预览仍应保留会改变决策的数值、对象标识、关系与否定，不能只留下模糊主题词。

### 2.1 参考黑板：分层短读与显式维护，不复制共享状态机

现有黑板的可复用部分由 [`TaskBoardEntry/TaskBoardPreview`](../../../src/core/types.ts)、[`readTaskBoardPreviews/readInboxTaskBoard`](../../../src/core/store/base.ts) 与 [`renderTaskBoardSurface`](../../../src/integration/agent-surface.ts) 承载。借鉴的是读取和维护语义，不要求 AG 使用同一 DTO 或调用黑板写入：

| 黑板做法 | AG 中的对应 | 不直接搬用的部分 |
| --- | --- | --- |
| 条目身份/状态与短正文分开，预览有界 | 正文优先；仅在消歧或解释有效性需要时附身份/状态 | 不默认展示 author、lease、attempt、ack、verdict 等协作头 |
| `readInbox` 只列当前对我可行动的工作 | 默认面优先显示当前任务需要处理的状态，不展示所有冷却帧或旧观察 | 不将“相关知识”误当成必须执行的任务，也不把 AG 变成收件箱副本 |
| `memory=<id>`、deliverable ref 指向原 owner | 精确值足以继续时直接保留；大证据用稳定 ID/路径引用 | 不用一串指针代替必须可见的关键事实；不复制权威正文 |
| 完成/过期条目退出默认活动视图 | 失效、过期或不再影响后续的状态退出默认面 | `resolve` 是协作生命周期，不是 AG 可以自行授予的验收 |
| [在飞任务约定](../../../skills/nmg-memory/references/board.md#in-flight-registry)不按步骤反复发进度条目 | 一份当前状态持续修订，不按工具调用新增进度记录 | 借鉴约定，不把私有摘要同步写回共享 board |

借鉴的是分离显示与内部记录、按需读取及显式收口，不是固定“短头 + 短正文 + 引用”模板。包装可能比正文还长；是否附头、摘要或引用，按必要性与整块显示成本决定。最小展示原语可以共享，但状态维护与访问权限仍由各自 owner 负责。

两项现状限制须显式保留：

- 黑板 `afterCursor` 按创建位置继续读新条目；旧条目的 claim、resolve 或裁定更新不会自动变成新游标位置。AG 状态刷新不能假定这个游标是完整的变更流；应使用当前状态读或宿主已提供的相关变化信号，压缩后恢复快照。
- 当前黑板渲染默认重复附加 conventions；AG 不照搬这项输出成本。约定放稳定 owner，动态面按需提醒。不能因为黑板已有紧凑读，就声称其全部默认输出已经足够小。

[帧与存储提案](2026-09-21-the-frame-and-its-storage.zh-CN.md#2-数据格式是三个分开的问题)进一步提出线上/存储结构与 LLM 显示分开、分层摘要与指针优先；它仍是 proposed，本文只参考该方向，不将协议选择器、载荷或 T0–T3 接口视为已实现依赖。AG 保持私有内存图，不增加共享条目、新 board kind 或另一套任务身份。

### 2.2 宿主无关的类型化信息视图与显式输出

共享的是数据和输出契约，不是数据库、图类型或协作状态机。普通工具/RPC 调用是基线；直接调用、SDK 客户端或任意宿主编排都消费同一操作与结果。仅参考 Pi codemode 将能力声明、结构化数据与显式输出分开的形式，不依赖它的 JavaScript、QuickJS、`text()`、`store/load`、执行生命周期或额外编排适配层。支持调用普通工具的 codemode 无需一套 NMG 专属入口；不使用 codemode 的客户端也必须完整可用。

| 边界 | AG | 黑板 | 可共享的设施 |
| --- | --- | --- | --- |
| 作用域与保有 | 私有 session/frame，内存驻留 | channel 共享，条目可跨会话，受 TTL 与收口控制 | 来源句柄、获准信息投影；不合并存储 |
| 更新与控制 | 当前状态 replace/clear，帧生命周期 | 发布及 claim/resolve/deliver/judge，租约与独立裁定 | 类型化参数/结果、失败表达；不统一操作权限或状态机 |
| 信息显示 | 工作正文、观察与来源投影 | 条目正文及必要协作状态 | 表示选择、预算、指纹、按需详情入口 |

AG 还承载引用、激活、图边与检索投影；共享信息视图不把它退化为纯条目容器。黑板正文不因共享而成为真值，AG 投影也不能写回黑板的协作权威。

最小视图提供正文、owner 指定的必要标注、可选详情入口及内部来源绑定；各域的完整类型仍由原 owner 定义。内部绑定复用原身份并覆盖实际显示相关的版本/指纹，不新建权威身份系统。必要时间、作用域、假设及协作状态由 owner 标为不可省略；没有必要的标注与引用不强制占显示空间。来源不同或权限不同的同文不能仅凭正文去重，正文未变但 claim/verdict/有效性变化也不能被旧指纹折叠。

共享调用结果区分三件事：

1. **获准的数据视图**：用于普通工具或程序化客户端，不包含原始内部图、隐藏推理或未获准元数据；读取不等于披露。
2. **准备输出的内容**：共享层依据 §6.2 选择表示和预算；普通工具可直接将它作为响应正文，不要求 Agent 再调用 `emit` 工具或写脚本。
3. **实际输出确认**：适配器将最终进入模型输入的内容与来源绑定交回会话 owner，才按 §6.3 提交披露记录。生成文本、拿到结构化结果或成功执行某个操作均不代替这个确认。

```text
AG 工作项 / 黑板条目
  -> 获准的类型化信息视图
  -> 内容优先表示与总预算
  -> 普通工具响应或宿主其他输出
  -> 实际内容与来源确认 -> 调用者 session 的披露账本
```

类型与结果契约在 NMG 层定义；Pi 的 `content/structuredContent/details`、MCP、CLI 或其他 SDK 是映射，不是核心字段或运行环境依赖。宿主实际将哪些字段送模型，就计量并确认哪些字段；不能只因字段名叫“结构化数据”就假定它不可见。额外包装、裁剪或输出失败时只确认仍实际可见的部分，来源关联不能验证则保守不做已披露折叠。一个 Agent 看过共享条目不改变另一个 Agent 的账本。

协作参数验证、身份、租约、权限与独立裁定继续由黑板 owner 执行，不依赖客户端有没有加载长说明。成功输出不是 accepted，输出失败也不会自动回滚已经完成的 AG/黑板写入；重试和幂等性按具体操作处理。黑板创建游标的限制仍见 §2.1，不被共享视图升级为完整变更流。

### 3. 持续状态显示规则

以下是待验证的规则，而不是强制领域 schema；状态可以是短文本或列表。字段名不要求固定，更不要求有值为空的项目也占据显示空间。

1. **用途**：只保留删除后会导致选错动作、遗漏义务、违反约束或重复失败的任务内信息。
2. **内容**：按需表达当前目标/阶段、必要事实与动态限制、仍有影响的失败尝试、未决问题与下一步。稳定任务说明不重复抄入。
3. **维护**：获得会改变这些内容的新观察、任务切换或恢复需要时更新；无需每个工具调用或每轮单独做一次总结。沿用模型当前工作，不默认增设后台总结 LLM。
4. **替换**：显示一份最新快照，修订旧值、移除失效值，不追加“第 N 次状态”。已完成且不影响后续工作的过程从默认面退出。
5. **可靠性**：保留必要的假设/未验证标记与来源入口。意图不是结果；只有动作结果或原 owner 判定能支持“已成功”“已接受”等描述。
6. **范围**：状态归当前 session/frame；跨任务不混用。同任务换查询不据此清空状态；不能可靠识别任务时，保持显式范围而不是猜测切帧。
7. **预算**：状态本身有小的显示预算；不足时优先移出可按需取回的细节。必要内容放不下，应指出缺口或缩小工作范围，不静默删掉关键约束。
8. **退化**：不可确认的新摘要不覆盖可信工作依据；内容仍是暂时解释，不能替代授权来源。被删出默认显示的内容不因此成为“不曾发生”。

例如下列为说明内容的假设场景，不是当前项目事实，也不是固定模板：

```text
Unicode 回归仍未通过；下一步检查字符边界，公共接口保持不变。
```

有多个独立未决问题时可以分行。只有精确失败条件或来源入口确实影响继续执行时才附加，不要求所有内容都带标签、ID 与引用。

不附每次读文件、每次运行测试和每段推理。具体路径、测试名、数值或输入条件若决定下一步，仍应精确保留，不能为了短而丢失可操作性。

### 4. 显示生命周期：短快照也不能无限追加

必须区分三个层次：

- AG 内部保有的当前状态；
- 本次投影显示的内容；
- 宿主已累计在模型上下文中的消息。

当前快照再短，每轮完整追加仍会增长。瘦身减少增量，不自动实现 SKILL.state 的 history-free execution。注入策略建议为：

- 当前状态无变化且仍在上下文中时不重复注入；状态维护与显示频率可以分开。
- 宿主支持模型输入选择/替换时，只保留最新的状态消息进入下一次输入；会话日志可保留审计记录，不等于全部进入模型输入。
- 宿主不支持替换时，在有意义的状态变化或恢复边界展示短快照，沿用既有压缩生命周期，明确仍会累计。不能仅通过协议宣称旧消息已消失。
- 压缩、上下文替换或恢复后，重新显示必要的最新快照/证据；disclosure ledger 必须符合实际可见性，不能因“以前展示过”折叠掉已不存在的内容。

已有 `projectionId` 继续承担曝光与反馈归因。当前状态刷新不等于新任务或事实确认；对外显示不能错误借用一个未包含该状态的检索投影作为其来源。需要关联时沿用既有投影/来源机制，不另建权威任务状态。

### 5. 总显示预算与恢复边界

把本次 NMG 动态显示作为整体测量：候选目录、当前状态、短提示和展开内容均计入，而非分别允许各自的大上限。默认面与明确请求的证据展开可有不同预算，但展开仍有界且要报告未展示部分。

先测现有输出，再确定各预算的起点与分配，不把猜测的 token 数写成产品保证。除单次字符/token 数外，还测每轮新增量、完整上下文增长与压缩频率；内部 item/字符上限不代表实际模型可见成本。

必要约束、标识、来源访问权限与事实标签不能为瘦身失去。来源保留沿用 HistoryRecord、工具/宿主 receipts、任务运行记录各自的准入和 retention；不把所有输出自动复制到 LTG，不保留隐藏推理。早期观察后来重要时，通过获准来源补读，缺失就报告缺口。session release 仍删除私有 AG，不以此协议建立持久检查点或共享状态库。

### 6. 可实施切片与文档归属

#### 6.1 状态由谁写，存在哪里

Agent 根据 §3 的规则提出一份新的完整短文本；共享接纳层校验身份、大小与写入政策；daemon 在现有 AG 当前帧替换它。正文不使用领域字段 schema，完整替换不包含嵌套 patch/隐式 merge。

在现有 `FrameState.items` 中增加一种 `working_state` item，用帧内固定内部身份保存唯一当前值；不再用正文哈希生成多条状态。内部保留正文、内容指纹与调用来源，复用 session/frame 生命周期与 resident budget，不增加数据库或并列 store。普通 `observe` 不允许写这一专用项，避免绕开替换路径。失败或超限保持旧值，冷却/驱逐/释放的行为沿用帧 owner；关键状态放不下时按 §3 报告缺口，不裁掉正文后报告写入成功。

默认工具中没有直接写 AG 当前状态的入口。建议经现有 `nmg_lab` 增加 session-scoped、低风险的 `working_state` 能力，初期保持显式 opt-in，直接转发到同一 AG，不使用 `reasoning_workspace` 的第二份 scratch graph。模型只需两个操作：

```text
replace(input={text: 新的完整当前状态})
clear(input={})
```

成功返回 `updated`、`unchanged` 或 `cleared`，不回显正文、不重复约定。session/frame 来自宿主当前执行上下文，不允许模型指定任意他人的帧；异步调用归属变更后拒绝迟到写入。首切片只支持所属 Agent 的串行更新，不引入多写者合并协议。宿主内部读仍复用 `sessionActiveGraph.snapshot`，无需模型每步先读再写。新增 capability/操作是待实施的协议扩展，须按既有发现与 gate 契约接入，不是当前工具已具备的功能。

当前状态启用时，宿主应将既有任务身份映射到同一个 AG 帧，并将这份绑定传给后续 search/observe/replace；查询变化不改变绑定。不能可靠识别任务时使用显式 session 工作帧并说明范围，不以查询哈希自动迁移状态，也不把 board channel 当任务身份。无任务识别能力的适配只能承诺 session 内当前状态，不能宣称已经实现 A→B→A 的语义恢复。

`replace` 只改变暂时工作文本，不写 LTG、不修改协作状态。形状和预算校验不能证明自由文本正确；假设/结果区分依赖维护规则与独立验收，不能声称 API 自动检测了所有虚假摘要。

#### 6.2 内容优先的显示决策

共享 renderer 接收 §2.2 的获准类型化信息视图、当前可见性与显示预算，不调用总结模型或脚本运行时。为每份内容选择合法表示：

| 情况 | 表示 | 必要检查 |
| --- | --- | --- |
| 当前短正文已经足够 | 直接正文 | 所属任务清楚；必要标签不缺失 |
| 正文包含关键值，证据较长 | 正文 + 必要来源入口 | 不重复同一事实，不丢精确条件 |
| 大内容暂不需要，来源可访问 | 有意义的短预览或引用 | 入口有效；引用和提示的总开销确实值得 |
| 没有安全短表示或正文超限 | 不足/超限结果 | 不静默截断关键状态，不造不存在的入口 |

元数据在内部 DTO 保留，不因此全部写入 LLM 文本。对于同等必要信息的候选表示，比较正文、标签、引用、分隔符与提示的整块成本；包装更长则保留直接正文。不用一个固定长度阈值决定所有类型。工作状态与候选目录仍按 §2 区分，后者的寻址 ID 不能仅因短就省掉。

显示预算由共享层控制，Agent 不能在写状态时抬高。实现参数区分默认动态面的上限与当前状态上限，后者必须在前者内；数值由基线测量与匹配实验确定。字符硬上限负责廉价检查，已有 token 估计负责比较，真实模型 token 计量用于验收。显式 evidence get 先保持既有证据契约，不因本切片新增截断。

#### 6.3 更新、披露与模型输入的接线

```text
新的必要观察 -> Agent 选择是否 replace/clear
             -> session-owned AG 更新唯一当前状态
下一次模型输入准备 -> 收集 recall / 当前状态 / 必要提醒
                  -> 去重与内容优先表示 -> 统一预算接纳
                  -> 宿主实际暴露 -> 记录已展示内容
```

预算选择和 §2.2 的实际输出确认必须在披露账本提交前；未进入最终输入的候选/状态不得被标成 already_in_context。普通工具直接响应与程序化客户端内部读取走同一结果契约，但后者的读取不得提前提交披露。确认写状态的工具参数已保留在下一步输入时，正文已经可见，不立刻再次完整注入；不能确认时，在下一次必要显示/恢复边界展示当前快照。既有 `disclose()` 会更新账本，因此实施时需调整调用顺序，不能先标记所有检索结果后再裁掉显示。

宿主提供的接线点必须覆盖实际的“下一次模型输入”，包括工具循环，不只看用户轮次开始。先验证现有适配支持；不以 `before_agent_start` 的一次调用冒充每次模型调用都处理过。当前状态与检索投影的来源关系遵循 §4，显示失败不破坏原工作状态，压缩/上下文替换重置可见性而不清空当前状态。

支持输入选择的宿主可给 AG 状态一个独立可识别的消息/片段，由内部 session/frame/type 标识，在送模型前保留最新状态，不靠匹配正文关键词删历史。只处理 NMG 自己的状态片段，不删除用户消息、工具调用与结果、原证据或任务政策。当前混合 `nmg-context` 消息不能整块删除，否则会误删 recall/证据。状态写入的工具参数本身仍占历史上下文，必须计入成本；即使最新状态片段可替换，也不声称整个对话 history-free。

不支持输入选择的宿主沿用 §4 的变化时追加与压缩恢复退化方式，并报告追加模式。这一能力差异由适配器报告，不在模型提示里重复铺开。

#### 6.4 最小实施顺序

| 切片 | 改动 | 单独证明什么 |
| --- | --- | --- |
| A：共享视图与纯瘦身 | 既有公开类型/结果契约、共享 `agent-surface.ts`、prompt 源表达、动态面总预算与输出确认 | 普通工具无需编排依赖即可消费；更少包装/重复且关键内容保真，不包含状态维护收益 |
| B：当前状态协议 | AG 专用项、现有 RPC 的 replace/clear 接线、Lab capability 描述与短 ack | 一份可替换的状态可从模型安全写入，仍保持私有/暂时 |
| C：宿主可见性 | 实际输入接线、最新状态片段选择、压缩恢复与退化报告 | 旧 AG 状态片段是否真的退出输入；不扩大结论到工具历史 |
| D：匹配评估 | §Acceptance criteria 的现有/瘦身/瘦身加维护三组 | 协议是否在同显示预算下改善连续性，成本是否值得 |

共享类型与结果边界放既有 core/protocol owner，显示规则放 [`agent-surface.ts`](../../../src/integration/agent-surface.ts)、[prompt 源文件](../../../src/prompts/nmg-prompts.yaml) 与既有 AG owner；capability 在 [`lab-capabilities.ts`](../../../src/integration/lab-capabilities.ts) 和 daemon/协议目录声明。适配层只做身份、结果字段、实际输出确认与宿主生命周期映射；核心不导入 Pi/codemode API，不新增编排执行器。生成的 prompt 文件不直接编辑。完整上下文重建、领域 schema、结构化 patch 引擎、HA/MGR 学习不是本切片前置。

[共享信息输出基础](../implemented/2026-10-07-shared-information-output.zh-CN.md)已实施：获准来源绑定视图、单份文本的纯准备、精确渲染片段的确认候选、兼容 AG/黑板文本路径与 opt-in 长约定。[有边界的当前状态切片](../implemented/2026-10-08-ag-working-state.zh-CN.md)现已通过普通 Lab/RPC 客户端实现 AG 专用 replace/clear 与捕获代际 fencing，当前适配器明确采用 session 工作帧退化。两个切片都未把最终宿主可见性接到账本、建立统一动态输入预算、替换宿主历史或证明模型收益；Pi 的[专用输入选择切片](../implemented/2026-10-08-ag-working-state-input.zh-CN.md)已实现逐次状态选择／恢复和捕获的直接写入去重，不改受保护历史；最终发送确认明确不支持。A／C 的剩余部分、退化以外的语义任务绑定、其他宿主选择器和 D 仍是提案。现行基础边界已进入 `design.md §7.1`、`memory-graphs.md §5`、runtime/display owner 与 completion audit；任务契约、协作判定、长期知识与执行事实仍归原 owner。

## Alternatives considered

- **只降低候选条数或截短所有内容。** 不充分：能省 token，但可能损坏必要信息，且不能维护当前状态。
- **先实现完整 schema/JSON patch/依赖失效引擎。** 暂不采用：尚未证明轻量显示协议不足，会把优先级从上下文成本移到新基础设施。
- **每轮追加完整短摘要。** 不采用为目标策略：单次变短仍会累计，旧摘要可能和新状态冲突。
- **只显示差分。** 不作为唯一方式：上下文压缩后可能没有基线；需要能够恢复一份短的最新快照。
- **新建共享或持久 SkillStateStore。** 不采用：重复 AG/任务协议身份与生命周期，模糊权威边界。
- **永久删除所有历史以换取短 prompt。** 不采用：瘦身的是默认显示，不是审计来源；不继承充分统计量无条件成立的假设。
- **依赖 Pi codemode 编排或自建通用脚本执行器。** 不采用：格式借鉴不要求运行时复用，普通工具已有调用入口；该依赖降低通用性，执行器也超出记忆组件职责。
- **只加 scope/TTL 就统一 AG 与黑板存储和状态机。** 不采用：私有工作图与共享协作的权限、并发与判定不只这两个参数；仅共享信息投影和输出设施。

## Acceptance criteria

先验证显示契约，再验证协议收益：

1. 现有 representative 输出与瘦身输出可比较；默认面显著减少字符/token 和重复块。精简后 ID 可取回，关键值、时间/范围消歧、否定、假设与撤销边界保真，explicit exact get 不被任意截断。
2. 同任务只有一个逻辑上的当前快照；修订不在默认面并列显示旧值；无变化且仍可见时不完整重复注入。压缩/替换后可以重新获得必要快照与证据。
3. 明确记录适配实际支持：若只有追加能力，测试和报告不得声称旧消息被替换或完整上下文有界。完整输入、单次显示与累积增量分别测量。
4. 状态不跨 session/task 混用，不自证 accepted、成功或权限；pending/failed/cancelled 不变成成功。状态显示不会隐式写 LTG 或给检索/学习附加正向证据。
5. 借鉴黑板后仍不新增共享条目或复制协议头；必要时引用的证据可取回。无新条目但旧来源状态变化时仍能刷新当前快照；不能仅凭创建游标判断状态未变。conventions 等静态说明不成为新增的每轮成本。
6. 回归覆盖“正文比包装短”“候选目录仍需 ID”“引用失效”“总预算筛掉但未标披露”“replace 失败保留旧值”“写状态参数已可见不再双注入”。输入选择仅移出旧 AG 专属状态片段，不删混合 recall 或任何工具调用/结果；追加模式与替换模式分别报告，写状态的工具成本计入。
7. 无 Pi/codemode 的普通工具/RPC 客户端可以使用同一类型化信息视图与结果契约；核心、测试及恢复不依赖 JavaScript 编排、Pi globals 或 codemode store，不额外强制 `emit` 调用。
8. 程序内部读取十项仅显示两项、最终裁剪/输出失败、来源绑定不可验证、另一 Agent 首次读共享条目等场景不产生虚假已披露；正文不变但协作状态变化刷新视图。共享渲染不获得 claim/裁定权限，写入副作用不因输出失败被误称回滚。

匹配实验先做三组：A，现有显示；B，仅瘦身；C，同样瘦身加状态维护协议。固定模型、任务、工具、检索与权限，对 B/C 匹配显示预算，避免把更短误当作状态更新更好。若要独立判断“更新内容”而非格式提示的收益，可再增加同一显示格式但不更新的研究对照；不能只看其在缺乏全部历史时失败就宣称机制被证明。

记录独立终局验收、义务遗漏、重复失败动作、当前状态正确性/过时率、恢复能力、每轮新增与累计上下文 tokens、模型输入/输出/额外总结调用、延迟和压缩频率。任务切换、外部状态变化与“早期无关观察后来必要”必须有反例。先验证纯瘦身是否保持质量，再判断协议是否在相同显示成本下改善连续性；不预先承诺二者必然有收益。本文未运行这些实验。

## Risks

- **压缩遗漏**：丢失精确标识、条件或来源后，短状态反而造成额外搜索或错误；保留按需补读路径并测量质量/恢复。
- **摘要伪装事实**：自然语言规则不能保证内容正确；假设标记与原 owner 验收不可省略。
- **增长被掩盖**：缓存降费或单次变短不等于上下文不增长；需要宿主能力与累计测量。
- **规则负担**：把长篇维护规则重复注入又制造新负担；规则只放既有 owner，动态面只给当前内容。
- **实现不足**：当前 `observe()` 的内容去重不能替换状态；必须验证最小承载机制，不能只写提示就声称持续状态已接入。
- **撤回条件**：若协议在同预算下不改善连续性、频繁生成错误状态或维护成本抵消收益，撤回协议默认推广；纯瘦身独立保留或撤回，不能因协议无效就取消已验证有益的瘦身，也不以增加状态引擎掩盖反例。

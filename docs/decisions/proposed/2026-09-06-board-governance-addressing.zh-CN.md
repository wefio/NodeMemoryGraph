# 黑板治理与能力寻址（提案）

[English](2026-09-06-board-governance-addressing.md)

**Status:** proposed
**关联：** [board-find-serial-a2a-compat-2026-08-13](../../design/board-find-serial-a2a-compat-2026-08-13.md)、
[agent-convergence-feedback-design](../../design/agent-convergence-feedback-design.md)

## 问题

NMG 任务黑板是 stigmergy 协调介质：自主 agent 靠读写一批带类型、可归因的共享条目协调，
而非点对点控制。这是正确的基础模型，且已具备寻址（`to=`）、claim/release/resolve 所有权、
ack、串行单 owner 晋升、唤醒器与 `memory=<id>` 记忆指针。

真实多 agent 使用（本批 3 agent 并行复核）暴露了摩擦；对 OpenAI Hugging Face 事件的独立分析
则提供了"真实使用踩坑"的证据，指出哪些语义真正重要。摩擦与事件指向同一组两个缺口：

1. **格式 / 读取成本**：`read` 返回整段长条目拼接文本；即便状态未变，重新同步也烧上下文。
   记忆指针省的是*内容*成本，不是*状态同步*成本。可发现性弱：要知道有没有活须逐频道 read，
   没有"我该处理什么"的视图。
2. **协议 / 正确性**：任务由 claimer 单方 `resolve` 终态，无机制让独立审阅者拦下过早完成。
   HF 事件里共享板让 agent 扩散"怎么过评分器"污染测量本身；同伴带硬截止的 "GO" 还压过犹豫者。
   这正是设计文档所称"board resolve 是有偏自报信号"（agent-convergence-feedback-design §3.8）。

从第一性，好黑板须满足六角色：共享工件介质（外部记忆）、能力寻址、带超时/接管的单一所有权、
可信身份与内容真实性、**终止完整性**（任务仅经可复核终态才算完成）、**作用域隔离**（并非
所有 agent 见同一板）。黑板还喂给 agent-convergence 的全局校准器，故其终止完整性是把
`resolve` 变成可用（去偏）训练信号的关键。

## 提案

两条轴。借事件所验证的*语义*，同时保住 NMG 特性（记忆指针、A2A、单 owner、唤醒器、上下文
节俭）。**不**照搬事件的自由共享存储模型。

### 格式轴（降读成本，条目保持有类型、指针优先）

- **F1 紧凑读模型**：`read` 默认返回短结构化摘要（id/kind/状态/一行正文或 `memory=<id>`/
  是否定向给我/是否未 ack），而非整段拼接全文；全文走显式 `detail`/`nmg_get` 展开。无论频道
  多大，单次同步的上下文都受限。
- **F2 收件箱/待处理视图**：对我订阅频道提供单一"该处理什么"读取——可行动且未处理、且面向我
  （定向或我可 claim 的非定向）的条目。替代逐频道轮询。
- **F3 正文指针优先（正式化）**：允许正文仅为 `memory=<id>` 指针、按需展开；黑板是*外部记忆*，
  真相存于持久记忆。这是 HF 事件"共享存储当外部记忆"的受权版本。

### 协议轴（正确性；借事件的教训）

- **P1 可复核终态（VETO）**：`resolve` 不是 claimer 单方自报。条目上的独立复核角色可拦下过早
  终态；终态带可审计轨迹。保留串行单 owner 执行，仅在存在独立复核者时增加显式 veto 路径。
  这是"给 board resolve 去偏"背后的机制。
- **P2 内容真实性**：每条目默认带轻量内容 hash（防篡改、可审计）；完整 Ed25519 签名可选，仅当
  条目跨越信任边界才启用。writer 归属 + `agent_id` 仍为基底。
- **P3 作用域隔离**：条目可限定可见 agent 子集/组，使失控群体被收进边界、黑板默认非全员互通。
- **P4 能力寻址**：工作条目带 `need`/能力字段，可不经手动 `discover`-再点名即匹配到有能力的
  agent（类 zzINFO 的"活找 agent"）。复用现有 roster/身份；是寻址便捷层，非新调度层。

### 非目标（刻意不采纳）

- 自由共享文件存储（HF 式）：保留有类型条目 + 归属 + 作用域。
- Contract-Net 多 bid 分工：事件中的内竞争/干扰及我们的单 owner 安全主张都不支持它。
- 胁迫原语（"GO"+ 硬截止）：保留每 agent 独立判断。
- 黑板作为真相源：它仍是临时协调介质；真相在持久记忆。

## 考虑过的替代方案

- **整套引入 Linda 元组空间 / ZooKeeper / Contract-Net 栈**：否决——面与上下文成本高；多 owner
  竞标会重引入串行单 owner 刻意避免的重复干活与干扰。
- **只保留黑板并改进文档/约定**：否决——摩擦是结构性的（读模型、可发现性、无可复核终态），
  非文档缺口。
- **自由共享板文件（HF 式）**：否决——无类型写入且无逐条作用域/真实性，恰是让事件板成为盲点的
  属性。

## 验收标准

- `read` 默认返回紧凑摘要；全文需显式展开；含大量未变条目的频道不增单次同步上下文。
- 收件箱/待处理视图列出面向我、可行动且未处理的条目。
- 独立复核者能拦下过早 `resolve`；终态保留可审计记录（谁 claim、谁 verify、谁 finalize）。
- 带 `need` 字段的工作条目无需手动 discover-再点名即浮现给有能力的 agent。
- 条目默认带内容 hash；跨信任条目可用签名。
- 作用域把条目可见性限到其授权 agent 子集。
- 单 owner 执行与唤醒节俭得到保留（无全员广播或重复干活回归）。

## 风险

- **新增语义面**与"降复杂度"相悖：缓解——F1–F4 与 P1–P4 全部增量、可选；默认单一路径保持简单。
- **VETO 拖慢进度**：缓解——仅当存在独立复核角色时适用，带审计记录，且 claimer 不能借此阻塞
  自己已完工项。
- **签名成本/性能**：缓解——默认轻量 hash；仅跨越信任边界才启用签名。
- **作用域过紧隐藏工作**：缓解——收件箱视图兜底，即使紧作用域也显示待处理可行动项。

## 后续关联

黑板是喂给 agent-convergence 校准器的事件流（§3.7/§3.8）。此处协议改动（P1 终止完整性、
P2 真实性、P3 作用域）是"reconcile 给 board resolve 去偏并测 false-complete 率"的机制底座；
格式改动（F1–F3）让黑板可作为高频协调面而不烧预算。本文记录语义与优先级；具体字段/verb 设计
属后续实现切片。

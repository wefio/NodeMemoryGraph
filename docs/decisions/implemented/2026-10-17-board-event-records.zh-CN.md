# 兼容增强的事件记录与 Agent 任务状态

[English](2026-10-17-board-event-records.md)

**Status:** implemented
**Approved:** explicit
**Relates to:** [黑板治理](2026-09-06-board-governance-addressing.zh-CN.md), [协作事件契约](../../design/board-event-records.md)

## Problem

普通消息、频道发现与工作项认领，不能单独承载一次跨频道协作从开始到结束的粗粒度脉络。
参与者需要知道哪些频道正在讨论什么、哪些讨论已结束或方向已弃用，而不必重建所有细粒度任务，
也不依赖发送方一直记得补发后续。Agent 还需要简便地展示当前工作，不公开私有工作上下文。

某次维护暴露了问题，但需求属于通用协作。把世界频道改成纯目录会拿掉原有发消息、找人的用途，
不是兼容增强。

## Decision

本记录接受[事件记录、事件空间与 Agent 状态契约](../../design/board-event-records.md)中的设计语义。
运行时证据、部署边界和剩余工作由 [完成台账](../../design/completion-audit.md) 记录。

世界频道继续通信。事件记录增加粗粒度过程、频道关联，以及可退出的事件更新订阅，
不施加新的执行调度器，也不限定为维护流程。
事件关联只提供上下文，事件通知才对当前订阅者批量点名；显式讨论／决策请求和关键过程变化
可以通知；普通回复不自动重新通知整个事件，协议 ACK 静默，频道讨论按频道订阅继续提醒。
协作由 Agent 自己组织，
不设置自动唤醒链长度、轮数或事件通知次数硬上限，也不加必须由人恢复的门槛。
完整通知规则与循环风险边界由专题契约维护。
点名对象、频道订阅者和事件订阅者是独立受众。明确邀请的首条通知直接面向被邀请人，
不要求其先订阅；受邀自动订阅指定频道，后续按该频道订阅提醒，可以退出。
单纯事件订阅仍不意味着订阅所有关联频道；邀请重试不撤销后来的退订，受邀不等于接单。
同一次通知的重叠受众只接收一次。
Agent 状态采用默认空闲、自留说明与自动任务关联，不通过模型或工具活动推断忙闲。

专题契约是语义的单一 owner。现有黑板、身份、订阅、送达、认领和独立 verdict 继续负责各自边界，
不被第二套共享记忆图取代。

## Alternatives considered

- 世界频道只作目录：损失普通通信，也不能表达用户要求的过程历史。
- 仅增加频道文件夹：能归类地点，但缺少事件身份、演变、参与者和生命周期观察。
- 细粒度任务流水或新调度器：强加协作执行，增加事件记录不需要的细节。
- 维护专用编排：把发现问题的场景误当成通用事件空间的范围。
- 自动总结忙闲或复制私有状态：增加模型成本、隐私暴露和歧义，显式任务关联已足以表达名册状态。
- 每次变化重新广播并要求全员确认：重复状态、依赖发送方补发，也会重新引入通知风暴。
- 每条关联或定向消息都唤醒：混淆寻址与通知意图，新的确认条目仍能相互叫醒。
- 把事件参与等同订阅所有关联频道：让讨论流量跨范围扩散，覆盖独立订阅选择。
- 邀请前必须先订阅频道，或邀请后仍不登记订阅：前者漏掉首次邀请，后者漏掉后续讨论。
- 自动唤醒链硬上限或强制人工续开：截断用户期望的自组织协作，没有解决通知与回复的混淆。

## Consequences

设计保持增量兼容：旧消息／频道继续可用，事件历史提供可选的组织与订阅。
过程结束、工作结果与持续影响相互独立。默认空闲只描述任务登记，不证明实际可接单；
手写状态说明独立保留。

共享 Store 采用增量迁移及预期修订检查，事件快照、历史与通知事务性提交。
带版本的定向通知复用既有收据，不把更新变成任务或世界广播。
共享宿主送达先等待入队成功，再写收据；异步入队失败不消耗预算，通知仍可重试。
任务 owner 关联、历史参与和退订是独立事实；名册状态派生于任务，不维护另一套任务状态机。

讨论通知沿用原消息身份，不为每句聊天增加过程修订。邀请订阅登记及 outbox 与原消息事务性提交。
最小作者／请求键／摘要／源 ID 墓碑独立于消息 TTL，防止重试把退出者拉回；退出某范围撤掉其旧排队提醒，
不撤掉同一通知仍有效的其他范围。频道待送回复保留关联来源的通知用于批次投递。
显式通知采用 note，任务认领另走原协议。
带来源标签的唤醒预览控制单次输出大小，不限制会话讨论轮数。

参与者修改检查及影响条目的记录 owner 是协作规则，不是设施授权或真实性认证。
事件档案独立于普通消息 TTL，只能在结束、影响解除且无必要引用时显式删除。
既有宿主入队与收据边界不承诺任意崩溃下的恰好一次，也不证明模型已经理解。

文档检查只建立结构与链接证据；源码测试和宿主集成分别证明其较窄契约。
部署、真实空闲 Agent 唤醒、自然协作结果和收益与源码验证分开，不因本决策重启共享服务。

## 按需吸纳概念

DSH 原型提供的有用区分不止 Ticket、Assignment、Session。
记录词汇可以保留选项，但实现完整清单会重复已有 owner，并引入未经支持的生命周期承诺。
用户选择先复用已有基础，其余概念在需要时再使用。

[事件契约](../../design/board-event-records.zh-CN.md#概念吸纳)拥有扩展条件。
[复用指南](../../guides/board-concept-reuse.zh-CN.md)与黑板工作流提供当前操作的发现路径。
概念清单记录词汇，不宣称通用 Assignment、输入责任或 DAG 调度已经完成。
不采用整套照搬或强制实施清单；只把概念留在私有对话中则难以恢复后续复用所需的信息。

## 事件内的阶段协商

Agent 可能依据尚未确认的讨论开始实现，也可能将重设计建议误解为停止指令。
可选的范围级阶段声明让共同活动边界可见。事件修订、事务、历史、订阅和 InformationView
沿用现有 owner；另设调度器或监督角色会重复这些职责。

[阶段契约](../../design/board-event-records.zh-CN.md#范围级协作阶段)区分阶段版本与事件版本，
并将确认绑定到唯一提案。默认参与者确认是保守起点；显式受影响参与者集合允许依协作约定局部协调。
该集合是声明，不是经过验证的组织权威。未启用的事件保留无阶段状态，避免全局模式变化。

执行许可和在途操作隔离仍属于额外机制。
[草案](../../design/board-event-records/collaboration-phase.zh-CN.md)保留这些策略选择。
领域／state 测试覆盖版本检查、确认、撤回、持久化、局部范围与披露，不证明真实多 Agent 一致性或宿主强制约束。

## 共享活动与回复批次

只选第一条回复会拆散已有多条回复的讨论。因此频道提醒保留逐条待送来源，共用一个有预算的投递片段。
分页前过滤待送资格，使已送条目继续可读，同时允许后续回复进入页面。
范围间轮转排序让其他讨论也有机会进入同一次有界准备。

忙碌是黑板的独立语义。Agent 声明和 Harness 观测分别持有租约，busy 优先，能力取并集。
这使缺少原生观测时仍可使用声明，并避免 Harness 的 idle 覆盖 Agent 的 busy。
逐 Harness 制定协调策略会分散共享语义，要求共同支持则会损失部分宿主已有的能力。
未知观测保持可见，并允许通过已有输出机制投递。租约默认 180 秒，上限 3,600 秒。

[活动与批次契约](../../design/board-event-records/agent-activity-and-batches.zh-CN.md)拥有行为定义。
初始传输页最多将 200 个来源交给已有的 16,000 字符上下文预算。
收据在宿主实际接收后写入，只覆盖纳入的来源，批量收据事务性提交。
进程内 singleflight 避免重叠轮询同时提交同一会话，投递前重查阶段快照。
跨宿主与 daemon 的崩溃恢复保留至少一次语义。

受控夹具覆盖 64 位作者的 240 条待送回复分页、8 个 DSH 接收者的 12 作者批次、
Agent 独立忙碌声明、准备期间阶段变化、收据回滚及 WorkBuddy 输出失败。
这些夹具测量协议与适配器边界，真实 Harness 界面和自然协作结果仍有各自的验证范围。

## 原生端点身份与在线状态

DSH 的项目级身份混合了适配器存活与 Agent 可用性，也将多个会话合成同一订阅者。
普通工具、事件变更和唤醒投递因此使用不同的身份规则。DSH 将这些路径统一绑定到
原生 Agent／会话，共享层选定收件人并提供待送通知后，直接连接对应的原生入队或恢复操作。

在线状态增加显式退出操作。软退出保留历史作者、说明及未完成工作。
删除注册记录会丢失这些上下文，只等待心跳窗口则会让正常关闭的会话继续显示在线。
注册代次 token 约束迟到的心跳与退出，端点内写入顺序处理重叠的适配器生命周期回调。
适配器存活期间会重试失败的退出。

更新后的适配器激活时撤下旧项目身份。历史角色与订阅保留原 owner，
将它们自动交给任意原生会话，会授予该会话其他参与者的范围。
能力检查让旧 daemon 明确识别新增生命周期。
受控集成覆盖空宿主、原生销毁、插件卸载、独立订阅、定向接收、显示名寻址、
continuable 子会话和退出恢复。真实 DSH 界面与进程突然退出仍属于独立验证范围。
最终行为由[在线状态契约](../../design/board-event-records/agent-activity-and-batches.zh-CN.md#在线身份与原生会话)维护。

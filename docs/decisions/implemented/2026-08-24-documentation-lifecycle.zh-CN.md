# 轻量文档生命周期

[English](2026-08-24-documentation-lifecycle.md) · [使用的术语](2026-08-24-documentation-lifecycle.terms.yaml)

**Status:** implemented  
**Approved:** explicit
**Relates to:** [文档治理设计](../../design/documentation-governance.md)

## 问题

NMG 的规范设计、实现状态、临时工作、实验与操作说明增长很快，而文档所有权规则没有同步成熟。重复摘要使维护者难以判断应该更新哪份文件；严格镜像全部双语文档又会引入与 NMG 本身无关的维护成本。

## 决策

采用轻量的所有权与生命周期系统：

- 一份规范设计基线，加上负责具体机制的专题设计；
- 使用带生命周期的决策记录保存理由；
- 分离实验、完成审计与未完成 TODO；
- 只使用一个名为 `doc-maintenance` 的项目 Skill 承载操作流程；
- 所有非临时文档按[双语规则](../../README.zh-CN.md#双语规则)组织英文、中文和使用术语三件套，但不强制逐段一致或翻译哈希；
- 结构检查对公共/规范入口破损、错误决策结构、活跃设计与 Skill Markdown 的结构卫生及 [CI 契约](../../README.zh-CN.md#ci-契约)准入的角色字节预算报错；根 README、`docs/` 与 `skills/` 的三件套完整性也阻塞，包含归档和自动发现的新主题，仅保留 CI 契约声明的可丢弃运行草稿例外；其他内部笔记问题与双语漂移只告警。

已认可的[治理设计](../../design/documentation-governance.md)以读者能完成的事、完整事实和带拒绝用例的局部检查细化本模型，并分开术语定义归属与发现。具体义务由设计负责，本记录保存理由。读者审稿直接检查正文；已准入的结构检查覆盖全部活跃设计与 Skill Markdown，包含新增子主题和 reference。原三份流程文档仍须存在。归档设计和实验原始证据保留各自角色，不自动套用本门禁。

字节预算是独立性质：活跃设计单元与 Skill 入口沿用 15,000 B，AGENTS 与决策索引沿用 5,000 B。检查 reference 标题不等于给 reference 加入口文件的字节上限。原始超限正文先真实失败，再按职责迁移，不以读者收益测量为前置条件。

[读者导向写作规范](../../../skills/doc-maintenance/references/reader-review.md)拥有具体起草与审稿要求，先写定规范，再按主题整改。受控技术英语只影响表达层，不声明符合 ASD-STE100，也不整体采用其词表或数量约束；这样能改善清晰度，同时保留领域标识符、条件和设计需要的论证。不另建词典或文笔质量门禁。

## 考虑过的替代方案

- 只保留非正式约定：对多 Agent 协作约束不足，已经出现信息所有权漂移。
- 强制逐段镜像或翻译哈希：双语语义覆盖不要求段落结构相同。共用术语文件服务于译名一致，不是确认哈希，也不是每篇再复制全部定义。
- 只要求公开入口双语，或只对决策通常配对：由用户明确的“所有非临时文档”范围替代。保留的内部笔记、实验与归档不是可丢弃工作材料；新增的翻译与术语使用维护成本，在每组三件套完成审稿前保留为待整改项。已准入语料的文件存在性由机械检查强制，文件是否表达正确仍由审阅判断。
- 扩充逐文件白名单：新增设计主题和 Skill 仍会漏检；目录/角色覆盖需要迁移链接与 owner，但无需维护另一份名单。
- 等待文笔或抗膨胀收益测量后才执行预算：真实红→绿足以验证已准入的机械性质，不认证文风或语义等价。拆分会增加主题文件与导航成本，因此整职责迁移，小解释留原 owner。
- 只在三份试点文件检查标题：同一检查准入活跃设计与工作流后不再保留白名单。角色发现避免名单漂移，成本是修复新覆盖的结构缺陷；归档和原始证据不被静默改类，reference 卫生也不意味着 reference 字节上限。
- 用单一大小上限或检查通过定义文档健康：两者都不证明读者理解或事实完整；任意拆碎文件只是转移维护负担。
- 整体采用 ASD-STE100，或用句长作为验收：NMG 包含双语流程、查阅材料和研究论证，统一语言限制不能证明读者获得了必要事实。适配表达原则的成本是逐项对照来源并由作者审稿；不能把这些检查宣传为独立语义证明。
- 只润色句子：句子清楚仍可能缺少任务入口、前提、owner 或失败路径，因此规范先处理内容组织，再处理措辞。
- 将父文档章节位置或生成式 slug 带入主题文件名：它们编码的是旧提纲而非主题，且不符合既有的描述性英文 kebab-case 命名。该约定由读者规范拥有；修复既有拆分的成本是迁移路径、片段链接与术语指针。这不是一律禁止有意义的日期、版本或稳定标识符，也不新增文件名风格门禁。
- 给每个产物增加 `nmg-` 前缀：仓库本身已提供项目命名空间，`doc-maintenance` 更清楚也足够。

## 后果

贡献者新增文件前必须先找到已有的信息所有者。所有保留的文档遵循双语主题组规则，以是否保留相同事实与意图为标准，而不是要求结构完全一致。CI 阻止公共/规范导航、决策契约破损和已准入的结构卫生错误；其他内部组织问题与翻译漂移只报告，不成为发布阻塞；已准入语料的三件套缺件直接失败，不再积成告警。代价是三份文件必须一起维护，但不新增确认格式、翻译哈希或文笔质量门禁。细化后的设计提供评估阅读负担和检查范围的归属，不要求建立文档平台，也不改变现有 owner 的权威。

## 未完成项

其他文档角色的预算和结构卫生准入、自动文风判断和可选的小节确认记录仍不在本轮推广内。其准入需要在现有规则 owner 固定范围、严重级别、豁免与拒绝用例。翻译哈希不是全仓要求，确认记录也不替代语义评审。

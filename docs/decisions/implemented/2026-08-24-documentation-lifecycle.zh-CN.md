# 轻量文档生命周期

[English](2026-08-24-documentation-lifecycle.md)

**Status:** implemented

## 问题

NMG 的规范设计、实现状态、临时工作、实验与操作说明增长很快，而文档所有权规则没有同步成熟。重复摘要使维护者难以判断应该更新哪份文件；严格镜像全部双语文档又会引入与 NMG 本身无关的维护成本。

## 决策

采用轻量的所有权与生命周期系统：

- 一份规范设计基线，加上负责具体机制的专题设计；
- 使用带生命周期的决策记录保存理由；
- 分离实验、完成审计与未完成 TODO；
- 只使用一个名为 `doc-maintenance` 的项目 Skill 承载操作流程；
- 公开入口成对维护双语，决策通常也成对，但不要求逐段一致或翻译哈希；
- 结构检查对公共/规范入口破损和错误决策结构报错，内部笔记问题与双语漂移只告警。

## 考虑过的替代方案

- 只保留非正式约定：对多 Agent 协作约束不足，已经出现信息所有权漂移。
- 为所有文档建立严格镜像、哈希或侧车文件：机械一致性更强，但会给实验与内部笔记带来过多变更。
- 给每个产物增加 `nmg-` 前缀：仓库本身已提供项目命名空间，`doc-maintenance` 更清楚也足够。

## 后果

贡献者新增文件前必须先找到已有的信息所有者。公开入口继续双语，但以是否保留相同意图为标准，而不是要求结构完全一致。CI 阻止公共/规范导航和决策契约破损；内部组织与翻译漂移只报告，不成为发布阻塞。

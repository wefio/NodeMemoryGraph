# 在执行与证据边界保持自动化可维护

[English](2026-10-23-maintainable-automation-boundaries.md) · [使用的术语](2026-10-23-maintainable-automation-boundaries.terms.yaml)

**Status:** implemented
**Approved:** explicit
**Relates to:** [约束结果属性，而非工具身份](2026-09-09-gates-assert-results-not-tools.zh-CN.md)

## Problem

小型分析可能逐渐成为维护型工具，却没有相应调整共享逻辑、资源和已有结果的管理方式。
本次规则调整所依据的检查发现：进程生命周期代码重复、共享测量存在本地变体、结果复用
只依据行身份而非计算身份，以及辅助函数测试无法说明命令是否仍可运行。报告后文追加
订正，也让旧结论继续呈现为当前结论。

既有规则已经覆盖复用与证据范围，但一次性脚本的表述和一般提醒没有明确上述决策点。
用户选择增加通用预防规则，而不是追溯改造被检查的文件。

## Decision

扩充既有工作流 owner，不另建第二份检查清单：

- [脚本复用](../../../skills/script-reuse/SKILL.zh-CN.md)同时覆盖维护型、可续跑自动化与
  可丢弃分析。部件规则拥有复用与共享语义；执行章节拥有资源隔离、兼容结果复用和
  完成状态的持久化。
- [验证可追溯性](../../../skills/verification-traceability/SKILL.zh-CN.md#验证实际执行边界)
  拥有可运行入口所需的证据要求，包括受控检查与尚未验证的真实依赖之间的区别。
- [读者审稿](../../../skills/doc-maintenance/references/reader-review.zh-CN.md#审稿与验收)
  拥有主张改变后对现行结论和指南的同步核对。
- [仓库开发](../../../skills/repo-development/SKILL.zh-CN.md#编辑前)将脚本工作路由到这些
  owner，保留型脚本也不例外。

这些是对新增或修改工作的作者与审稿要求。本次不增加运行框架、登记系统或 CI gate，
不重构既有实验代码、结果或报告。独立验证与维护同一运行契约的竞争实现保持区别。

## Alternatives considered

- **立即重构所有触发问题的文件。** 本次不采用：超出用户要求的预防范围，也会干扰并行
  实验工作。
- **另加反重复 Skill 或根目录清单。** 不采用：既有 owner 已负责这些决策，新增入口会
  重复规则。
- **要求通用 runner、统一 manifest 格式或固定目录布局。** 不采用：工具的执行成本与
  生命周期不同，所需属性可由既有 owner 满足，无需新框架。
- **新增全仓重复函数体 gate。** 不采用：文字相同不等于语义共用，关联决策已有此限制的
  记录。既有类型、测试与文档检查仍是有效证据。
- **继续只按一次性脚本表述。** 不采用：保留与续跑正是临时假设变成长久依赖的地方。

## Consequences

新增审查发生在具体边界：第二个调用方、共享测量、资源取得、结果复用、可执行入口修改，
或结论变化。不增加逐文件登记或强制抽象。可丢弃脚本仍可丢弃；复现依赖的命令应被维护，
而不是按临时标签删除。

小型受控执行可以验证命令连接，不必支付真实工作负载的成本；它不能证明真实集成或答案
质量。同样，文档检查证明结构，不证明 Agent 会遵循规则，也不证明历史产物已满足规则。

## Risks

身份可能过弱或过宽。执行 owner 选择影响结果语义的字段并排除秘密，整个环境的转储不能
代替身份设计。复用也可能演变为过度抽象，因此抽取依据实际调用方，任务特有选择留在
调用方。

某条规则反复产生与受影响边界无关的工作时，在既有 owner 修改或移除它，不再加一份
清单补偿。

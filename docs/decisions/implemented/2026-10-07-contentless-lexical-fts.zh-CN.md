# 词法 FTS 保留倒排索引，不再保存重复全文

[English](2026-10-07-contentless-lexical-fts.md)

**Status:** implemented
**Approved:** explicit

## Problem

`memory_fts` 的 content 影子表保存了处理后的记忆正文、节点名和证据，
但权威的记忆/历史字段已经存在。表面三元组索引原本就是无内容索引。
删除索引、合并相同文字的证据，或者只索引一个来源字段，都会改变检索或溯源，
而不只是去掉冗余载荷。

## Decision

- 词法 FTS5 使用 `content = '', contentless_delete = 1`，保留原列布局、
  tokenizer、汉字二元组转换、词项位置和文档长度。直接读取 FTS 的文本列
  得到 NULL；正文和证据仍保存在各自的权威表，独立保留 ID、角色、作用域、
  时间及关系。
- 增加可空、带唯一索引的 `memory_fts_registry.lexical_rowid`。registry
  自身 rowid 仍对应表面索引。迁移保留旧词法 rowid，包括 BM25 同分顺序和
  有限候选集合；日常刷新继续沿用词法文档的追加顺序。
- 查询和删除使用各自的 rowid 映射。检查器及当前只读存储代码只查询 FTS
  schema 元数据，兼容未迁移的旧库，也能读取写入方原子升级后的布局。
- 在一个 savepoint 内，从权威正文、节点名、历史内容和召回触发词标记重建
  两个索引。registry 列/索引、倒排数据及
  `fts_storage_format = contentless-registry-v1` 一起提交。
  保留原 `fts_text_format`，因为词项语义没有变化。失败恢复旧 schema、
  行和标记；调用方外层事务也能回滚迁移。
- 单文档刷新原子更新两份索引及映射。已完成迁移的打开操作只修复缺失映射，
  不重建全文；注册和修复排除已删除记录，避免重开后把忘记的内容重新建索引。
  冷存、恢复及删除共用一致的清理路径。
- 不更改页大小、向量表示、原始字段或持久性，不自动执行 `VACUUM`。

## Alternatives considered

- **外部内容 FTS：** 汉字二元组及“证据加触发词”字段不直接等于权威字段。
  再建物化内容表只是搬走全文副本。
- **词法索引复用表面 registry rowid：** 旧刷新会追加词法文档，表面 rowid
  则保持稳定。合并映射会改变同分顺序及 LIMIT 选中的证据。
- **历史与正文跨表共享文字载荷：** 相同字节可能共享，但需要另行迁移 API
  和生命周期；独立证据不能合并，摘要也可能不同于原文。本轮明确只去除
  FTS 的全文副本。
- **去掉 FTS 或合并不同字段的倒排项：** 会改变中文检索、表面锚点、
  BM25 字段长度或召回质量。

## Consequences

[有界本地实验](../../experiments/store/contentless-fts-2026-10-07.md)在 300 条
合成记录上去掉 418,580 字节的逻辑 UTF-8 FTS 全文，权威字段、向量表、
排名、两种 rowid 映射和行数保持不变。迁移时分配大小没有缩小；单独对
实验夹具做压缩后，端点分配约减少 20.0%。这不是云端节省或延迟估计。

表面 FTS 已经要求 SQLite 支持 contentless-delete，没有提高引擎版本下限。
但所有读写端必须使用匹配的 registry 感知代码。旧程序读取
`memory_fts.memory_id` 会得到 NULL，旧删除方式也无法定位文档。
不要在迁移后的库上混用旧写入程序，也不能仅回退可执行程序。
集成端应一起升级，先迁移可丢弃的副本，并保留一致备份。
当前只读代码的兼容性不等于旧程序兼容性。

11 项回归覆盖去除载荷、正向中文/触发词 BM25 一致性、同分顺序、
溯源、更新与删除、冷存恢复、两种失败回滚、外层事务、重复打开、
检查器以及只读连接跨写入方升级。旧检索夹具现在真正创建旧式有内容表，
不再用对无内容行无效的删除谓词模拟迁移。

## Deferred

跨表共享文字、云端/WASM 部署、备份恢复、多进程崩溃升级、生产压缩、
延迟及正式召回基准均未由本轮实现或验证。

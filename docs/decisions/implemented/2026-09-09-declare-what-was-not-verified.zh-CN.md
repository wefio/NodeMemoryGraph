# 显式声明「没验证什么」

[English](2026-09-09-declare-what-was-not-verified.md)

**Status:** implemented
**Date:** 2026-09-09

## 问题

NMG 的核心失效模式是**声明跑在代码前面**：文档说某个行为已实现，代码却不交付。
RCP 记录「跑了什么」，从而堵住其中一部分缺口；它不记录「什么没跑」。

失败是可见的：收据里 `status: failed`，并在失败时写入 `evidence`。**遗漏不可见**。
一个跳过某条路由、构建不起来、没有复现步骤、只在一个平台上跑过的改动，看起来
与一个已验证的改动完全相同。缺席没有表示形式，因此既不能被审阅，也不能被计数，
更不能被检查。

Linux 内核的 AI 编码助手政策把这件事写成了硬要求，理由恰恰相反：维护者
「浪费了太多时间去分析未经验证的报告和未经测试的修复」，所以助手必须显式说明
自己**没能**构建、测试或复现什么。NMG 没有对应义务，而本仓库 2026-09-08 的几次
纠正全部属于这一类遗漏：一个从不携带覆盖率数字的收据、一个声明了却从未被读取的
字段。

## 决策

每个由 Agent 交付的改动，在承载它的 PR 里用 `## 未验证项`（英文
`## Not verified`）一节声明自己未验证的范围。该节使用仓库已有的词汇描述没有被
执行到的范围：没跑的路由、没构建或没启动的平台与环境、没覆盖的构建模式、没有
复现步骤的行为。字面内容 `None.` 表示「没有遗留项」，这是一个和其他任何声明一样
可被审阅的声明。

这份声明是关于**范围**的散文，不是证据。它永远不能替代一项检查，绿色的门禁也
永远不使它变得多余：`gate.fullGateRun: false` 的收据、`documented-only` 的断言、
以及证据只是一个具名测试而非某个行为的检查，正是必须写进这一节的情形。

规范规则住在 `skills/repo-development/SKILL.md`，紧挨它所限定的交付流程；
`.github/pull_request_template.md` 让这一节出现在每个 PR 里，因此**提醒本身就是
机制**。

## 考虑过的替代方案

**写进收据。** 收据由 planner 与 provider 观察到的事实机器生成；而「我没能验证
什么」是作者对**没有发生的事**的陈述，没有任何 provider 能观察到它。写进收据
要么变成不可验证的机器文本，要么诱使验证器去认证一个它无法检查的声明。

**只依赖 `gate.fullGateRun` 与 `documented-only` 断言。** 它们记录「覆盖是部分的」，
不记录「作者知道缺什么、并选择不覆盖」。后者才是误导读者的那一种。

**在 CI 里读 PR 正文来设门禁。** GitHub 会暴露 PR 正文，检查可以要求该节非空。
但它写一个 `None.` 就能通过，并且会给一个当前输入全是本地文件的门禁引入网络与
token 依赖。提醒由模板承担，内容由审阅承担。

## 验证

- `skills/repo-development/SKILL.md` 在 PR 那一步写明该义务及其范围。
- `.github/pull_request_template.md` 带有 `## 未验证项` 一节，内含
  `**Not verified**` 一行，其指引点名路由、平台、环境、构建模式与复现步骤。
- 未完成或未验证的项使用
  [让已写明的文档规则真正生效](2026-09-09-enforce-documentation-rules.zh-CN.md)
  所拥有的 `## Deferred` 小节。
- 合并后的 PR 的读者不必读 diff 就能回答「这个改动没验证什么」。

## 后果

- **形式化遵从。** 一个必填小节会招来不经思考的 `None.`。它与改动在同一次
  审阅里被读，而一个错误的 `None.` 是关于已知范围的可检查声明。
- **没有门禁。** 没有任何东西检查这一节是否填写，因为没有任何测试能区分「这个改动
  无需验证」与「这个改动声称它无需验证」；一道门禁写一句话就能通过。
- **与取舍记录重叠。** 决策已经会记录自己放弃了什么。本节的边界更窄：一个没有被
  验证的范围，而不是一个被接受的取舍。两者并存时，取舍记录拥有取舍，
  `## Deferred` 拥有遗漏。

# 持续工作状态的日常使用

**Status:** implemented
**Approved:** explicit
**Relates to:** [状态写入](2026-10-08-ag-working-state.md), [按回合携带](2026-10-08-ag-working-state-input.md)

[English](2026-10-12-working-state-daily-use.md) · [术语](2026-10-12-working-state-daily-use.terms.yaml)

## Problem

状态写入与携带机制不等于日常可用的进度入口，也没有自行决定 Agent 何时
更新。每次翻历史或搜索记忆来确认进度，背离持续状态的目的。用户要求先让状态
闭环可用，再进行其他 AG 改进。

## Decision

共享 Agent 策略通过已有、显式开启的 `working_state` 会话租约维护简短状态锚点：
目标、已验证完成及来源、当前步骤、下一步、阻塞。仅在实质变化时完整替换，区分
计划、已实现与已验证。这是指令驱动的维护，不是自动进度分类器，也不强制模型
续跑。模型可见策略的唯一来源仍为 `src/prompts/nmg-prompts.yaml`，Skill 路由到
操作说明。

Pi 从本回合消息所携带的同一份、完整准入的快照读取状态，在编辑器附近提供只读
预览。默认显示六行原文，更多内容明确提示 `/nmg state` 完整查看。子命令通过
宿主通知 UI 返回完整准入文本，RPC 客户端也可接收；`/nmg state on|off` 只切换
预览显示，不改状态、不改携带、不写披露账本；两个状态入口同时出现在 `/nmg`
无参交互菜单里（与召回、唤醒同级），因此扩展不新增顶层命令；非终端模式不设置终端
widget。不发送模型消息，不追加会话条目，不授予写租约，不搜索记忆，不写披露账本。

启动/重载和状态工具结果刷新显示，无空闲轮询，也不每次模型调用读一份快照。
展示请求代数阻止旧响应越过更新的读取、会话启动和退出回写。外来或未完整准备的
快照、owner 读取失败不能把旧进度显示为当前，也不为本回合贡献状态正文。无状态
或 clear 移除 widget。用户界面显示不证明最终 provider 输入。

任务完成后撤销写租约，最终状态仍可读取。frame/session 淘汰、release 或 daemon
重启可能移除状态。必要进度事实留在仓库或明确共享任务引用中；状态缺失后依
当前证据重建，不从展示缓存恢复，也不猜测延续。会话 frame 回退不保证语义任务
识别或 A→B→A 恢复。

## Consequences

核心写入、存储、权威、公用 RPC 和模型工具不变。Pi 只承担本地显示与生命周期
映射；其他宿主可复用同样的快照/准备契约，共享更新策略不依赖 Pi。

安全/契约测试覆盖最新状态、直接完整读取、clear、会话隔离、owner 故障、外来
快照、迟到响应和退出、明确预览裁剪、RPC/终端区分，以及模型历史保护。加载的
Pi factory 配合真实隔离 HTTP daemon 验证快照至 widget、完整命令通知、按回合携带、直接写
去重、撤销写租约后最终状态仍可读，以及 clear。这些是限定范围的机制验证，不证明模型自然遵循、终端视觉效果、
token 收益或最终 provider 确认。

## Alternatives considered

- 新任务/状态库或持久展示缓存：不采用；既有私有 AG 承载一个临时值，事实权威
  仍在原 owner。
- 从每个工具结果推断进度或完成：不采用；Agent 维护有证据的公开状态，adapter
  不猜事实。
- 为状态更新强制增加模型调用：不采用；不引入续跑循环。
- 每次查看都搜索语义历史：不采用；快照直接寻址当前值。
- 把每次状态显示写入模型/会话历史：不采用；用户展示不是新输入源或最终披露收据。

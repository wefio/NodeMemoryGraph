# 在写边界拒绝没有期限的流程位置

[English](2026-10-23-coordination-state-write-guard.md) · [术语](2026-10-23-coordination-state-write-guard.terms.yaml)

**Status:** implemented
**Approved:** explicit
**Relates to:** [机制而非策略](2026-09-21-mechanism-not-policy.zh-CN.md)

## 问题

`assessMemoryWrite` 原本拒绝三类：密钥、显式「不要保存」指令，以及一小串临时词（`temporarily`、`for this session only`）。这三条都是**措辞检查**，而该边界自己的注释写明：harness 负责不变量，语义价值仍归模型判断。

漏过去的是一整类：**关于进行中流程当前位置的断言**——「本地 main 领先 origin 16 个提交且未推送，等 PR」「下一步是重跑门禁」。它的措辞里没有任何临时标记，于是以**无期限**的形式入库了。写入当天为真、第二天为假；它与活的来源（`git log`）重复；而且没有任何东西标记它已失效。**一条读起来像现状的过期记忆，比没有记忆更糟**，因为后续会话没有理由怀疑它。

扩临时词表解决不了：缺陷不在「临时」这个词，而在**没有期限**。

## 决策

流程状态类陈述默认拒绝，唯一放行方式是调用方**说明它在什么时候不再成立**。

- 新增评估原因 `coordination_state`，由一组很窄的模式匹配：`unpushed`/`unmerged`/`uncommitted`、`not yet pushed|merged`、`pending review|merge|push|approval`、`next step`、`N commits ahead of origin`、`waiting/blocked on … to land|merge`，以及对应的中文表述（未推送、尚未合并、待办/待定/待审、下一步、领先 origin、等…落地后再）。
- 该规则的逃生口是 **`expiresAt` 而不是 `bypass`**：给断言一个终点，正是无期限记录所缺的信息。`bypass` 仍然可以覆盖——显式 unsafe 必须保持无条件，否则它就不再有审计意义。
- `memoryType: "event"` 与临时词规则一样豁免：事件记录的是**有日期的一次发生**，不是当前状态。
- 绝不匹配光秃秃的动词。「合并必须通过门禁」「发布顺序是暂存再生产」这类**只提到流程词汇的持久规则**照常放行。

Agent 策略文本也点明了这一类，使规则既写在调用方读得到的地方，也落在无法争辩的地方。

## 考虑过的替代方案

- 把 `pending`、`waiting`、`next` 直接加进临时词表：太宽，「等待是重试循环的失败模式」会被误拒。
- 让模型自己判断持久性并据以拒绝：这正是边界要从模型手里拿回来的职责。
- 直接拒绝而不给期限通道：没有正当路径，真正有界的调用方只会改写措辞来绕过检查。
- 接受后靠衰减/排序自然过期：衰减缩短的是寿命，不是**调用方从未给过的边界**。

## 后果

写入一份进行中工作的快照会失败，而失败原因直接指出修法：给它期限，或放进工作状态。拒绝经既有的 rejected-write 路径记录，这一类的发生频率因此可观测，而不是靠回忆。

该模式集是启发式的，既有漏（完全不含流程词汇的状态断言），也可能误伤（一条读起来像状态的持久规则）；后者仍可用 `bypass` 走审计通道。本记录**不声称**边界已能拦住所有临时写入，只声称**这一类**不能再无期限入库。

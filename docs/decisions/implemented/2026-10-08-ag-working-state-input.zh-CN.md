# 每用户回合一次携带 AG 工作状态

**Status:** implemented
**Approved:** explicit
**Relates to:** [持续工作状态](2026-10-08-ag-working-state.zh-CN.md)

[English](2026-10-08-ag-working-state-input.md)

## Problem

替换状态本体不会替换对话历史中的旧正文，所以每个回合都得重新呈现当前值。
但在一次回合内的每次模型调用前重新呈现是另一件事：它重复发送同一份正文、
挪动上一份正文的位置，还需要一套删除与依据计划来防止副本累积。回合边界
没有这个问题——它本来就是追加新上下文的地方。

## Decision

按用户回合、经既有共享准备契约和 Pi 薄适配携带一次状态。部署顺序仍是先改
适配层，再加载插件并使用验证后的 NMG 程序。这不等于最终发送确认或 C 整体
完成。

- `working-state-input.ts` 从当前 daemon snapshot 准备一份专用暂时正文，复用
  完整正文输出预算。元数据绑定 session、AG incarnation、frame、捕获 binding
  和内容／文本哈希；这不是认证，宿主元数据不进入模型正文。
- Pi 每个用户回合只携带一次该正文，作为带标签的 `<nmg_working_state>` 块，
  位于宿主本就从 `before_agent_start` 返回并会持久化的 `nmg-context` 消息
  内。扩展不注册 `context` 钩子：同一回合内后续模型调用不再重发，也不改写
  或移除任何更早的位置。
- 混合 recall 投影继续排除状态（`includeWorkingState: false`），因此一个回合
  不会以两种形状携带同一份值。
- 回合中途要读状态，用会话历史里已有的那份，或用只读 `/nmg state` 视图；
  不新增模型侧只读入口。
- 失败关闭：缺失、异 session、不完整或超预算的正文不贡献任何块；owner 读取
  失败或读取期间 session 改变时，该回合消息不带状态正文，用户视图显示不可用。
- clear／release 从下一回合起停止携带，但不删除驻留内容；清披露也从不删除。
  压缩可以丢弃某个回合消息，下一回合会再次携带当前值，那是追加，不是改写
  已保存的位置。

## Consequences

核实的安装版本 Pi 1.1.0 的 `before_agent_start` 返回宿主会持久化的消息，本
决定即以此为携带方式。逐次模型调用的 `ExtensionRunner.emitContext`／SDK
`transformContext` 边界不再用于状态，扩展也不再每次模型调用读一次 snapshot
RPC。`context_with_system` 与 `before_provider_request` 仍能替换输入，而响应
事件只有状态／响应头，没有最终请求正文。因此 Pi 能力明确报告
`confirmation: unsupported`，本切片不写披露账本、语义记录或学习证据，也不修复
既有语义记忆披露路径。

契约测试覆盖完整当前正文、预算与异作用域失败关闭、无关历史保护、清空、不存在
逐次状态钩子、对隔离真实 HTTP daemon 的按回合携带，以及用户视图刷新。这些检查
不测量最终模型输入、token 收益、缓存效果或连续性。此前的逐次方案不被认定造成了
供应商侧缓存未命中：实测 provider payload 是追加式前缀，报告出来的未命中模式在
此不作归因。

## Deferred

- 最终请求／传输观测及精确来源确认；输出到账本前重新检查权限和版本。
- 合并动态输入预算及匹配的模型成本／连续性实验，含"每回合重复一份正文"的代价。
- 对没有持久化按回合消息的其他宿主的等价携带、可靠语义任务身份和 A→B→A
  恢复；session 工作帧退化不变。
- 生产插件 reload／daemon 替换属于独立安全生命周期操作，不能从 build 或
  适配器测试通过推断。

## Alternatives considered

- 保留逐次模型调用删除再追加正文的选择器：拒绝；它在同一回合内反复重发同一
  正文、顶替上一份正文的位置，并为一个回合边界本已解决的职责维护依据计划。
- 把正文并进混合 recall 投影而不单独成块：拒绝；recall 为空或失败时也必须携带
  状态，且状态必须与召回证据可区分。
- 删除混合 `nmg-context` 或工具参数：拒绝；状态携带不得丢弃其他约束、recall
  和原始证据。
- 新增模型侧只读状态工具：拒绝；值已在历史中，第二条读取路径可能与本回合携带
  的内容不一致。
- 根据准备消息、payload 钩子或工具成功推断最终可见：拒绝；后续变换和发送失败
  仍然可能发生。
- 修改 Pi 安装包或引入 NMG provider 执行器：不属于要求的适配层优先路径；
  不支持的确认必须明确保持未确认。

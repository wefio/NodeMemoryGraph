# 首次输出计时显式开启

[English](2026-10-04-first-response-timing-is-opt-in.md)

**Status:** implemented
**Approved:** explicit
**Relates to:** [会话钩子](../../design/session-memory-lifecycle-hooks-2026-08-10.md)

## 问题

目标是普通使用中偶发的首次可见响应前等待，排除压缩。整项任务的耗时和 assistant 完成消息的时间戳都不等于这个区间。Pi 在准备结束后构造持久化的用户消息，在生成及消息结束钩子之后保存 assistant；现有记录不能把准备等待与首次流式输出分开。

## 决策

用户允许在共享 checkout 只接入计时，不部署召回期限，不中断运行中的 Premiere 会话。`/nmg-latency on|off|status` 显式控制记录，默认关闭，会话替换、分支导航或重载不继承开启状态。共享计时原语负责身份、单调累计时间、每阶段首次标记、排除、结局及安全存储失败；Pi 绑定只观察原生生命周期事件，把纯元数据追加为不进入模型上下文的自定义条目。

用户选择只持久化慢的输入到召回区间，而不是每个被观测输入。过滤放在持久化 sink，不改变首次阶段时钟；保留的 trace 包括较短的早期边界。保留阈值、事件、隐私和解释口径由[会话钩子契约](../../design/session-memory-lifecycle-hooks-2026-08-10.md#首次输出计时)统一定义。观测包裹现有准备 handler，原异步返回值或错误原样传递；不增加召回期限，不改变模型参数、daemon 生命周期或供应商请求数量，不把 host 事件时间声称为客户端可见 TTFT。

## 考虑过的替代方案

- **使用整轮耗时或把等待归因于压缩。** 拒绝：与用户澄清的症状不同，含压缩的 trace 排除。
- **从 assistant 落盘推断首次响应。** 拒绝：输出可能更早流出，时间戳还遗漏准备阶段。
- **记录提示、供应商原始帧和请求体。** 拒绝：划分等待边界不需要原始内容，这会引入隐私和存储风险。
- **默认开启或发送探测请求。** 拒绝：调查显式开启，利用自然使用记录，不增加模型或嵌入调用。
- **只计 Core 检索。** 不足：它遗漏准备、传输、模型输出和 host 事件边界。
- **持久化每个输入或过滤单个短阶段标记。** 拒绝：快速输入增加不需要的日志量，丢掉短标记会失去起点，无法还原慢准备。

## 后果

每个输入只有有界的首次阶段元数据。召回结束前只在内存缓冲；只有满足条件的 trace 才补写完整边界序列。未完成的 trace 可在状态中查看，不伪造结束；关闭或重置时丢弃未判定缓冲。保留样本按慢准备筛选，不能代表完整延迟分布。压缩尝试或排队/steer 输入使 trace 排除普通输入对比。失败尝试在重试后仍可追溯，最终稳定才关闭 trace；缺失阶段仍然缺失。存储失败关闭观测并在状态中显示，不中断对话。

[原语测试](../../../tests/integration/first-response-timing.test.ts)验证时间身份、排除、迟到事件隔离和失败处理。[Pi 绑定测试](../../../tests/extensions/nmg/first-response-timing.test.ts)验证显式启用、事件映射、隐私、重试和重置，不调用供应商。

## 延后范围

由用户在目标会话空闲时重载并显式开启观测；源码已接入不等于运行时已加载或开启。确定性测试没有建立自然正常/异常样本对、前端发送/绘制时间或根因。Host 事件自身不能细分准确发包时刻、供应商排队或 UI 绘制；只有首次样本指向这些边界时才继续细分。

# 精确锚点查找与排序后取证

[English](2026-11-19-exact-anchor-and-deferred-evidence.md) · [术语](2026-11-19-exact-anchor-and-deferred-evidence.terms.yaml)

**Status:** implemented
**Approved:** explicit

## Problem

本地默认搜索即使收到精确标识符，也要等待查询向量。引擎在决定返回哪些候选之前已经读取了整个候选池的历史证据。SQLite 还会重复计算查询向量范数，并可能为多条记忆重复评分同一个层级向量。

## Decision

当默认本地显式搜索只含独立标识符或引号短语，且可见候选的陈述完整匹配时，词法检索可以完成该次查找。精确匹配保留标识符中的标点并检查边界。作用域、调用方指定的检索模式及附带查询遵循原有行为。

先选出返回结果，再加载证据。分数相同时沿用候选次序，证据从同一个读取版本中按既定顺序返回。SQLite 复用查询向量范数，只计算所选模型下可达的层级向量分数。

## Alternatives considered

命中任何词项就跳过向量会让常用词压过语义召回。用近似分数缩小向量候选会改变排序输入。持久化缓存会引入失效和存储成本，而这些重复工作可以在单次查询内部解决。

## Consequences

词法精确查找命中可以省掉 embedding 请求。锚点落空会在普通检索前增加一次有界词法查找。测试覆盖完整匹配、前缀命中、限定作用域的回退以及显式 hybrid 模式。固定向量可在无需连接 embedding 服务的情况下比较分数。

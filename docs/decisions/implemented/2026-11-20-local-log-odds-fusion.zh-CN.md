# SQLite 混合检索融合校准后的词法和向量分数

[English](2026-11-20-local-log-odds-fusion.md) · [Terms used](2026-11-20-local-log-odds-fusion.terms.yaml)

**Status:** implemented
**Approved:** explicit

## 问题

显式搜索和经济档分别用不同规则排序 SQLite 混合候选。统一排序需要在无需相关性标注、
无需按库调参的条件下工作。

## 决策

SQLite 在同一读取快照内，为两路候选的已授权并集提供 BM25 和向量余弦分数。
记忆引擎对每路使用正分的中位数和总体标准差校准，再以固定权重融合向量证据和 BM25 证据，
权重分别为 0.75 和 0.25。有 BM25 命中的候选将加权分乘以二的平方根，其余候选直接使用校准后的向量分。
同分时按稳定的记忆 ID 排序。

## 考虑过的替代方案

固定权重省去查询路由输入和用相关性标注估权的步骤。两个候选深度下，3∶1 的证据覆盖都高于 6∶1。
经济档在相同的默认五条预算下，使用 3∶1 也比原来的排名融合覆盖更多证据。
逐查询调整权重改变了各数据集的覆盖率，整体覆盖率没有提高。
[实验报告](../../experiments/retrieval/local-log-odds-fusion-2026-11-20.zh-CN.md)记录召回效果和 SQLite 读取开销。

## 后果

引擎先应用权限和可见性规则，再校准分数。候选选定后才读取原始证据。
SQLite 复用已有全文和向量索引，批量补齐两路分数。纯词法和纯向量模式继续使用各自的检索路径。
[显示契约](../../design/recall-context-and-display.zh-CN.md#候选排序)说明 daemon 如何把排序带入召回。

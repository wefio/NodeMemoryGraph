## 原始输入的拒绝

此前的验证器只为七个具名常驻条目设预算，而不是活动设计正文。本次角色扩展保留既有 15,000 B 阈值，将其应用到所有活动设计 Markdown（含新建的嵌套主题），并发现所有 Skill 条目而不是五个具名条目。5,000 B 的 AGENTS/决策索引预算不变。归档设计、实验来源证据与 Skill 参考材料保留各自不同角色。

六个新回归用例先针对原检查器运行：37 个测试，33 通过，4 失败。那四个失败分别是：一个 15,001 B 的新具名设计、一个过大的新嵌套主题、一个虽少于 15,000 字符但 UTF-8 字节超限的中文文件，以及一个新具名的 Skill 条目。恰好 15,000 B 的接受与历史/证据角色边界此前已通过。扩展检查器之后，37 个测试全部通过。

在任何长源文件被改动之前，真实的 `npm run docs:check` 以 **1** 退出，报告 **21 个字节预算错误**、无警告。具有代表性的原始输入：

| 原始路径 | 原始 UTF-8 字节数 |
| --- | ---: |
| `docs/design/design.md` | 200,588 |
| `docs/design/task-unit-semantics-obligations.md` | 206,542 |
| `docs/design/task-unit-semantics.md` | 61,514 |
| `docs/design/ooo-execution-bootstrap.md` | 55,352 |

那个 200,588 B 的读数属于 `design.md`，不属于 `task-unit-semantics.md`。21 个原始输入逐一与其基线 Git blob 精确比对，并在迁移前记录其 SHA-256。合成夹具补充了这次真实拒绝的结果；它们不能替代它。

## 职责迁移

既有的整章一起移动。最大的职责先被路由出去；相邻的小型说明留在其当前所有者中。仍然过大的章节在它自己既有的小节处划分，而不是按等字节或等行区间切分。生命周期义务表被分为 Store/port/借用视图义务与 host/运行记录/daemon 客户端义务两部分，每一整行都被保留。

该操作产出 106 个文档输出：21 个原始条目、**84 个受同一 15,000 B 预算约束的新活动设计主题**，以及一份带日期的历史阅读记录。Markdown 表格的列填充被移除，单元格文本不变。这不是切分的替代品，也不是抬高上限。

唯一的一处证据迁移是 ledger 的历史 `Verification commands` 区块。其原始工具名、历史失败、修复、注意事项、耗时与计数都保留在[该阅读记录](task-unit-semantics-ledger-readings-2026-10-14.md)中，并带双向导航。当前义务行与规范性设计正文仍留在受预算约束的设计单元内；它们没有被移进豁免的实验目录。

父条目链接完整的职责，子条目链接其父作用域。必需的定义仍是显式的本地引用，而不是"去读每个父页面"的一揽子指令。23 处既有的 Markdown 入向引用被重定向。七个既有术语指针被更新为实际的契约所有者，保留了全部名称与别名。

## 验证与界限

一个独立的守恒探针检查了全部 21 个原始 Git 哈希以及每个原始非空源行原子，其中表格对齐被归一化、标题层级被忽略、本地链接目标被规范化。所有源原子都仍在。义务行 ID 保留了精确的重数；一个删除 D1 行的负控被拒绝。这是一次有界的文本检查，不是语义等价或写作质量的证明。这些探针是一次性工具，不是新的文档平台。

迁移后的第一次检查发现三处被误当作 frontmatter 暴露的正文标签、一个被错误重定根的尖括号外链，以及六个陈旧的术语 owner anchor。这些失败被修复而不是绕过：由小节标题界定元数据区、外链保持外部、术语指针解析到其新所有者。

修复之后，`docs:check` 报告 **431 个文件，0 错误，0 警告**；`glossary:check` 报告 **17 个术语，0 错误**。验证器/卫生/术语合并目标套件通过 **67/67**。对改动过的验证器/测试代码与两个临时探针，LSP 诊断为零。

另一次有界的 Markdown 片段审计把基线的 372 个 Markdown 文件与迁移后的 458 个相比。它识别出 162 条基线与 165 条当前片段边，未发现新出现的断链目标。十六条先前存在的断链边仍被标为基线问题，而不是被静默计为有效；该解析器不是通用的 Markdown 语义验证器。

2026-10-15，完整定向运行 `c4d265e0-793d-43fb-b1fc-057f10e87108` 完成了全部 **16 项阻塞检查**，每项都是原生退出 0（`04:10:00.564Z`–`04:11:46.013Z`）。research 与 chaos 仍按策略跳过。外层任务工具调用随后报告超时，尽管原生证据已完成；那次包装调用不被报告为成功。随后的仅处理 EOF 的清理移除了多余的文件末尾空行，`git diff --check` 通过。

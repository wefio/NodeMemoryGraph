## 协议

在同一份 Windows 工作树与 Node v24.19.0 上，先用该路由原有的嵌套 `verify:static` 检查运行 `rtk npm run agent:verify -- --full`，再运行由 `ci-and-tests` 声明该契约原子检查的版本。变更后的测试断言该路由的原子清单与 package 脚本完全一致。两次运行都使用默认的 150 秒整次运行预算，并执行全部阻塞检查；research 与 chaos 检查仍为建议性。该工作树中还包含未提交的整次运行时限改动与导入影响探针。

## 观察

| 方案 | 端到端 | 产品测试 | 其他检查与开销 | 阻塞结果 |
| --- | ---: | ---: | ---: | --- |
| 嵌套静态检查加独立的路由检查 | 137.3 s | 85.1 s | 52.2 s | 通过 |
| 原子静态检查，按名称去重 | 102.3 s | 72.9 s | 29.4 s | 通过 |
| 文档更新后的原子静态检查 | 107.4 s | 72.4 s | 35.0 s | 通过 |

第一次运行报告了八个阻塞命令结果。第二次报告了 13 个原子结果，每个都带路由归属。原有的 `verify:static` 脚本包含六个命令，而完整计划也独立运行了这六个命令。它们在第一次运行中的独立耗时合计 17.5 秒。观察到的非产品时间下降为 22.8 秒；运行间波动与 npm 启动开销使得无法把这一下降全部归因于路由改动。原文报告产品测试耗时波动 12.3 秒，但显示的舍入后表格在首组对比中为 85.1−72.9 = 12.2 秒，若使用第三行为 85.1−72.4 = 12.7 秒。本轮未重新核对未舍入的耗时账本；12.3 作为尚未解决的原报告值保留，不作为重算证据。

报告记录原子运行有 1,533 个产品测试通过。前两行是原始对比，第三行在文档更新后运行，不是对完全相同输入的重复。它们记录了重复执行及观察到的耗时下降；它不证明对每个仓库状态或每台机器都低于 150 秒的最坏情况界限。最终那次运行包含决策、设计与本文档；它通过了全部 13 项阻塞检查。完整验证器仍是当时实验最终判定的来源。137.3／85.1 秒这一组数值也出现在[影响探针报告](impact-probe-2026-09-23.zh-CN.md)中；两份摘要没有为这些相同数值提供不同的原生 run ID，不能因其出现在两篇文档中就计为独立重复。

## 被认证的是什么

此处认证是统计工具结局，不是上线许可；风险要求 accepted > 0，全弃权不是零风险证书。按题不重叠不证明用户／对话独立或题间 i.i.d.。
精确二项检验还需抽样假设与有效候选族构造。旧文从标定集派生截断，当前协议改在训练集
构造；单个 alpha 下对一个格点族做 Bonferroni，不验证任意自适应候选、反复调 test 或
所有 alpha 同时选择。条目整群 bootstrap 是近似，不是题级二项检验的同一个精确有限样本定理。

问题不是"精确率是多少"，而是**"这个闸门可以上线吗？"**：

- **单元：** 一道题。当闸门为某题保留至少一个候选时，我们说该题被**接受**；当被保留的**每一个**候选都是噪声（无 gold）时，被保留的题就是一个**错误**。选择弃权的闸门不暴露任何内容，因此不算错误。
- **风险** `R(λ)` = 错误数 / 接受数，对应阈值对 `λ` =（集合级截断，模型下限）。**α** 是承诺：`R ≤ α`。
- **检验。** 在一个标定切分上（n = 307 题，与模型的训练切分不相交，且模型的 Platt 标定刻意**不**拟合——下限是一个自由的格点轴），对每个阈值对的错误数用精确单侧二项尾检验 `H: R > α`，当 `p ≤ δ / |lattice|` 时认证通过（Bonferroni，δ = 0.05；BalanceRAG 的顺序图检验是更紧的替代方案，我们未实现）。
- **格点：** 67 点 = 一个无闸门基线 +（4 个 cv 截断 + 7 个 QPP 截断）× {模型关闭，下限 0.2/0.35/0.5/0.65/0.8}。所读 `latticeSpec` 包含该基线，解释按这些已报轴为何是 67 而非 66。旧分位数用该切分自身分数。后来的 109 点属于另一控制器扩展格点（增加 42 点与七个截断 × 六个下限相容），未恢复完整旧截断列表。
- 选中的是**接受率最高的已认证阈值对**，然后在留出检验切分（n = 307）上重新评估。这是额外留出检查，不是总体保证或抽样独立的证明。

集合级分数取原始尺度的 `cv`（已上线的程序闸门）或产品自身的 QPP 分数（`composeQpp` = `top1 + 0.5·nqc`，`src/core/qpp.ts`，由缓存的、有界混合分数重建）。

## 约束一切的那个数字

检验题中仅 **48 / 307（15.6%）** 在这个固定池中有 gold，纯移除闸门不能找回池外 gold。
全接受的题风险为 84.4%（至少 84%），但选择性闸门不承受同一风险下界。接受比例 a、
含 gold 比例 c 且 a > 0 时，理想选择器风险下界为 max(0, 1 − c/a)。c = 15.6%、接受率
10% 时，池覆盖本身不排除零风险；测到的阈值族前沿不是普适最优风险界。

## 前沿（在标定上选定，检验沿用相同下限）

`q` = 题级风险，`c` = 候选风险（注入项中噪声的占比），`n` = 接受单元数，`acc` = 接受率。

| 点 | cal acc / q / c / n | test acc / q / c / n |
| ------------------------ | ---------------------------- | ---------------------------- |
| 无闸门（全接受） | 100.0% / 83.1% / 94.3% / 307 | 100.0% / 84.4% / 94.7% / 307 |
| cv ≥ 0.0583，模型关闭 | 25.1% / 53.2% / 84.4% / 77 | 26.4% / 63.0% / 87.2% / 81 |
| cv ≥ 0.1414，模型关闭 | 10.4% / 34.4% / 78.1% / 32 | 9.8% / 36.7% / 77.8% / 30 |
| cv ≥ 0.2652，模型关闭 | 2.9% / 11.1% / 70.4% / 9 | 2.0% / 33.3% / 77.8% / 6 |
| cv ≥ 0.1414，模型 ≥ 0.5 | 3.3% / 10.0% / 10.0% / 10 | 2.3% / 14.3% / 14.3% / 7 |

模型下限**以接受 3% 而非 10% 的题为代价**，换来注入噪声的大幅下降（同一截断下 78% → 10%）。

## 等接受率前沿（稳健比较）

"至少接受 L"时的风险，标定 → 检验，模型关闭对比格点中的最佳点：

| L（题级单元） | 模型关闭 | 任意点 | 选中点 |
| ----------------- | ----------- | --------------- | -------------------------- |
| 5% | 34.4 → 36.7 | 12.5 → 35.7 | qpp ≥ 0.3847，模型 ≥ 0.35 |
| 10% | 34.4 → 36.7 | **26.3 → 51.4** | qpp ≥ 0.3529，模型 ≥ 0.2 |
| 15% | 53.2 → 63.0 | 35.4 → 52.5 | qpp ≥ 0.2826，模型 ≥ 0.2 |
| 20% | 53.2 → 63.0 | 53.2 → 63.0 | cv ≥ 0.0583，模型关闭 |
| 30%, 50% | 75.8 → 83.2 | 75.8 → 83.2 | qpp ≥ 0.3529，模型关闭 |

从 20% 接受率往上，模型不改变任何东西；在 10% 处，它表面上的标定优势**在检验集上反转**（36.7% → 51.4%）。

## 认证

| α | 判定 |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0.10 – 0.50 | 两个家族（cv 或 qpp）**都没有任何阈值对通过认证** |
| 0.60 | cv ≥ 0.0583，模型 ≥ 0.2：cal 11.7% / q 27.8% / n=36 → **test 8.8% / q 40.7% / n=27**；或 qpp ≥ 0.2826，模型 ≥ 0.2：cal 15.6% / 35.4% / n=48 → **test 13.0% / 52.5% / n=40** |
| 0.70 | cv ≥ 0，模型 ≥ 0.2：cal 16.0% / 36.7% / n=49 → test 13.0% / 52.5% |

条目单元的运行在下面单独一节报告；那才是最初那条抱怨所针对的承诺，而它的行为不同。

## 条目级：最初那条抱怨所针对的承诺

本表 n 是保留条目数、acc 是条目接受率；前面按题计数。`DROPS` 表示新切分未通过同一
统计界，不必然表示观察噪声高于 alpha：alpha 0.40／0.50 下的 14.3%／23.1% 点风险仍
低于目标。源码 `boundHolds` 确认会重做二项／bootstrap 判据。有限整群重采样不能排除
未见错误；观察到全零噪声的簇重采样仍全零。

"自动召回注入的多是噪声"是一个**条目级**主张（被注入 memories 中无关的占比），而不是上面那个题级主张。两者需要不同的检验，因此 `--risk item` 用**对题做整群自助（cluster bootstrap）**来界定被注入条目的**聚合**噪声占比——同一题内的条目彼此相关，所以对条目做精确二项检验会过于乐观。

基线：无闸门时注入条目中 **94.3% cal / 94.7% test** 是噪声；在已上线的程序截断下（`cv ≥ 0.0583`）为 **84.4% / 87.2%**。

| α | 通过认证的阈值对 | cal: acc / 噪声 / n | test: acc / 噪声 / n | 是否保持 |
| --------- | -------------------------- | -------------------- | --------------------- | --------- |
| 0.10 | cv ≥ 0.2652，模型 ≥ 0.2 | 0.7% / 0.0% / 6 | 0.3% / **33.3%** / 3 | **下降（DROPS）** |
| 0.20–0.30 | qpp ≥ 0.3847，模型 ≥ 0.35 | 1.7% / 12.5% / 16 | 1.5% / **35.7%** / 14 | **下降（DROPS）** |
| 0.40 | cv ≥ 0.1414，模型 ≥ 0.5 | 1.1% / 10.0% / 10 | 0.8% / 14.3% / 7 | **下降（DROPS）** |
| 0.50 | cv ≥ 0.1414，模型 ≥ 0.35 | 1.5% / 14.3% / 14 | 1.4% / 23.1% / 13 | **下降（DROPS）** |
| 0.50 | qpp ≥ 0.3529，模型 ≥ 0.2 | 4.1% / 26.3% / 38 | 3.8% / **51.4%** / 35 | **下降（DROPS）** |
| 0.60–0.70 | cv ≥ 0，模型 ≥ 0.2 | 5.3% / 36.7% / 49 | 4.3% / 52.5% / 40 | **下降（DROPS）** |

由此得到两点，而它们指向相反方向：

- **条目级承诺是可形式化、且能在标定上通过认证的**，不像题级承诺——在 α = 0.10-0.50 有阈值对通过认证。
- **每个所报选中点在留出统计界复查中都标为 DROPS。** 旧称“1.4-2.5 倍”不统一：12.5% → 35.7% 约 2.86 倍，0.0% → 33.3% 没有有限比值。工作点只留 6-49 项；小样本、重采样限制及切分差异均需关注，不是单独证明样本量导致结果。

**哪个旋钮真正改变条目噪声？** 不是集合级截断：丢弃 90% 的候选（`cv ≥ 0.1414`）仍留下 78.1% 的噪声，因为 `cv`/QPP 是查询级分数，对"被保留的题里哪个条目是垃圾"一无所知。真正改变它的是条目模型（94% → 10-24%），而且只能通过只保留 1-2% 的条目做到。这就是为什么两个旋钮是互补而不是二选一，也是为什么自动注入策略可以精确率优先（大多数时候什么都不注入），而显式检索仍保留召回。

## 闸门控制器："开多大"能学到东西吗？

控制器（`--controller-cuts`，打印在格点那一行）是一个 12 特征的查询级头，其目标是"这个池里到底有没有 gold"；它决定**闸门开多大**，从不决定保留哪个候选，因此不拥有删除权限。它在同一 train 切分上训练，在同一格点中认证（现在是 109 个点，因此每个家族的 Bonferroni 阈值都更紧）。

- **它确实小幅改善了集合级前沿。** 在 15% 与 20% 接受率下，最佳点是模型关闭时的 `controller ≥ 0.1663`：题级风险 **48.1% → 56.3%**，而最佳常数 cv/QPP 截断为 53.2% → 63.0%。所以按查询的截断并非空洞：它用到了单一全局截断看不到的信息。
- **它对条目级承诺毫无帮助。** 没有任何控制器点在 α ≤ 0.10 通过认证，而在它能通过认证的地方（α ≥ 0.20），其检验噪声比常数截断更差（42.9% vs 35.7%）。

## 发现

1. 84.4% 无 gold 限制固定池覆盖，不限制所有接受率下的选择精确率。10% 接受率下约
   34% 风险属于所测候选族，不是所有可能闸门的界。
2. 报告中的题级族在 307 道标定题、67 点下，没有低于 alpha 0.60 的认证。这是依赖
   输入／假设的工具结果，不证明其他方法不能认证。
3. alpha 0.6／0.7 点的标定风险为 27–37%、检验为 41–53%；重新认证失败不等于
   检验点风险超出 alpha。
4. L = 10% 的标定优势在 test 上反转，L = 20% 起选中模型关闭。L 是标定接受率下限，
   不一定是相同留出覆盖率；AUC 0.89 不能决定策略。
5. cv／QPP 的所报前沿在这个有限比较中重合，不证明查询排序完全相同、跨路径不变或普适相等。
6. 所测 cv ≥ 0.0583 点的标定条目／题风险为 84.4%／53.2%，全接受为 94.3%／83.1%；
   test 为 87.2%／63.0%。单位及切分须分开，这不是当前默认审计。
7. 条目头所报 94% → 10-24% 噪声变化发生在 1-2% 条目接受率，不证明只有该模型能
   达到，也不使标定工具通过成为总体保证。
8. alpha 0.10-0.50 的条目标定通过未通过留出统计界复查。保留 6-49 项很小，但这
   不为统计方法或切分构造免责。
9. 20% 接受率下控制器标定题风险 48.1% 对 53.2%、test 56.3% 对 63.0% 是描述读数；
   条目 test 噪声 42.9% 对 35.7% 在该比较中更差，不证明经重复验证的通用收益。

## 这意味着什么

- 保留原先**不启用模型、不替换默认**的建议。旧理由称 41–53% test 风险“更差”方向
  错了：题风险 40.7%／52.5% 低于 63.0%，87.2% 则是条目风险，不能跨单位比较。
  接受率也不同（约 9-13% 对 26.4%）。不晋升的依据是留出统计界未保持及证据有限，
  不是该反向比较。
- 标定通过与 HOLDS 检查是评估证据，不足以授予运行时权限；当前数据准入、自然验证及
  经审阅启用策略仍分开，本文不创设启用流程。
- `.benchmarks/retrieval-stores/` 的五个已报 store（`locomo`、`longmemeval`、`beam`、
  `halumem`、`personamem`）曾支持多 store 提案。至少两个不证明独立样本增大十倍或
  实测便宜；当前 memory benchmark 仅用于评估，本文不授权新训练／实验／花费。
- 纯移除闸门不能创造固定输入池中没有的证据。

## 什么会改变答案

- 更高的池上限（恢复 embedding 路径）——最主要的杠杆。
- 更多标定题，或多 store 标定，让有限样本检验有东西可咬。
- 一个 `cv`/QPP 看不到信息的集合级信号（查询与保留集合之间的语义一致性，即由 embedding 派生的特征）。

## 复现

以下保留旧命令／切分描述，不是当前可运行配方；当前 trainer 要求 manifest 及训练集
派生格点，须按训练 owner 操作。本轮未执行命令。

```bash
node --experimental-strip-types tools/relevance-model-train.ts --certify \
  [--risk question|item] [--alphas 0.1,0.2,0.6] [--delta 0.05] \
  [--cv-cuts ...] [--qpp-cuts ...] [--controller-cuts ...] \
  [--model-floors ...] [--json]
```

`--risk question` 对题使用精确二项检验（题间独立同分布）；`--risk item` 使用对题的整群自助，因为同一题内的条目相关。每个通过认证的阈值对都在检验切分上重新检查，并报告为 `HOLDS` 或 `DROPS`。

输入：缓存的按查询分组的 LoCoMo store（`.benchmarks/retrieval-stores/locomo-groups.json`，构建时不使用 embedding 服务）。切分按题进行（每第 5 题给检验，再下一个第 5 题给标定，其余给训练）。该运行断言行切分非空、池上限非零、且 `errors ≤ accepted`；它拒绝从空的一侧打印数字。

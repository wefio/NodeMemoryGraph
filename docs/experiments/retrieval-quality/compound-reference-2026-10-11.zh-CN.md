## 冻结的问题与对照臂

在实现之前于 2026-10-11 冻结。基线修订：`09cd5495296b45f9edf668972ebfcc112b4567a5`。这个隔离候选检验：在取回相同规范记录的前提下，现有共享文本检索 → get 能否比完整 UUID 使用更少 token。排序、预览长度、记录正文、存储身份、live provider、部署与第三个对照臂均不改变。

基线：完整 UUID 的文本 header 与 get 输入。候选：NMG 生成的 `ref:<hex-prefix>|<quote>` 键，被整段复制进现有 get 的 `memoryIds`，并带上现有 `activeGraphId`。前缀从四位十六进制数字起，每次增加两位，直到该组合在该图可读的原始候选集合中唯一匹配一个规范 ID。引文取空白归一化后陈述的前六个 Unicode 码点，并去掉尾随空白。匹配是字面、区分大小写的，不做 NFKC 或模糊归一化。UUID 前缀比较不区分大小写并排除短横线。不符合 UUID 文本形状的 ID、已撤回记录、空引文、行分隔符，或并不比 UUID 文本更短的引用，回退为完整 ID。此长度守卫使用 JavaScript UTF-16 字符串长度，不是编码 token 成本。deferred／folded 的仅 ID 行保留 UUID；它们不会获得未作为预览显示过的内容。

引用是图作用域的选择器，不是持久标识符或认证凭据。缺失的、外来的或过期的图，以及零匹配／歧义匹配，都 fail closed；不做 latest-graph 推断，也不做自动重试。完整 UUID 在没有图的情况下仍可使用。引文改变可以使引用失效，而后缀改变不改变记录身份。现有精确 get 的脱敏、过滤与规范归因仍然权威。不增加工具或模型解码步骤，不独立存储别名映射，不新增环境 gate。

RPC service 提供图／会话／store 检查及当前可读目标。纯共享库解析器依赖调用者提供原始作用域和当前目标；其默认 `currentTargets = targets` 不会独立刷新记录内容或强制图归属。

原始诊断结果与紧凑 JSON ID 仍是规范的。共享文本渲染可以消费一份派生引用映射；对原始 JSON 消费者或最终 provider payload 而言，这不是省 token 的主张。

## 固定的验证与测量单元

安全／契约用例：被复制的引用与规范 ID 等价；重复引文；ID 前缀碰撞；剩余歧义；零匹配；畸形键；Unicode 与归一化；陈述编辑；撤回；混合／批量请求；会话／项目／图归属；图过期；规范披露记账；普通 JSON-RPC 与共享库函数。不允许任何候选选择第一个歧义结果，或改变检索顺序／正文／预览。

两臂 token fixture：英文单条、中文单条、混合 13 条长记录、重复引文但 ID 不同、前缀碰撞但引文不同、前缀与引文都碰撞因而需要扩展、标点／完整 ID 回退、Unicode、已撤回、空、deferred 与 folded。每臂统计完整共享 search 显示、实际序列化的 get 参数、精确 get 显示，以及变更过的 get 工具描述一次。两臂都保留必需的图 ID。记录各组成部分的差值与所有输入字符串；重复的引文文本是成本，不是额外有用信息。使用已安装的 tiktoken 0.13.0、`cl100k_base` 与 `o200k_base`，不安装任何东西，也不把这些当作与模型匹配的计费测量。

负例单元的字符串／成本单独报告，绝不作为成功读取的节省。还要报告一次失败引用之后显式恢复规范 ID 的成本，包括其额外调用；并未把这种恢复实现或承诺为「无额外调用路径」。把正常的被复制引用与 UUID 比较，而不是与一个臆造的更短 ID 最优值比较。保留规范紧凑 DTO 以及全部预览与精确正文字节。对 1／13 条记录收集一次有界的本地 CPU 观察，不臆造在线延迟保证。

## 退出规则

只有当安全／契约检查通过、使用引用的正常 fixture 链在两种点名编码下都使用更少 token、且回退／空／deferred／folded 单元不增长（除显式分列的 tool 指令增量外）时，才接受这个隔离原型。要求定向检查、LSP、阻塞性验证与一份干净修订的退出回执。若该引用格式无法满足这些，就回退原型，而不是扩到 ID 生成、排序或模型评测。通过本试验不是批准合并、部署、重启 daemon，也不是对语义相关性、任务质量、cache 或计费收益的主张。

## 结果

正常矩阵保留所有预览字节、精确输出字节、规范 DTO 与披露条目。十二个 fixture 中有七个、共 22 个显示的引用解析到相同的规范 ID。其余五个是标点、已撤回、空、deferred 与 folded 控制：其规范／回退或空流水线保持不变；空 fixture 不是成功读取记录。共享 get 描述指令在每种点名编码下增长六个 token。

| Fixture | cl100k_base 基线 → 候选 | o200k_base 基线 → 候选 |
| --- | ---: | ---: |
| 英文单条 | 445 → 419 | 447 → 421 |
| 中文单条 | 462 → 440 | 460 → 438 |
| 混合 13 条长记录 | 5669 → 5361 | 4858 → 4550 |
| 重复引文 | 573 → 507 | 574 → 508 |
| 前缀碰撞，引文不同 | 563 → 507 | 564 → 508 |
| 前缀与引文都碰撞 | 561 → 507 | 562 → 508 |
| Unicode | 468 → 458 | 457 → 437 |
| 标点回退 | 446 → 452 | 448 → 454 |
| 已撤回 | 473 → 479 | 475 → 481 |
| 空 | 175 → 181 | 176 → 182 |
| Deferred | 388 → 394 | 388 → 394 |
| Folded | 484 → 490 | 485 → 491 |

这些是跨受控的共享 display／arguments／exact-output 链加上一份指令副本求和的组成计数，不是 provider 消息框架或计费。排除指令增量，英文／中文链分别节省 32／28 个 token，13 条长记录节省 314 个。回退／空／deferred／folded 的流水线文本保持相同，但其指令仍然贵六个 token。键内部的重复引文文本被计入，而不作为新信息记功。该测量不是 raw／compact JSON 优化，也不是语义有用性提升的证明。

一个仅基于当前内容的解析器未能通过记录移动负向对照：把匹配引文移到另一记录，不得让已显示的选择器转向另一 ID。报告中的修正在现有私有 AG 的 projection 值中保留原始 ID／引文见证，并只对最初解析出的 ID 检查当前内容。记录中的负向对照随后通过；这不是对任意编辑的穷尽证明。它不依赖不可变存储语句、模糊匹配、首匹配选择或新的别名存储。不具备这些见证的持久 trace 会有意无法解析组合 RPC 选择器。共享库调用者可以捕获／解析其原始作用域。见证冻结的是 ID 与短归一化引文，不是整条记录正文；Core 的规范精确 get 仍对当前内容具有权威性。

一次受控的陈述前缀编辑产生了一个真实的本地 HTTP `-32602` 错误。显式已知 UUID 恢复需要两次调用而不是一次：实测链成本为 257 → 320（+63）cl100k_base 与 260 → 326（+66）o200k_base。这是一个失败成本的例子，不是成功节省，也不是自动的无额外调用恢复。未知 UUID 恢复与最终宿主错误封装未被测量。

在该试验检查点，服务的 UUID 与组合 get 对比（含查找与记账）观察到的中位数为单条记录 0.499 → 0.861 ms，13 条记录 4.736 → 8.586 ms。每臂两次预热与十轮交替存有记录。宽泛的重复词 13 记录查询弃权（`guardrail_empty`）；受支持的多查询融合在不改变检索策略的情况下构建了所请求的批量。最初一次单记录融合尝试提供了非法的空 `queries` 数组，通过省略该可选字段得到修正。这些是 fixture 修正，不是排序修正、旧 search 延迟测量或生产边界。

## 验证与 artifact

最终八文件的定向运行通过 159/159，LSP 在八个被改动文件上报告零诊断。第一次阻塞运行暴露了一个 stale 的 MCP 仅 UUID 断言、必需的测试环境守卫与一个未认领的集成文件；它们都被修正，同时修正了控制字符 lint 失败而未削弱任何规则。MCP 现在通过真实 stdio 复制所显示的引用，并在精确输出中检查规范 ID。一次六文件回归打印了 43 个通过，但其外层 shell 超时，因此该运行并未建立干净退出。

最终的 precommit 运行通过全部 16 项阻塞检查与 1702/1702 个产品测试，实际 exit 0、signal null、error null。150 秒的默认 watchdog 此前曾在验证接近尾声时到期，尽管测试通过；那份不完整的回执被保留。完成的运行使用了既有的显式 300 秒 watchdog 选项，而不是改变的 gate 或源码超时。一个干净的后提交运行必须在收尾前独立验证已提交的修订。已完成的 precommit 计数不履行这项单独义务。

主要 artifact 是 `.nmg/verification/compound-reference/{paired-probe,token-probe,boundary-probe,render-parity}.json`。probe artifact 记录输入／来源哈希与完整来源；render parity 在等价的 lint 安全控制检查之后，把全部十二个 fixture 的显示与引用绑定到最终源码。临时 probe 入口点在采集后被移除。没有执行任何 live 模型、embedding、完整 benchmark、合并、推送或共享 daemon 重启。

# 预测一次召回是否值得打开：归一化形状特征族

[English](sufficiency-shape-features-2026-09-12.md) | [简体中文](sufficiency-shape-features-2026-09-12.zh-CN.md) · [术语](sufficiency-shape-features-2026-09-12.terms.yaml)

**Status:** 计划 + 首次测量。下面的 S1–S6 是实施顺序。本文是形状特征这条线的归属文档；闸门/组合类记录留在 `docs/decisions/implemented/2026-09-09-retrieval-relevance-gate.md` 与 `gate-certification-2026-09-09.md`。

## 1. 重新陈述问题

这是带日期的 S1–S6 计划及历史测量，含后来 2026-09-15 标签审计，不是当前部署或运行许可。
[训练协议](../../design/relevance-training.zh-CN.md)拥有数据准入；当前 trainer 拟合候选
相关性，不是自动部署整列表 head。外部记述／原始产物未重验。全部 qrels 结果（含早期
AUC 表）使用历史假定负例，不建立核验的实时降噪。词法 15.6%／embedding 52.8% 池
数字限于特定缓存／切片，不是新配对因果比较；打开一个正项不等于完整多跳充分性。

产品症状是"注入的 memories 大多无关"。删除候选是一种有边界的补救：闸门只能移除检索器已经放在它面前的东西，因此它的天花板就是检索器的池。在 LoCoMo 缓存上测得：只有 **15.6%** 的题在词法池中有任何 gold（带 embedding 时为 **52.8%**），而已上线的确定性程序闸门把候选精确率从 **5.9% 提升到 13.1%**，同时保留 81% 带 gold 的题。这是所报的 2.2 倍代理比率，不是核验的实时质量改善。

无边界的问题是另一个问题，而且它是一个**逐召回决定**：_这次召回的列表值不值得打开？_ 记录了两个动机，不是统计独立的证据来源：

- 轮换记录支持探索查询级选择，但认证记录也报告条目标定通过，不能跨运行声称“仅查询族曾认证”；标定通过、留出统计界复查及经验风险变化是不同结局。
- 捕获自身的标签是**展示级**的（`noise` / `partial` / `on_target`），不是逐候选的，而这正是"打开/弃权"决定的粒度。

同一个决定在文献中也有名字：**检索充分性预测**，它是查询性能预测（QPP）的一个分支。

## 2. 我们已测得的（自有数据）

| 测量 | 结果 |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 域内召回标签、6 个查询级信号、25 个标签 | 最佳信号 `top_gap` AUC **0.683**；`max_score` **0.444**、`mean_score` **0.421**（反向）；在此 n 下没有任何结论成立 |
| NFCorpus qrels、298 个查询、46.0% 充分、归一化形状特征族 | logistic 检验 AUC **0.658**（5 个切分：0.654 / 0.720 / 0.539 / 0.659 / 0.719） |
| NFCorpus 单特征 | `top1` 0.622、`bimodal_gap` 0.600、`top_gap` 0.547、`gap_concentration` 0.520，其余 ~0.50 |
| 切分间方差 | **n=298 时跨切分为 0.539–0.720** — 单一切分什么也说明不了 |

驱动本计划的两点解读：

1. **`top1`（绝对分数）是 NFCorpus 上最强的单特征（0.622），而同类特征在域内是反向的（0.42）。** 绝对分数的使用限于检索器配置；这本身不标定跨查询分数，也不建立跨配置迁移。按配置分别训练；让形状特征承担迁移。
2. **在这些规模上切分间方差占主导。** 未来每个数字都报告为 ≥5 个切分的均值加离散度，绝不以单一切分呈现。早先的组合扫描之所以失败，恰恰是因为单切分被当成了结果。

## 3. 文献怎么说（arXiv 2609.11646，_Your Retriever Already Knows_）

最接近的工作从检索器自身分数列表的**分布形状**特征预测**检索充分性**（Hit@k：前 k 中是否至少有一个充分条目？）。

**特征** —— 24 个非词法特征，分三族；13 特征的精简子集表现相同，因此特征**数量**不是杠杆：

- **分布（15 个）：** `top1−p99 gap`、`top1−top10 gap`（top1 与 top-10 的差距）、`top-10 std dev`（top-10 标准差）、`score decay slope`（分数衰减斜率）、`bimodal gap` = mean(top-3) − mean(ranks 10–30)、`exp. decay rate`（指数衰减速率）、`99th percentile`（第 99 百分位）、`nn above 0.8`、`nn above 0.7`（高于 0.8／0.7 的最近邻数）、`top-50 skewness`（top-50 偏度）、`top-5 concentration` = Σtop5/Σtop100（top-5 集中度）、`max 2nd derivative`（top-10 上的最大二阶导，即肘部）、`nn above τ`、`top-1 margin over τ`（高于 τ 的最近邻数、top-1 相对 τ 的余量）、**`gap concentration` = (top1−top2)/(top1−top10)（间隔集中度）**。
- **查询表面（5 个）：** 字符长度、词数、是否含数字、标点数量、平均词长。
- **全局（4 个）：** 语料相似度均值/中位、最大相似度、百分位区间（p90−p10）。

**标签：** Hit@k，带**两类负例**——_语料内不可答_（不存在充分条目，但存在部分匹配）与_主题缺失/对抗式_（主题完全不存在）。模型对对抗式这一类识别得最好。

**数据：** 每个领域约 1,032–1,747 条有标签查询（1,208 train / 302 test，80/20，架构选择用 3 折 CV，5 个种子），约 50% 正例。

**模型：** logistic 回归 / ridge / 小型 MLP（64, 32）。从经典池化特征换成他们的特征只买到 **+0.018 AUROC**（在其 Hit@5 集上 0.875 → 0.893），因此模型不是瓶颈。

**两个值得拥有的负结果：** 绝对分数阈值基线的 AUROC 为 **0.489**（无用），而逐查询的 **LLM judge 只得 0.649** —— 比 24 特征模型（0.856）差，且慢约 3000 倍。不要为此建 LLM judge。

**作者自述的限制：** 单一检索器、单一 judge、未在实时查询上验证，且跨域迁移较弱（留一领域 AUROC 降到约 0.71）。

## 4. 拟议特征族比较

并非每个特征都归一化：分数差与标准差仍带单位。比值需定义零分母、短列表及负分处理，
本文不擅选 fallback。形状迁移须实测，不是自动不变。

今天的控制器读 12 个特征，其中有信息量的核心是_原始_离散度（`cv_raw`、`max_bounded`、`mean_bounded`、`mean_raw_log`）加上产品的 QPP 组件与文本重叠。文献用**归一化形状**取代原始量级：质量落在哪里、列表衰减多陡、以及顶部间隔与 top-10 范围相比如何。

具体采用：

- **归一化形状（新增）：** `gap_concentration`、`bimodal_gap`、`top10_std`、`decay_slope`、`top5_concentration`、`elbow`（top-10 上的最大二阶导）以及 `top1 − top10 gap`。
- **以覆盖度为锚（新增）：** `τ 以上的 nn 数` 与 `top-1 相对 τ 的余量`，其中 τ 为**目标覆盖度**标定（论文用 90%），而不按风险标定。这也是"我们多频繁地打开一次召回"的正确操作规则。
- **查询表面（新增）：** 词数、字符长度、平均词长、是否含数字、标点数量。这些需要**查询文本**，而我们的缓存目前不保留它。
- **保留：** 产品的 QPP 组件与文本重叠最大值（文本重叠是词法特征，成本／迁移须测量），原始离散度特征仅作为_按配置_的特征。
- **作为可移植性陷阱丢弃：** 任何跨配置使用的绝对分数（`0.8 以上的 nn 数`、`0.7 以上的 nn 数` 同样是尺度绑定的）。

## 5. 标签与数据（仅用现有数据集，不做标注）

- **标签定义：** 当被披露的列表中含有至少一个判定为充分的条目时，该次召回记为_充分_。对 qrels 语料这是可派生的——`label = any(relevant in list)`——因此已知正例可不新增标注提供正目标；仅正例 qrels 下无匹配仍为未知，不是负监督。
- **负例类别须有证据**（语料内不可答／主题缺失），缺 qrels 或检索失败都不能单独建立类别。
- **来源：** NFCorpus（323 条判定查询）与 SciFact（339）是本地数据；两者都是 IR 语料，不是 memory benchmark。规模目标约为每配置 1,000 个查询，这正是文献所用的量级，也是让切分间离散度小到可读的量级。
- **域内（89 个召回实例 / 25 个展示标签）仅用于调整**——覆盖度/阈值标定，绝不用于重训练。

## 6. 步骤

**S1 —— 把形状特征族实现为纯函数。** 在 `CONTROLLER_FEATURE_NAMES` 旁加入归一化形状与查询表面特征，并对手工构造的列表（单调列表、平坦列表、单肘列表、空列表）写单元测试。不涉及模型，不改产品。这就是更正本身，因此先做。

**S2 —— 捕获运行时实际会拥有的特征。** 在召回实例中保存查询文本与逐候选分数拆分（lexical / vector / route）以及 `memoryType`。目前捕获只保留 `combinedScore`，因此训练时无法复现预期的特征向量；在这一点落地之前，任何训练出的头都是在与它上线后所见不同的分布上训练的。

**S3 —— 构建充分性集合。** 把查询文本存进 qrels 组缓存，并派生 `label = any(relevant in list)`；加入 SciFact。对正例率（约 50%）与查询数量做断言；偏离拟定约 50% 仅提示检查，不证明联结错误，也不允许强平衡类别或把未知改负例。

**S4 —— 小规模训练并诚实比较。** 先用 logistic 回归（特征标准化），仅当线性模型被击败时才用小 MLP。对以下三者报告 **≥5 个切分的均值与离散度**：形状特征族、当前 12 特征控制器、确定性 cv 规则。继续推进的门槛：在匹配覆盖度上击败确定性规则。

**S5 —— 在域内调整，不重训练。** 在 25 个域内标签上按目标覆盖度选 τ；如果域内显示该头比规则更差，该头不上线。

**S6 —— 上线闸门与机械守卫。** 只有当某个头的产物声明了 `domain`、`labelSource`、`unit`、`trainedAt` 以及它所训练的检索器配置时，才允许加载；加载器拒绝不匹配（与 `acceptsEmbedder` 相同的模式）。采用该头需要决策记录，如果出现新的闸门标志还需要一行隐藏特性登记。

## 7. 这条线的长期规则

以下是原计划约束，不另设当前政策 owner。≥5 切分／离散度要求保留，但历史表未给出
全部离散度，不因此证明符合；fold 共享数据，不是独立自然任务。当前标签／训练政策仍归所链设计。

1. 任何 memory benchmark 数据集（LoCoMo、LongMemEval、BEAM、PersonaMem、HaluMem）都不用于训练。它们最多只是评测面。
2. 每个数字都是 ≥5 个切分的均值加其离散度；单切分不是结果。
3. 标签来自既有判定（qrels）或域内判定——绝不来自 gold 答案字符串的包含关系，0.894 与 0.722 的 AUC 使用不同标签／语料设置，不单独识别标签方法的因果效果；未判 qrels 仍未知。
4. 学习型头的门槛是同一批特征上的线性模型，并且必须在匹配覆盖度上击败确定性规则。
5. 绝对分数按配置；形状特征迁移须证明。

## 8. 目前的结果（S4、S5）

**标签审计（2026-09-15）：** 本地 NFCorpus 的 train/dev/test 与 SciFact 的 train/test qrels 都不含显式的零分判定。历史导入器给所有不在正例 qrels 中的候选都赋了零分。因此下面的表使用的是*假定*负例，而不是经独立核验的噪声标签；它们不确立线上的噪声下降。[训练协议](../../design/relevance-training.zh-CN.md)把这些候选保留为未知，并在没有显式负例判定的情况下拒绝监督拟合。在提出新的模型质量主张之前，需要重建有标签数据集并做跨语料评测。该协议的夹具测试检验的是数据隔离与报告，而不是这些 benchmark 分数。

该头在样本外训练（5 折，对 11 个形状特征做 logistic）；"覆盖度"是阈值之后仍保持打开的查询比例。所列精确率／召回对采用历史代理判定规则，不是核验噪声或完整可答性；充分召回统计含已知正项的查询仍打开的比例。基线是同样分数上最便宜的确定性规则。

**SciFact 历史代理标签**（300 查询、41.7% 记录为充分、126 已判正项、597 假定负例／未判项）：

| 覆盖度 | 该头 | cv 规则 | 单特征 `top1` |
| -------- | ----------------- | ------------- | --------------------- |
| 50% | **26.5% / 78.4%** | 20.9% / 67.2% | 24.7% / 69.6% |
| 70% | 21.9% / 89.6% | 19.5% / 85.6% | 21.8% / 86.4% |
| 90% | 18.6% / 96.8% | 17.7% / 94.4% | 18.6% / 96.0% |

**NFCorpus 历史代理标签**（298 查询、46.0% 记录为充分、195 已判正项、525 假定负例／未判项）：

| 覆盖度 | 该头 | cv 规则 | 单特征 `top1` |
| -------- | ----------------- | ------------- | --------------------- |
| 50% | **34.4% / 60.6%** | 21.4% / 47.4% | 32.7% / 58.4% |
| 70% | 30.4% / 76.6% | 27.2% / 75.9% | 31.9% / 78.8% |
| 90% | 28.0% / 92.7% | 28.4% / 94.9% | 29.2% / 95.6% |

解读：

1. 50% 覆盖下代理 head 两轴高于 cv：SciFact 精确率 +5.6pt／召回 +11.2pt、NFCorpus
   约 +13pt／+13pt。这是代理数值差，不是核验的实时收益或显著性检验。
2. 70%／90% 与 top1 的比较缺不确定性，不建立“噪声范围内”。引言称 11 形状特征，
   旧解读却称 10 特征 head，产物绑定仍未对账。
3. SciFact 17.4% → 26.5%（50% 打开）约 1.5 倍，程序闸门另称 2.2 倍；标签／语料／
   工作点不同，没有联合比较不能相乘或声称可叠加。
4. 所报配置相关值 NFCorpus 0.562、SciFact 0.803 不自行与前面 AUC 表对账，也不
   建立迁移；这些有限可行性代理不是产品承诺。

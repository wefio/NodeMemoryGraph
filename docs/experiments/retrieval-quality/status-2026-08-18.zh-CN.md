```powershell

npm run eval:retrieval -- --dataset <datasets>
```

store 持久化在 `.benchmarks/retrieval-stores/<dataset>/` 并被复用；摘要也被报告为持久化（`membersKey` 指纹）。有效且兼容的 cache 复用可避免新摘要调用；缺失／陈旧输入或配置变化可能要求重新生成，持久化不保证零 LLM 成本。

## 此后已完成的工作

这些带日期跟进保留历史测量及当时开关，不是新的产品默认或部署回执。

- **节点摘要层**（2026-08-24）：每个节点一条由块摘要生成的摘要、滞回刷新、位于块命中之后的 node-FTS 路由。BEAM 堆叠 27.0% → 27.4%；LoCoMo 在当时保存的布局下不受影响（≥2 块闸门，退化为单块节点）。细节见 [retrieval-quality-node-summaries-2026-08-24.md](node-summaries-2026-08-24.zh-CN.md)。
- **跨块链拉取**（2026-08-24）：块成员选择之后，剩余的成员预算（≤ `leafBlockRoutingMaxMembers`）拉取 ±1 跳的链邻居——显式 `memory_chain_edges` 加上 `memory_chain_members` 中的位置相邻项（需要后者是因为评测 `chainInjection: "logical"` 的链只带成员、没有边）。BEAM 堆叠+节点 27.4% → 27.7%，any@20 65.1% → 80.0%，all@20 26.4% → 39.6%，event_ordering 15.6% → 17.4%（any@20 57.5% → 90.0%）。成本：ctx 51.1k → 159.4k 字符。细节见 [retrieval-quality-chains-2026-08-24.md](chains-2026-08-24.zh-CN.md)。
- **激活门控链扩展**（2026-08-25）：`expandChains` 的默认不再是整链——只有当邻近度（1/(1+到最近命中的距离)）+ 查询词重叠 + 0.5×重要性达到 0.5 时才追加成员，并由 `chainExpansionMaxMembers`（默认：排序结果条数）硬性封顶。BEAM：R@20 27.7% → 28.9%（原称噪声，本轮不建立显著性），ctx 159.4k → 93.9k 字符。详报保留约 25.5% 的 any@20 增益，使用约 39.5% 的新增上下文，或整链总上下文的 58.9%；早先约 40% 覆盖增益混淆了分母。Event_ordering 回到无链水平。常量被报告按原则固定、未扫 benchmark，但这不是独立预注册回执。细节见 [retrieval-quality-chain-activation-2026-08-25.md](chain-activation-2026-08-25.zh-CN.md)。

## 1. 问题

在上下文干预（`none` / `cue` / `resurface` / `retrieve`）之上做成本感知的选择，能否按**模型调用 token 预算**（检索／搜索成本被推迟——见 §5/§9——不构成本处测量的成本）足够改善任务结果，从而相对于**固定回退**值得引入实验性路由器——并且这种优势是否依赖**实测历史**（先前的动作与经独立验证的结果），而不是在宽松预算下可由静态的 always-retrieve 策略解释？

两条拟议假设（不代表已核实完整冻结）：

- **H1（闸门／效用）：** 经 validation 调参的路由器在评分任务准确率上相对固定回退是非劣的（在边际 `δ` 内），并在端到端预算下具有更低的单题成本（或满足预算上限）。
- **H2（历史依赖）：** 加入历史的路由器相对无历史的头会实质性改变留出的顺序任务决策——即按 §9.4 存在一个可解的、依赖历史的错误。**实质性被固定（B-B）：** 仅当 (a) R1 相对 R0 在 ≥ 5% 的留出顺序决策步上改变了所选动作，**且** (b) 该改变按 §6 的边际／闸门在准确率或模型调用 token 成本上相对 R0 带来 owner 级改善时，H2 才算得到支持。否则 H2 不被支持（不具实质性）。若 H2 不被支持，则不新增循环／历史节点架构（§9.4 用这一证据作为新增架构的门槛）。

## 2. 为什么离线探针无法回答这个问题

此前的 #25 离线探针（LoCoMo 组件）从未让真实模型消费干预，也从未把成本惩罚纳入优化；在宽松预算下覆盖度奖励随上下文长度单调递增，因此线性头退化为 retrieve-常量，`fixedRetrieve == linear` 精确成立（`0.3505885122`）。这种结构**无法**否证 cue/resurface/历史相关假设，也不是效能结果。

## 3. 总体、单元与合格性（在查看任何结果之前锁定）

- **独立单元 = 一位对话 owner**（persona／长期记忆用户会话），绝不跨 train/validation/test 切分。同一 owner 的相邻行或改写不算独立单元（§9.5）。
- owner↔行映射在**读取任何结果之前——包括接线 dry run（§8）**——就固定，而不仅仅是在有功效运行之前固定（B-D）。
- **数据集选择判据（合格性锁定）：** 在已完成同模型答案+判定流水线演练的官方 OmniMemEval 套件中，选择最小的一个，其准备数据在排除不可答／空上下文／超预算的行之后提供**≥ 30 位合格独立 owner**。当前候选：LoCoMo（10 位 owner → **已拒绝**，太少）、LongMemEval（500 行，逐行 haystack → owner 分组须先确认）、PersonaMem v2（200 位 persona，多轮聊天 → 对顺序历史最强）。最终套件与 owner↔行映射必须在任何结果读取之前记录并以哈希固定；本记录尚未提供它们。
- **顺序历史的可得性：** 行必须能在 owner 内排序（按时间），从而可定义先前的动作／奖励。若所选套件无法提供干净的 owner 内顺序，则 H2 报告为"以所选数据不可测"，而不是事后重新定义。
- 排除条件（固定、非结果导向）：检索／渲染到的上下文非空、在硬上下文预算内、属于合格 owner、类别不是 canary 中所用的被排除类别。不基于任何分数／结果做排除。

## 4. 臂与决策规则

动作是来自 `src/lab/context-router.ts` 的四个固定 `ContextAction`，经 `src/lab/context-executor.ts` 执行（`none`、`cue`、`resurface`、`retrieve`），沿用已实现的相同授权／预算／信号语义与整片段截断。

在**相同的留出问题**上比较策略（匹配方式：同一 `(owner, question)` 在独立的真实模型调用中接收各策略的上下文——canary 模式）：

- **F0 固定回退：** 本提议实验的固定 always-retrieve 基线，不表示当前所有 NMG 调用方都会注入全部记忆。
- **F1 固定 `none`：** 空上下文参照。它不保证模型调用成本界限或质量下限；回答长度与质量仍可能变化。
- **R0 无历史路由器：** 132 参数头（32→4），在执行动作回归上离线训练，选择 = 成本调整后的 epsilon-greedy。
- **R1 历史路由器：** 同一个头 + 实测历史特征（§9.4）。

路由器的训练／服务必须只在**按 owner 留出**的折上运行；validation 选择 `λ` 与超参数；未被触碰的、owner 不相交的 test 集只评分一次。

## 5. 成本惩罚 λ 必须参与（修复离线 P1）

离线探针的缺陷是成本从未进入优化。这里的优化目标是

```
Q(action) = E[ graded utility ] − λ · cost(action)
```

其中 `cost` 是从真实 `create()` 用量测得的**模型调用 token 成本**（检索／搜索成本推迟到 §9，不计入本测量的成本；不伪造任何数值）。λ **不是**事后自由旋钮：本页的 `Λ = {0, λ1, …, λk}` 只是模板，尚无具体 λi 数值；对每个 λ ∈ Λ 在 train 上训练路由器，并在 **validation** 上读取所得的（准确率, 成本）；选择在 validation 上使 `accuracy − λ·cost` 最大的单个 (λ, 策略)（并列时取更低成本）；该选择在读取 test 折之前固定。报告必须包含完整的 λ 扫描与每个 λ 下的 retrieved-vs-nothing 行为，使退化为 retrieve-常量 的结果可见而非被隐藏。

**retrieve-常量 不是附加价值（B-E）。** 由于固定回退 F0 就是 always-retrieve 策略，一个仅仅复现 always-retrieve 并对 F0 达到非劣的路由器**没有展示任何附加价值**；仅凭质量非劣闸门无法发现这一点。因此，当 R0/R1 在所选 λ 下退化为 retrieve-常量（可经 λ 扫描看出）或以其他方式未能超过 F0 时，同样计为未观察到附加价值的结果。无价值的结果据此报告，而不是作为支持性证据。

## 6. 指标、闸门与功效（预先声明）

- **主要指标：** 在相同主模型设置下，经该套件官方答案流水线得到的逐题官方评分正确性（0/1）（canary 中为 `deepseek-chat`；确切模型在运行前固定并记录）。
- **次要指标：** 由真实用量得到的逐题模型调用 token 成本与延迟（搜索成本推迟）。
- **估计量：** test 折上逐 owner 的均值差 `router − F0`。
- **质量非劣边际：** `δ = 0.05` 绝对准确率（路由器在 test 的 owner 均值上不得比 F0 差超过 0.05）。**成本闸门（已钉住，B-C）：** 路由器在 test 上的模型调用 token 成本 ≤ F0 的模型调用 token 成本（无宽限，`C_R ≤ C_F0`）；否则无论准确率如何，H1 的成本主张失败。与上面的 retrieve-常量 条款合并，H1 还要求路由器优于 F0 的 retrieve-常量 复制品（所选 λ 不是 always-retrieve），否则即为未观察到附加价值的结果。
- **样本量：** 按所选套件的 owner 数量与假设的 owner 内方差计算，以检出逐 owner 效应；对预先声明的最小效应在 α = 0.05 下目标功效 ≥ 0.8。若所选数据集达不到，则该实验功效不足，并按功效不足报告（未观察到附加价值也是有效结果；不得包装为正面结果）。
- **主要分析：** owner 级配对比较（相同 owner 在两种策略下），对 owner 均值差使用非参数检验；逐题的次要分析是描述性的。

## 7. 分析／报告／停止规则

- 预注册的分析计划按所写执行；任何偏离都作为偏离报告，不得静默折入结果。
- 运行前固定停止规则：真实模型调用与成本预算上限；一旦触及预算，实验停止并按未完成报告，而不是外推。
- 若发现 R0/R1 在闸门下**未能超过或匹配** F0，或在所选 λ 下退化为 F0 的 retrieve-常量 复制品（无附加价值），这属于有效结果，并默认阻止新增架构（§9.4、§9.5）。不得仅凭任何离线／留出分数默认启用；晋升另外需要 §9.5 预先声明的任务指标、不确定性估计、无安全违规，且无质量／成本回退。
- 报告必须把接线证据与因果／效用证据分开，并披露确切模型、日期、数据集哈希、owner 映射、λ 扫描以及任何基础设施故障（记录，绝不零填充）。

## 8. 可行性与成本

第一步可执行的是**小型 dry run**（少量 owner，不学习），用于确认该套件的官方答案+判定流水线与真实用量捕获能从 LoCoMo canary 扩展到所选套件，然后才进行任何有功效的投入。该 dry run 报告为接线扩展，不作为效能结果。

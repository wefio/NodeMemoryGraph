及报告的测试描述当时检查点，不是新执行或当前验收。本轮未重开日志，也未运行 Pi、
provider、daemon 或标定；当前源码视图在下文单列。

这是一次单一的自然 Agent 使用观察，不是标定数据集，也不是能力分数。此次运行之后收紧了术语与信任边界：原先称作 `exact-use` 的事件属于历史歧义观察，不能证明 API 模型因果地使用过某条 memory，也不是有效的证据监督。

## 观察

该运行在控制器超时前没有完成。终止之前影子日志捕获到：

- 1 次自动召回；
- 8 次显式检索；
- 2 个当时称作 exact-use 的历史事件；
- 9 个已完成的 Agent 轮次结果遥测事件；
- 8,686 个实际注入字符（按每 token 四字符的标注估算约 2,175 tokens）；
- 没有任何显式成功、纠正、充分性、噪声或无需记忆的标签。

那 8 次显式检索主要是对 ANN、approximate nearest-neighbour、default selection、HNSW 与 brute-force search 的同义改写。这是检索/停止循环的证据，不是"更多检索有用"的证据。这次未被纠正、未完成的运行仍是未知结果，不是正训练样本。九个 outcome 事件行不证明九个已完成用户任务、独立用户或成功结果。

## 由此产生的工程改动

这些是原记录所报的跟进，不是当前回归回执。

- 影子检索事件现在把实际注入字符数与后端 token 估算分开记录。
- `nmg_remember action=feedback` 可以附加显式的、会话自有的标签：任务成功、用户纠正、证据充分性、扩展有用性、过度噪声、无需记忆。
- `npm run eval:controller-shadow` 审计事件与标签覆盖度，并拒绝宣称已具备标定就绪性。
- 无头 Pi 辅助程序使用可写的隔离 Agent 目录、有界提示词超时与工具调用上限。计时器包住 prompt／settling 操作，而不是仅依赖 Pi 的事件收集超时；它不是已证实的整个 helper 墙钟期限。这些保护的是评测运行；它们不改变产品检索预算。
- 该辅助程序现在向 Pi 传递一份项目本地路径契约（`NMG_DATA_DIR`、`NMG_PROJECT_DIR` 与 `PI_CODING_AGENT_DIR`）。它在启动 Pi 之前显式取得 daemon，且只在辅助程序拥有它时才关闭它。所报策略在受控超时路径中安排自有 daemon 清理，并保留预先存在的 daemon；这不是所有崩溃／竞态都安全的保证。
- 辅助程序与报告解析到同一个项目本地 `.nmg`，因为辅助程序显式提供了 `NMG_DATA_DIR`。普通 Pi 使用有意不同：在没有覆盖的情况下，所有客户端解析用户级 `~/.nmg` store。2026-08-11 的审计发现扩展与导出器已漂移到不同默认值；共享数据路径解析器现在强制该契约。本报告中的历史事件计数是快照，不是当前的可用性证据。

## 补齐缺失决策之后的跟进

第一次运行是在索取一条 NMG store 中尚不存在的 ANN 策略。在经核验的项目决策被记住之后，第二次隔离运行恰好新增了一次自动检索、一个 use 事件与一个显式反馈事件。Pi 将任务标为成功、注入证据标为充分；它没有再执行同义检索循环。这些是显式 Agent 任务／检索判断，不是独立核验的 claim-support 标签；两个 episode 不单独识别补入决策的因果效果。

第二次辅助进程仍未能自行退出，因为 Pi 的 `promptAndWait()` 事件超时无法约束卡住的提示词 RPC。该运行通过其被精确拥有的进程句柄终止，绝不通过全系统 PID 启发式。记录中的辅助程序把 prompt／settling 操作包在硬超时中，并让 `RpcClient.stop()` 只终止它创建的子进程。

## 当前源码边界

此源码视图与历史运行回执分开：

- [`resolveNmgDataDir`](../../../src/cli/data-path.ts) 优先采用非空 `NMG_DATA_DIR`，
  否则使用调用者 fallback（默认用户级 `~/.nmg`）。项目本地 helper 运行不验证普通客户端
  默认值或每个调用者。
- [`pi-control.ts`](../../../scripts/pi-control.ts) 使用 `finally`，但先等待
  `client.stop()` 再调用 `shutdownOwnedDaemon()`。计时器包住每次 `promptUntilSettled(...)`，
  不覆盖启动、后续取结果调用或清理。本记录不证明该 await 失败或宿主退出时
  仍能清理；受控关闭不等于所有崩溃／竞态都安全。
- [数据集构建器](../../../evals/controller-shadow/dataset.ts)要求 natural-origin 收集、
  语义任务 ID、必需显式标签及可重放输入。缺 `verified_claim_support` 的行可能被保留并
  标为 control-label-only，不能监督证据排序／预算；旧受控／歧义观察并不因此成为有效训练行。
- [标定](../../../evals/controller-shadow/calibrate.ts)输出 `eligibleForActivation: false`
  的候选。[Gate](../../../src/lab/controller-gate.ts)还包含质量、成本及配对产品条件，
  不止历史上的八个主目标条件。离线通过不启用运行时模式，也不提供经审阅的启用回执。
  环境中的 `NMG_CONTROLLER_SHADOW=1` 配置观察收集；候选的 `eligibleForShadow` 不是该日志
  开关，两者也都不是 active／default 部署批准。

## 本文不证明什么

两次冒烟运行无法设定 QPP 阈值、训练下一层/检索动作，也无法比较 Graph 与 Lite。那些决定仍需独立标注的语义任务，以及留出的时间/任务切分。

## 工具流跟进

后来一次实时代码审阅提示词暴露了另一类渐进披露失败：即使 NMG 无法核验当前源代码，模型仍不断改写 `nmg_search`。仅靠提示词指引并没能阻止该循环。

Pi 适配器现在施加一个确定性的、按用户轮次的推进守卫：

- 自动召回不消耗显式检索配额；
- 在加载精确证据之前可以执行两次显式检索；
- 再有一次检索会被折叠为"使用 `nmg_get` 或当前来源工具"的指令；
- 成功的 `nmg_get` 会重新开放检索以做一次补充证据跳；
- 新的用户提示词重置配额，而 Pi 内部的 `before_agent_start` 工具循环不重置。

第一版实现错误地在每次 `before_agent_start` 时重置，因此允许了三次真实检索。把守卫改为按会话加用户提示词作键之后，有界重放产生了一次自动召回、一次显式检索、一次精确 `get` 和一次补充显式检索。辅助程序正常退出，项目 daemon 报告 `running: false`。这验证的是工具序列边界，不是检索质量或 QPP 标定。

一次专门的跟进要求 Pi 在不调用 get 的情况下发出三次不同检索。只有前两次到达检索。第三次返回了推进提示，Pi 如实报告自己已被暂停，影子报告记录了一个 `tool_flow/search_suppressed` 事件。这让守卫可被观察，而不会把抑制当成任务成功或证据充分。

新的检索事件还保留 Active Graph 查询指纹、QPP 决策/组件、渐进扩展阶段与逐候选选择分数。因此 `npm run eval:controller-dataset` 可以把这些特征与当时记录的 `exact-use` 事件、结果与显式反馈联结，并按时间切分整个语义任务。在那一步它有意返回零行：当时只有一条不完整反馈事件，没有任何语义任务具备全部四个必需检索标签。下面较晚的有界收集跟进取代了该快照。

## 可重放性跟进

原始事件形状足以统计标签，但不足以复现控制器决策：它省略了当时的特征向量与硬预算。新事件现在携带带版本的 global/memory/node/edge 特征快照与 AG 预算包络。数据集构建器会排除缺少其中任一输入的有标签历史行，而不是假装它们可标定。

`npm run eval:controller-calibrate` 是记录中的离线重放机制。它使用按时间排序的语义任务切分、训练一个全新候选、在留出行上与基线排序比较、报告成本观察，并持久化一个带日志与回滚指纹的可审计非激活产物。在当时的项目日志上运行它正确地被阻断：存在 36 个 graph，但没有任何一个具备完整的独立标签集。这是数据就绪性结果，不是控制器失败，也不是用 benchmark 标签替代的许可。

## 反馈收集边界（2026-08-11）

无头辅助程序现在可以在一个 Pi 进程中接受重复的常规 `--turn` 参数。这在一个会话内跨过回答/审阅边界，同时保留当时描述的超时（不是当前整个 helper 的期限）、工具调用上限、自有 daemon 关闭与隔离可写 Agent 目录。旧式单消息形式不变。

第一次实机多轮探针暴露了两个生命周期错误。Pi 在工具结果之后会再次调用 `before_agent_start`，因此反馈提醒可能在同一个用户轮次内、下一条用户消息之前就被标记为已显示。一次回答还可能同时产生自动 header graph 与显式 `search -> get` graph；因此选择最新 graph 可能会为一条证据从未被披露的 graph 请求标签。bridge 现在对每个不同的 `(session, user prompt)` 只检查一次反馈，并且只提供带非空披露事件的 graph。确定性测试覆盖这两种情况。

历史有界日志包含 48 个检索 graph、11 个当时命名为 "exact-use" 的事件（现在保守地视作披露或诊断归因）、48 条结果记录、四条反馈事件、三个完全标注的 graph，以及三个查询派生任务 ID。新的可观测性事件也做了端到端验证：一个 `feedback_nudge_shown` 事件先于同一 AG 的反馈事件。每次辅助运行后 daemon 都被停止。四个标签是否可观仍由 Agent 决定：沉默、正常完成、没有纠正、候选曝光，永远不会自动成为标签。

在当时事件格式下，`npm run eval:controller-dataset` 报告按时间排序的两任务 train / 一任务 validation 切分，且无协议阻断；这项历史结果不建立当前构建器的准入。这证明的是收集与重放边界，不是统计充分性。最近产生的 `npm run eval:controller-calibrate` 产物仍是非激活候选：

- validation 候选召回：`1.0`；
- 基线精确率/召回：`0.333 / 1.0`；
- 学习得到的精确率/召回：`0.333 / 1.0`；
- 对照准确率：在唯一 validation 行上为 `1.0`；
- 控制器平均推理：约 `0.14 ms`；
- 历史证据多样性：两个主训练目标与一个主验证目标；历史歧义集合包含 7 个与 2 个目标，其中一个目标同时出现在两个切分中；
- 控制器闸门：失败，因为两个训练用例与两个不同的训练证据目标不足，且共享的证据目标违反留出边界；
- 是否有资格用于 shadow/active/default Pi：全部为 false。

正确的产品结果是继续收集。三个受控的有标签任务足以跑通切分与失败即关闭的闸门，但不足以标定路由策略或授权启用。

三个已记录任务 ID 只覆盖两个实际主题（ANN 启用与渐进披露评测）。它们是受控的生命周期探针，不是三个语义独立的自然任务。因此不得把查询哈希用作多样性主张；即便导出器已能形成合法切分，未来标定仍需明显更广的常规 Pi 工作集合。

标定闸门现在以机械方式强制一个更严格的区分。在该次跟进中，除整任务按时间切分外，gate 被描述为为每一行从第一个按排名排序、且由 `verified_claim_support` 支持的精确记录派生一个保守的主证据目标。它要求至少八个不同的主训练目标，从而防止一个多证据任务虚增多样性。另外，它拒绝完整训练集与验证集的经核验归因集合之间的任何重叠，包括非主证据。历史产物报告 `primaryTrainingTargets=2`、`primaryValidationTargets=1`、历史 `exactTrainingTargets=7`、`exactValidationTargets=2` 与 `overlappingExactTargets=1`，因此即便查询派生任务 ID 构成的切分在语法上合法，它仍会失败关闭。主证据只是多样性的代理指标；它并不主张多证据任务存在单一真值。那些历史计数来自已被取代的歧义事件格式，不得用于激活控制器。新的收集需要独立核验的 claim 支持。

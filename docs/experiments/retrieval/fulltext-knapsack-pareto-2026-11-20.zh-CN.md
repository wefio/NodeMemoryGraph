# 完整原文下的分档背包策略与帕累托前沿

[English](fulltext-knapsack-pareto-2026-11-20.md) · [术语](fulltext-knapsack-pareto-2026-11-20.terms.yaml)

## 问题与设置

在不截断候选正文（不设 160/320 码点预览上限）的前提下，将完整原文按不同字符预算装入渲染结果，
比较不同背包与分档策略在各预算段的标注证据召回率，找出各预算段的最优策略及可组合的统一分档方案。

- **评测语料**：离线回放 1,867 题，与 [边际证据覆盖](marginal-evidence-coverage-2026-11-20.zh-CN.md) 共用同一批冻结三路 RRF 候选池（每题最多 100 条，无固定前三条预留，新增 embedding 请求为零）：
  - LoCoMo 1,532 题（2,348 条标注证据，短记录，单条平均约 170 字符）
  - BEAM 235 题（833 条标注证据，超长记录，单条平均约 3,000 字符）
  - LongMemEval 100 题（170 条标注证据，中长记录，单条平均约 1,000 字符）
- **渲染计费**：采用紧凑 `search` 渲染格式（去掉 `node=`、默认 `type=`、重复键名 `memory=` / `preview=` 与 `count=`，精简顶部提示语，使用短引用 `ref:...` 与 8 位 `activeGraphId` 前缀），按完整记录的 UTF-16 单元计费，包含整页固定包装与换行。
- **预算档位**：1,000、1,500、2,000、2,500、3,000、4,000、5,000、6,000、8,000、12,000、16,000 字符。
- **对比策略**：
  1. `prefix_stop`：严格按 RRF 排名顺序加入，遇到第一条超预算记录即停止。
  2. `rrf_fill`：单次按 RRF 排名扫描，跳过放不下的长记录，继续装入后面的短记录。
  3. `staged_rrf`（当前基线）：从 1,500 字符起分档装包，升档时保留上一档已选记录，再用剩余空间按 RRF 顺序补齐。
  4. `density`（无保护下限 `floor=100`）：按相关性除以长度代价排序 $\frac{40 / (40 + r)}{\max(L, 100)^\alpha}$（$\alpha \in \{0.25, 0.5, 1.0\}$）。
  5. `staged_floor`（下限保护分档背包）：同样按 $\frac{40 / (40 + r)}{\max(L, F)^\alpha}$ 排序并逐档单调保留，但设置保护下限 $F \in \{400, 500\}$ 字符。对不超过 $F$ 字符的短记录不施加长度惩罚，只惩罚真正占满上下文的超长记录。

## 关键发现与组合分档策略

1. **为什么早期 `floor=100` 的密度背包在 LoCoMo 上崩掉**：
   当长度下限只有 100 字符时，一条 250 字符的高排名有效记忆会被惩罚，反而让位给 100 字符的寒暄短句，导致 1,000–2,500 字符下 LoCoMo 召回骤降 7–19 个百分点。
2. **400 字符下限保护同时消除短记录回退并保留长记录收益**：
   把长度代价设为 $\max(L, 400)^\alpha$ 后，短消息之间完全按原始 RRF 排名竞争（LoCoMo 在所有预算段零回退），同时对超过 400 字符的长记录按密度排序跳过巨无霸条目。相比当前 `staged_rrf` 基线：
   - LoCoMo：全档持平或略优（−0.18 到 +0.13 pp）；
   - BEAM：全档净增 **+0.6 到 +1.9 pp**（16,000 字符达 38.54%）；
   - LongMemEval：全档净增 **+0.6 到 +2.9 pp**（16,000 字符 `α=0.5` 达 97.65%，`α=1.0` 达 99.41%）。
3. **RRF 阻尼 $k$ 敏感度验证（固定 `floor=400, α=0.5`）**：
   扫频 $k \in \{5, 10, 20, 30, 40, 50, 60, 100\}$ 显示 $k \in [30, 50]$ 为平坦高原（三集波动 ≤ 0.6 pp）：

| 数据集 | 预算 | $k=10$ | $k=30$ | **$k=40$** | $k=50$ | $k=60$ | $k=100$ |
|---|---:|---:|---:|---:|---:|---:|---:|
| LoCoMo | 1,500 / 4,000 | 49.23% / 63.33% | 49.40% / 63.33% | **49.32% / 63.37%** | 49.15% / 63.50% | 49.11% / 63.50% | 48.89% / 63.42% |
| BEAM | 2,500 / 8,000 / 16,000 | 20.29% / 32.29% / 36.85% | 20.77% / 33.25% / 38.18% | **20.77% / 33.13% / 38.54%** | 20.77% / 32.53% / 38.54% | 20.65% / 32.65% / 38.54% | 20.65% / 32.29% / 38.42% |
| LongMemEval | 1,500 / 6,000 / 16,000 | 76.47% / 92.35% / 96.47% | 77.06% / 93.53% / 97.06% | **77.65% / 94.12% / 97.65%** | 77.06% / 93.53% / 98.24% | 77.06% / 93.53% / 98.24% | 76.47% / 93.53% / 99.41% |

4. **最终落入渲染器的默认策略**：
   - 共享渲染器 `packAutomaticRecall` 在全文模式采用 **`k = 40, floor = 400, α = 0.5`** 的下限保护分档背包，逐档单调保留已选记录（杜绝 BEAM 上无分档 `rrf_fill` 的 4k 非单调回落）。
   - 经济档（≤160 码点）天然低于 400 字符下限，保持原始 RRF 顺序不变。

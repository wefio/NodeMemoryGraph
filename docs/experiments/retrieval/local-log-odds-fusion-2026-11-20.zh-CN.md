# SQLite 混合检索的局部对数几率融合

[English](local-log-odds-fusion-2026-11-20.md) · [术语](local-log-odds-fusion-2026-11-20.terms.yaml)

## 问题与设置

能否用一套固定的向量与 BM25 权重，同时改善普通混合检索和经济档，无需按库调参？
离线回放使用 LoCoMo 1,532 题、BEAM 235 题和 LongMemEval 100 题，共 3,351 个黄金证据标签。
实验复用缓存的 384 维 BGE-small-en-v1.5 查询向量和原有时间过滤。SQLite 为两路候选并集提供
BM25 和余弦分数。黄金标签用于评估和留出网格诊断。固定融合在运行时无需标签。

固定权重方案用每路正分的中位数居中，再除以总体标准差。有 BM25 命中的候选取两路校准分的
加权和，再乘以 √2。没有 BM25 命中的候选直接使用校准后的余弦分。3∶1 给余弦 0.75、BM25 0.25。
6∶1 沿用早先三路对照中的向量与 BM25 相对权重。QARF 按查询 IDF 变权，另有一个方案取同一数据集
其他会话的平均权重。分数差方案用标准化后的头部分数与中位数差距估算两路强度。

## 权重网格

网格比较 40 个固定权重。每组使用相同的两路候选深度和本实验的原始消息邻接补全规则。
补全保留前 80 个结果，在相同时间约束下最多加入 20 条邻接记录。输出仍最多 100 条。

| 每路候选 | 向量∶BM25 | 总体 Recall@20 | 总体 Recall@100 | BEAM Recall@100 |
| ---: | --- | ---: | ---: | ---: |
| 100 | 6∶1 | 57.65% | 81.92% | 69.51% |
| 100 | 3∶1 | 58.46% | 82.48% | 69.99% |
| 200 | 6∶1 | 57.98% | 82.04% | 69.63% |
| 200 | 3∶1 | 58.46% | 82.69% | 70.35% |

每路 100 条时，3∶1 相对 6∶1 找回 39 个黄金标签、挤掉 20 个。总体提升 0.57 个百分点，
按会话分组抽样的 95% 区间为 +0.19 到 +0.96 个百分点，BEAM 单项区间跨零。每路 200 条时，
逐查询 QARF、其他会话平均 QARF 和分数差方案的总体 Recall@100 分别为 82.07%、82.27% 和 80.45%，
都低于 3∶1。每次留出一个数据集，并按另外两个数据集的平均 Recall@100 选权重时，深度 200 的三次
都选中 3∶1。深度 100 的选择有所变化。

在 3∶1 下，候选深度翻倍只多覆盖 0.21 个百分点，但参与评分的候选中位数从 167 增到 297。
记录的帕累托前沿使用总体 Recall@20、总体 Recall@100 和 BEAM Recall@100 三个目标。

## 经济档

回放使用共享渲染器，每条正文预览最多 160 个码点。覆盖率按展示的引用能取回的黄金证据计算，
字符上限以 UTF-16 单元计。

| 排序 | 3 条 / 1,000 | 5 条 / 1,500 | 10 条 / 2,500 |
| --- | ---: | ---: | ---: |
| 固定三路 RRF | 33.39% | 39.72% | 48.13% |
| 固定 3∶1 对数几率 | 34.89% | 40.97% | 49.60% |
| 逐查询 QARF 对数几率 | 33.99% | 39.99% | 48.34% |
| 其他会话平均 QARF 对数几率 | 34.05% | 40.56% | 49.15% |
| 分数差对数几率 | 33.57% | 38.65% | 46.43% |

默认五条时，3∶1 找回 157 个黄金标签，挤掉 115 个。预览里直接可见的黄金证据覆盖率从
16.23% 升到 16.56%，两组输出长度的 p95 都是 1,205 个 UTF-16 单元。逐查询 QARF 把 BEAM
从 13.21% 提到 16.33%，同时让 LoCoMo 从 46.29% 降到 45.02%。

## SQLite 读取开销与验证边界

集成实测在 SQLite 副本上使用 138 个查询，普通检索和经济档引擎检索的返回上限同为 20 条。
计时包含候选读取、补齐分数、排序和原始证据读取。普通检索还包含书签查找。每个查询跑三遍，
丢弃首遍，后两遍按相反的方案顺序运行。

| 数据集 | 查询数 | 普通 p95，原版 → 3∶1 | 经济档 p95，原版 → 3∶1 |
| --- | ---: | ---: | ---: |
| LoCoMo | 41 | 18.4 → 15.8 ms | 18.9 → 13.8 ms |
| BEAM | 47 | 28.2 → 16.6 ms | 30.8 → 17.1 ms |
| LongMemEval | 50 | 23.6 → 20.8 ms | 24.2 → 20.7 ms |

集成改动同时减少候选深度并采用新的评分规则。已有候选分数后的融合计算 p95 为 0.07–0.10 ms。
在单独的 BEAM 读取实验中，扫描一次匹配的 BM25 分数 p95 为 0.71 ms，候选 ID 映射另占 0.11 ms。
按候选 rowid 限制全文匹配的 p95 为 8.70 ms，为词法候选补齐余弦分数的 p95 为 0.25 ms。138 个集成查询的前 20
排序全与离线 3∶1 一致，普通与经济档顺序也一致。早先的 6∶1 移植在两个候选深度下都逐条对齐了
Python 版的 1,867 题前 100，邻接补全也一致。

LongMemEval 衡量已标注答案会话的覆盖，LoCoMo 和 BEAM 衡量来源消息。实验未测最终答题正确率、
daemon 或向量服务耗时，也未运行在用户的在用库上。新增 embedding 请求为零。

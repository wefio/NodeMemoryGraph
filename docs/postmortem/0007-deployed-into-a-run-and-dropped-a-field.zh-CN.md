# 0007 - 我在评分运行中做了部署，而一次重构丢了一个没人盯着的字段

[English](0007-deployed-into-a-run-and-dropped-a-field.md) · [术语](0007-deployed-into-a-run-and-dropped-a-field.terms.yaml)

**Status:** open

## Executive summary

同一天里，两个失败到达了 `main` 和线上端点，而现有的一切都没能拦住。一次**在评分运行进行中**做的部署让所有函数路由下线约十分钟，harness 收到 404；禁止这么做的规则早就存在，只是没有任何东西在部署时检查它——所以缺的从来不是规则。另一件事：一次重构把检索的答案装配搬进独立函数，顺手带走了给 `persistence.inline_bytes` 赋值的那一行，套件依旧全绿，因为没有任何测试断言这个字段存在——最终是 linter 以"变量未使用"的形式报出来的。两件事的教训是同一个：**不落在改动实际经过的路径上的规则或测试，只是意图声明，不是控制。**

## Summary

2026-11-01，端点在服务一次评分运行。为加入定时心跳，部署了带 `schedules`（`edgeone.json`）的构建。部署后 `/health`、`/add`、`/search` 全部返回 **404**，域名返回平台默认页。回滚恢复服务；对同一提交去掉该块做 A/B 后部署正常，从而确定问题在那一块。

同一天稍后，为满足复杂度门槛，把答案装配从 `search` 提取成 `searchAnswer`。提取把设置 `persistence.inline_bytes` 的那一行一起带走了。没有任何东西失败：端点 200，页面除少一个计数外都正确，`npm run verify` 报 49 PASS。CodeFactor 报 `'deltaBytes' is defined but never used`——症状正确，类别错误。

## Impact

- **可用性**：评分运行期间所有函数路由不可用约十分钟。harness 在 17:25:21–17:25:24 之间记录到 404（`/add` 1287 ms、`/search` 370 ms）并重试；该轮最终因其它原因失败，因此两种影响无法在最终分数里分开。
- **响应契约**：重构到修复之间，每个检索响应都缺少 `persistence.inline_bytes`。评测端没有消费者读它，所以分数未变；监控类消费者会看到字段缺失，而不是错误数值。
- 这些失败**不能**做到的事：存储层没有被写错，没有用户数据丢失，回滚一次部署即完成。

## Timeline

1. 构建产物加入 `schedules`；平台文档化过这个数组。
2. **在评分运行进行中**部署到线上项目。
3. 所有路由 404，域名返回平台默认页。
4. 回滚到上一版本，服务恢复。
5. 对同一提交去掉该块做 A/B：`/health` 200、`/beat` 200、`/add` 200、`/search` 200。确定是该块。
6. 移除该块，并加一条"若它回来就失败"的测试。
7. 稍后：复杂度门槛命中 `search`，答案装配被提取。
8. `persistence.inline_bytes` 从每个响应中消失；`verify` 全绿。
9. CodeFactor 报未使用 helper；读 diff 才发现缺失的那一行。
10. 恢复该行，并新增测试要求每个页面都带数值型 `inline_bytes`。

## Root cause

**运行中部署。** "评分运行开始到结束之间不得部署"这条规则在 0006 之后写下，住在那一篇里。部署时没有任何东西去查它：部署路径是一条 shell 命令，而评分运行的状态在一个浏览器标签页里。**依赖操作者在动手那一刻记得的规则不是控制，是便签。** 与 0002、0003 同形——验证存在，但不在动作经过的路径上。

**被丢掉的字段。** 重构搬动了一块代码，其中一行设置了没有测试读过的字段。套件验证的是它断言过的行为，而它没有断言这个字段的存在。linter 的未使用符号检查偶然发现了它——也就是说这一类是被运气抓住的：如果那个 helper 在别处还有调用，就什么都不会报。

## Guardrails added

- `onlion/scripts/build-edgeone.mjs` 不再输出 `schedules`；`onlion/scripts/test-observability.mjs` 若发现构建出的 `edgeone.json` 含有它就失败。该故障在本地不可见——build、verify、预检都不读线上路由表——所以防护落在产物上。
- `onlion/scripts/test-backend.mjs` 现在要求每个检索页面的 `persistence.inline_bytes` 是数值。
- [edgeone-runtime-mechanism](../design/edgeone-runtime-mechanism.zh-CN.md) 记录实测行为（"按文档写出来的 `schedules` 会让整个函数路由失效"），让下一次从证据出发，而不是从平台的示例出发。

## Lessons

1. **不在动作路径上的规则只是文档。** "运行中不得部署"需要在部署时检查——一条会拒绝的命令，或部署会读取的状态——而不是一段话。否则它仍然是一条会被再次忘掉的提醒。
2. **全绿意味着"断言成立"，不是"契约成立"。** 没有断言保护的响应字段是不设防的，而重构正是会静默移除它的那种改动。
3. **linter 的发现可能是"症状正确、类别错误"。** "未使用变量"描述的是一个丢失的字段。把它当风格问题处理，就会删掉 helper 而不是恢复字段。
4. **自我批评属于事故记录，不属于发布 tag。** tag 回答"这一版是什么"，post-mortem 回答"它为什么能过去"。混在一起既削弱发布说明，也让教训更难被找到。

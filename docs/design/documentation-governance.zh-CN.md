## 范围与状态

用本设计处理三类任务：写出可独立理解的正文、找到术语定义、核对文档检查究竟证明了什么。文件短或检查通过都不代表读者能够完成任务。

- **写正文或拆分长文：**先确定读者要完成的动作，再按下节保留条件、例外和失败路径。用[读者审稿](../../skills/doc-maintenance/references/reader-review.md)逐项检查，不以长度替代审稿。
- **查词或登记定义：**按[术语的分布式定义与发现](#术语的分布式定义与发现)选择查询范围；词义与完整行为合同分开维护。
- **核对检查或处理失败：**[文档卫生与预算](#文档卫生与预算)说明机械边界；[CI 契约](../README.md#ci-contract)拥有准确范围和严重级别。

所有权由 [docs 索引](../README.md#ownership-and-authority)决定，修改和提交流程由 [doc-maintenance](../../skills/doc-maintenance/SKILL.md)负责。结构卫生覆盖活跃设计和 Skill Markdown；按角色的字节预算独立生效。流程术语在就近的 YAML 中定义，查询时聚合，不再手工维护中央全量表。正文引用提取和小节哈希未启用；文档分组遵循[双语规则](../README.zh-CN.md#双语规则)。

## 读者与内容归属

[读者导向写作与审稿规范](../../skills/doc-maintenance/references/reader-review.md)拥有内容组织、表达、事实守恒和人工验收的具体要求。它适用于起草、重组、压缩和发布，而不是只在写完后润色；操作流程、查阅合同和论证材料按各自读者任务组织，不强套同一模板。

规范借鉴受控技术英语的清晰表达思路，不声明符合 ASD-STE100，不引入第二套词典、英语词数或句长门禁。表达清晰不能替代任务入口和信息归属，也不能削弱条件、例外、义务或不确定性。具体审稿步骤与例子只在该规范维护。

[现有归属规则](../README.zh-CN.md#所有权与权威顺序)继续区分设计意图、决策理由、测量证据、事故经过、实现状态与未完成工作。按规范完成一个阅读单元的整改，不表示其他专题已经完成，也不表示机械检查能够判断文笔或语义正确性。

## 一致性的不同义务

实现与文档的一致性由其具体内容决定：类型摘录、可执行示例、命令说明和生成目录各有验证方式。生成材料从权威来源产生，确定性的内容以重新生成或新鲜度检查核验；不手工维护第二份目录。完整的操作声明需要实际执行证据，未执行的环境或路径明确标出。

双语或其他人工维护的同义材料，需要确认两份文字保留相同事实。结构、链接目标、代码块和生成区的匹配可以机械检查；词义、自然度和准确性仍归评审。确认记录只说明哪些确切内容被确认过，不证明确认可靠。

小节哈希是可评估的确认记录格式，不是全仓默认要求：分别记录两侧上次确认的内容，变化触发复核；不是通过两个哈希相等判断同义。代码块或声明的生成区只有在独立检查仍负责其一致性时才可排除。盲目重录错误文字仍可能通过，重录操作不能替代正常检查和审稿。不同小节能被 Git 合并，也不证明改动在语义上独立；合并后仍核验受影响的整体。

格式选择优先让普通工具完成必要工作。按小节记录可以减少整文件确认记录的无关合并冲突，但标题改名、章节重组、同节修改和记录维护仍有成本；没有收益依据时不增加这层机制。

## 术语的分布式定义与发现

### 定义与使用

术语定义就近归所属主题，一个概念只有一个权威定义；完整行为规则仍在设计或接口 owner。术语材料解释名称、别名、词义、适用范围和易混概念，并指向该行为 owner。

规范英文词形本身就是术语键，中文译名和其他精确别名归入同一定义；只有同名异义时才用作用域消歧，不另编概念 ID。词条保留简明语义和定义位置。跨域同名不等于同一概念，相关词不自动成为别名。弃用与接替关系保持可追溯，不能通过改名隐藏冲突。

文档“使用一个术语”与“定义这个术语”分开。主题的术语伴随材料只定义自己拥有的概念，共享概念直接引用；使用清单优先由正文引用派生，不同时手工维护正文、清单与总表。正文首次使用时仍给必要解释。术语文件按双语规则维护，没有专门术语时明确记录空清单，不为凑组制造定义；紧密相关的词条不必一词一文件。

### 分层按需发现

可识别的文件标记和必要字段是共同约定，不要求中央登记表或中心服务。领域入口介绍本域与直接子域，顶层只作分类和导航；细目录或全量结果从定义产生，不复制定义，也不成为查询必经点。

知道作用域时直接查询当地定义、名称和别名；未知或未命中时按相关领域扩大范围，必要时遍历明确语料范围内的合规定义并临时汇总。查询报告实际搜索范围；多义命中返回候选和作用域，不任意选一个 owner。局部未命中不能推出全仓不存在。

覆盖承诺只针对显式登记的术语，不包括自动识别自然语言中的所有名词。局部检查只证明局部性质；声称全仓无术语冲突、引用有效或覆盖全部登记定义，需要跨域聚合检查。聚合查询与校验不是集中维护定义。

### YAML 文件与查询合同

登记语料是 `docs/design/` 下常规目录中的 `*.terms.yaml`；`archived/` 和符号链接不属于定义语料。新增文件自动发现，不增加中央清单。这是工具的登记范围，不豁免其他角色的三件套义务。[CI/RCP 主题](ci-cd-and-quality.md)介绍流程词汇，[本主题词条](documentation-governance.terms.yaml)解释治理概念。

查询前校验全部选中引用，本地词也不例外。下例局部语料缺少 memory-graph 依赖，第一条预期失败；再运行第二条扩大范围，不删除正确引用来凑通过。

```sh
# 预期作用域不完整；下一条命令扩大范围。
npm run glossary:check -- --resolve 收据 --within docs/design/ci-cd-and-quality
npm run glossary:check -- --resolve receipt
# 只有同名异义时才需要 namespace；此选项过滤结果，不缩小读取范围
npm run glossary:check -- --resolve context --namespace repository.verification
```

成功查询首行保留名称、owner、标题三列 TSV；v2 随后输出 namespace、状态、定义和来源，不应把全部 stdout 当一条 TSV。歧义返回候选，不任选 owner；错误语料先修复再查询，不能解析出“碰巧命中”的词条。

v2 顶层为 `version: 2`、`terms`、可选 `namespace` 和 `references`。未声明 namespace 的定义属于默认 `repository` 作用域；namespace 使用点分的小写字母、数字和连字符标识，每段以小写字母开头。每条定义包含 `term`、`aliases`、`definition`、`owner`、`anchor`、`status`，不需要 `id`。

`term` 是规范英文词形，`aliases` 包含中文译名与其他精确别名。`definition` 拥有词义；`owner` 是仓库相对的完整行为合同路径，`anchor` 是精确 ATX 标题，不采纳代码块内的标题。`status` 为 `canonical`、`proposed` 或 `deprecated`；弃用词须以 `successor` 指向同域规范词形（或旧 ID）。登记或 proposed 不启用能力。

`references` 引用已有规范词形，不复制定义或增加定义计数；同名异义时才写带 namespace 的引用：

```yaml
version: 2
terms: []
references:
  - receipt
  - term: assertion context
    namespace: repository.verification
```

纯使用清单可写空 `terms`；确认无专门术语时另写 `references: []`。所选语料整体无定义与引用时失败。未知字段、错误类型、空词形、重复引用、未解析或歧义引用均失败；局部未解析需扩大查询，不能静默越界读取。引用按规范词形解析，别名仍用于查询发现。

同一作用域内名称和别名不能重复；跨作用域同名返回候选。改规范词形必须迁移使用清单和接替关系，旧名称可保留为别名供查找。这里接受显式迁移成本，不为避免改名而维护另一套编号。

解析器兼容存在的 v1 `docs/glossary.yaml`、旧 v2 的可选 `id` 及其查询和接替关系，不为新词生成 ID；旧 v2 查询有 ID 时仍输出 ID 行。旧 ID 须符合所属 namespace 且不重复、不被其他名称或别名遮蔽。v1 属于 `repository`、保留原三列输出。错误旧来源同样使聚合失败；有分布式来源时旧表可缺席，无任何来源不能成功。旧工具不保证接受省略 ID 或新增引用的形态。

`npm run glossary:check` 聚合上述语料；`--resolve <名称或别名>` 查询，`--within <仓库相对目录>` 限制实际读取，`--namespace <namespace>` 消歧。未命中报告实际范围，不宣称全仓不存在；空语料、非法目录和未知选项失败。局部接替目标未解析只说明当前范围未决。正文术语引用未自动提取，普通文件链接仍由文档检查负责。

### 现有索引的迁移边界

保留名称、别名与生命周期，合同位置变化时重绑目标。[术语索引决策](../decisions/implemented/2026-09-08-repository-terminology-index.zh-CN.md)拥有兼容范围与成本。迁移不改变行为，也不填补产品覆盖或创建时去重缺口；聚合不是另一张手工词典。

## 文档卫生与预算

结构卫生按 CI 契约覆盖全部活跃设计与 Skill Markdown，原三份必需流程文档仍须存在：标题非空、章节子树存在可见正文，同一父节内的同级标题在大小写与空白规范化后不重复。围栏代码和 HTML 注释内不解析标题；代码内容本身仍是正文。不同父节中的相同标题合法；删除登记文档不能变成静默跳过。这是 ATX 检查，不支持 Setext 或 HTML 标题，也不判断占位文字是否有用。

更广的卫生由审稿关注死链接、重复解释、职责混杂、过期状态、已解决的讨论和过期生成内容。已结束的讨论将结论提升到 owner，删除不再需要的工作过程；有效的历史证据、事故因果和覆盖缺口不随之丢弃。

预算是护栏，不是文笔评分或删减目标。沿用 15,000 UTF-8 字节约束全部 `docs/design/` 活跃 Markdown 阅读单元，新增子主题自动继承；`archived/` 历史设计和实验原始证据仍按各自角色维护。全部 Skill 常读入口沿用 15,000 B，AGENTS 与决策索引仍为 5,000 B；其他 reference 并未被统一限字。准确范围与严重级别只在 CI owner 定义，不另维护文件名白名单。

先使原始超限正文真实被拒绝，再按原有完整职责章节拆分；小解释留在需要它的 owner，条件、例外与相关证据一起迁移。旧入口继续路由，引用和术语指针转向实际合同 owner；历史执行读数归实验记录，不能拿它们声称本轮执行成功。清理表格对齐空格不代替职责拆分，也不把规范正文搬入豁免目录骗绿。无需先证明阅读或抗膨胀收益才执行这条预算规则。

## 检查准入与拒绝用例

新增检查先在现有 CI 规则 owner 明确语料范围、失败性质、错误或告警级别、豁免与退出条件，再实现校验和真实拒绝用例。定性评审不伪装成万能语义检查器。范围按已准入角色自动覆盖新增文件；扩大到其他角色须先修改 CI 契约与对应测试，不能仅因目录存在就纳入门禁。

| 义务 | 拒绝或明确报告的情况 | 检查范围 |
| --- | --- | --- |
| 结构卫生 | 空标题、空节、重复同父同级标题、缺少登记文档 | 活跃设计与 Skill Markdown；必需流程文件缺失也阻塞；`docs:check` |
| 角色字节预算 | 原文超限、未手工登记的新主题超限、移入设计子目录仍超限、中文 UTF-8 超限 | 活跃设计与常读规则入口；`docs:check` 阻塞 |
| 唯一术语定义 | 同作用域名称或别名冲突、引用歧义、错误 schema；旧 ID 冲突 | 登记语料；`glossary:check` 阻塞 |
| 发现范围与合同指向 | 非法目录、空语料、坏 owner/标题、歧义、未命中 | 登记语料或显式局部范围；不包含正文术语引用的自动提取 |
| 派生文档新鲜度 | 改来源但不更新派生内容 | 未新增检查；现有生成物检查不外推到所有文档 |
| 配对确认与合并 | 缺失材料、确认后变化、同单元冲突被覆盖 | 小节记录未启用；不借其他仓库的结果报通过 |
| 文字的完整事实 | 为长度目标删掉失败、时序或限制 | 读者审稿；不是自动语义证明 |

## 未定的合同项

- 未登记领域的术语定义与正文引用提取；流程词汇迁移不等于覆盖全部产品概念。
- 其他文档角色的预算选择与结构卫生准入；已准入角色的预算和卫生覆盖不再是未定项。
- 哪些配对材料值得采用小节确认记录，以及收益、成本与退出条件。
- 产品概念地图与登记定义的衔接。变更在原 owner 与对应测试中落实，不另建术语平台或新的版本控制系统。

# 日志写入路径的停止规则

**Status:** draft
**Created:** 2026-10-28

与 [Add 写不可变日志条目](add-append-log-and-fold-design.zh-CN.md) 和
[pending 计数器状态](add-log-pending-counter-state.zh-CN.md) 配套。那两篇负责设计，本页负责
**什么时候停**。

## 为什么需要这一页

前四轮复核每轮都发现真缺陷，而每一条都被当成阻断项处理。这个循环没有终止条件：复核方在
负责人写下"什么是完成"之前无从判断，而把每条发现都当阻断的负责人也无法回答"多少才算够"。
代价不是修本身，而是**A 类正确性问题与"少个字段"排在同一行**。

## 缺陷分级

**A —— 阻断。** 唯一能停下某一片的类别。它会让已受理数据不可检索、重复或丢失；让 `200`
声称不成立的事；或让回滚不安全。迄今所有缺陷都是 A：把对象当字符串迭代的折叠、忽略退休条目
的递减、从未写进 manifest 的零、二次扣减、先写条目后提交计数、把失败写读成"没落地"、丢掉
计数的 reset 交接、以及先截断后过滤的读取窗口。

**B —— 记录，不阻断。** 性能、可观测性、错误措辞、缺字段：每次折叠多一次列举、
`/capacity` 的字节口径、分阶段耗时。它得到一条带负责人的跟进项，而不是一片工作。

**C —— 明确判定不做。** 写下来以免有人重复提议：

- 真实对象写失败的故障注入（假 bucket 已能证明三态选择）；
- 并发下 manifest CAS 的形式化证明（设计依赖重试）；
- 读取路径遗留条目超过 32 的情况（受 `SCAN_FACTOR` 界定，且因 reset 交接把数量带进折叠
  触发器而自愈）；
- 跨区域延迟调优。

## 片 1 —— 代码入库，`NMG_ADD_MODE` 保持 `sync`

五条同时成立：

1. `onlion` 的 CI job 绿；
2. `verify:static` 绿，含本次触及文件的复杂度上限；
3. 状态表覆盖每个迁移并点名执行它的函数；
4. 最近一轮复核没有 A 类；
5. 生产行为不变——默认仍是 `sync`。

## 片 2 —— 默认切到 `log`

1. 实测 16 路并发 Add 突发，且 `log` 的 p95 低于 `sync` 的 p95；两个数字都写进决策记录，
   不是从理论上断言；
2. 回滚前对用户调用 `/admin/fold` 能返回 200，使 runbook 那一步可执行而非愿望；
3. 切换是一个设置项，且可逆；
4. 切换后**一轮**复核没有 A 类。

## 回合上限

连续**两轮**复核只发现 B 或 C，该片即完成。此后的发现一律记为带负责人的跟进项，不阻断。
声称阻断的发现必须**点名它破坏了哪条 A 类性质**——数据可见性、`200` 的诚实性、回滚安全——
因为"还能更好"按定义属于 B。

## 片 1 已接受并记录的已知风险

- 真实存储上的写失败只用假 bucket 覆盖过；
- 并发折叠由 manifest CAS 串行化，是假设而非证明；
- 读取窗口扫描 `4 × 8` 个键，大规模遗留代际只会延迟、不会永久遮蔽当前条目。

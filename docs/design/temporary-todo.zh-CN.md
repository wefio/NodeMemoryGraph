## 收集可信的已验证证据监督

- [ ] 积累在实质上独立的 Pi+NMG 任务，含检索、精确 `get` 披露、展开深度、用户／工具验证的证据、结果／纠正、注入 token、工具轮次与端到端延迟。
- [ ] 分别标注证据充分性、展开有用性、过度噪声与无需记忆。沉默或未被纠正的答案保持 `unknown`，不是成功。

**可用机制：** 会话所有权、provenance、按时间顺序的任务划分、披露捕获、claim outcome、紧凑就绪度报告，以及自然证据 Skill 工作流都已实现。受控样本验证了管线，但不能算作自然证据。

**当前阻塞：** 已采集的自然图里，独立验证的 claim 归因不足以训练证据排序或预算。采集应优先显式用户确认、工具可验证的成功结果、纠正与失败。答案重叠、任务完成、沉默或缺少纠正都不得被重新标为证据。

**完成条件：** 一个按时间分离的自然数据集包含足够多的可归因正、负、部分与无记忆结果，能在不依赖受控或仅 API 诊断的情况下支撑下面的匹配门禁。

## 校准检索与可微控制器

- [ ] 在语义任务与时间划分上，把冻结的启发式与冻结的 shadow 候选做比较；持久化特征版本、数据窗口、生效配置、指标、候选身份与回滚目标。
- [ ] 只有当自然 trace 能可靠把下一层与检索建议这两类标签与一般展开区分开时，才增加它们。
- [ ] 把证据／答案充分性与显式 token、工具调用、深度、延迟成本一起优化。硬安全与预算限制留在可微图之外。
- [ ] 只在一次匹配的自然评估之后晋升低风险决策。没有记录的倾向得分或已证明的序贯信用分配问题，就不要加入上下文赌博机或长时程 RL 机制。

**可用机制：** QPP1、QPP2、检索建议、一个无框架依赖的自动微分控制器、冻结候选、带类型执行遥测、按时间顺序校准、可回滚的 shadow 工件、官方 benchmark 评分，以及 fail-closed 的质量／成本门禁都已存在。

**当前阻塞：** 开发期比较改善了答案与证据指标，但增加了 token 与延迟成本，未通过一次独立的 LoCoMo 门禁，且既不是自然产品证据，也不具统计结论性。当前常数仍是冷启动先验，不是已校准概率。

**完成条件：** 一次规模足够、证据多样的匹配自然评估显示出有用的因果动作，并通过答案／证据质量外加 token、工具轮次、深度、延迟与回滚门禁。

- [ ] 在按自然结果启用默认无人值守晋升之前，测量 STG 到 LTG 合并的精确率与可逆性。

**可用机制：** 确定性合并与身份门禁、provenance 感知的 claim outcome、可逆变换、只读维护审计、积压计量，以及一个默认关闭的自动合并执行器都已存在。

**当前阻塞：** 普通 store 里自然可归因的 claim outcome 与身份决策太少。既有受控 fixture 证明的是管线与审计一致性，不是自然精确率或误合并安全性。

**完成条件：** 自然样本覆盖被接受与被拒绝的合并、反转、真身份、伪身份、作用域冲突、同名实体与回滚，且精确率与恢复成本可接受。

## 把特征哈希／SimHash 作为词法层的补充（候选）

用哈希的词级用法被明确排除在被拒绝的语义检索决策之外
（[2026-09-03-hashing-vector-retrieval-fallback](../decisions/rejected/2026-09-03-hashing-vector-retrieval-fallback.zh-CN.md)）；
本票只界定候选范围
（[记忆系统先例](https://github.com/nikhilsitaram/claude-memory-system/issues/53)）；
设计：[simhash-lexical-complement-design.md](simhash-lexical-complement-design.zh-CN.md)。

- [ ] 评估 `statementSimilarity`（词集 Jaccard）是否会漏掉拼写或词形不同的近似重复（"embedding" 对
  "embeddings"、拼写错误），以及一个存储的 64 位 SimHash 指纹
  （Hamming ≤ 3）是否能召回 Jaccard 路径召不回的候选。
- [ ] 决定它插在哪里：写入路径上的取代／近似重复候选召回——不是检索排序，也不是被拒绝的语义检索混合。
- [ ] 如果采纳，保持 store 小且离线：每条记忆一个整数列，内存索引约每千条约 KB 级，无外部依赖。

**可用机制：** `statementSimilarity`（词级 Jaccard）已存在，而 NMG 只在精确规范化相等时动作；表面锚点已为显式 token 提供字符级（trigram）容忍。取代／重复候选当前来自 token 重叠，对词形变体是盲的。

**当前阻塞：** 没有指纹索引；确切的缺口（词形／拼写变体召回）只是被断言，没有被测量，而写入路径的 judge 不是当前的去重消费者。

**完成条件：** 一次测量显示 Jaccard 路径漏掉词形变体重复而 SimHash 预过滤器能召回它们（或显示该缺口已被覆盖），无论哪个方向都记录一条决策——在召回缺口成为事实之前不建推测性索引。

## 明确推迟——不是当前工作缺失

这些选项只有在观察到其前提之后，才回到上面的活动清单：

- 云同步与多设备冲突解决：只在多设备操作进入范围时。
- Rust/Python 重写：只在测量到 TypeScript 瓶颈或出现不可回避的原生依赖之后。
- 把 vLLM 作为运行时依赖：已为本地优先默认拒绝。
- RCP 连续 watcher／队列／目录：只在出现真实的连续 Contract、证明运行到完成不足之后。
- 可移植 RCP 收据证明：只在收据必须跨机器或跨组织独立验证时；本地收据对当前的操作者审计与幂等性仍然足够。
- 严格的 Huffman 存储：只在层级／块访问未达已测量的规模或延迟目标时。
- 自动多边模体合并：只在普通节点与边适配拥有可信自然标签之后。
- L5 物理清除：只在隐私、恢复与用户同意策略经审阅并实现之后。
- 完整的长时程强化学习：只在出现真实的序贯信用分配问题之后。
- 跨会话 AG 延续、自动推理工作区捕获、事件归档与隐式 STG/LTG 晋升继续保持推迟。新 AG 归会话所有且内存驻留；只有其不可变观察 trace 可以持久化。
- MGR 默认／自动推理保持推迟。把 opt-in 引擎接到有界 AG 输入是实现工作，但自动启用它仍需要已证明的推理价值。
- `memory_maintenance_policy` 的自动 SkillOpt 优化与抽取：哈希绑定的提议存储、内容／作用域／检索三方归因、长时程门禁与显式审阅通道都已实现。学习与自动提议生成要等足够的自然标签；审阅从不执行变更。
- 完整物理隐私擦除、学习聚合重置、适配器擦除钩子与擦除回执：在任何隐私擦除产品声称之前，于威胁模型与用户同意审阅之后。当前 delete/forget 是逻辑撤回。
- 面向微小自动微分基座的 GPU/WGSL 执行：只在 profile 发现某个负载违反 CPU/WASM 预算之后。
- 运行时 RPC 注册与目录热重载：只在可信的动态扩展用例定义了处理者所有权、在飞请求行为、能力撤回与缓存失效之后。当前进程生命周期内目录是冻结的，增量发现使用其确定性指纹。

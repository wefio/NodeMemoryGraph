# EdgeOne Makers 运行时：平台实际做了什么

**Status:** draft
**Created:** 2026-10-31

本文负责**平台**的机制——EdgeOne Makers 云函数如何调用、复用和限制一个 Node 处理函数。它不是关于我们代码的；
那部分见 [search-time-budget-design](search-time-budget-design.zh-CN.md)。

它存在的原因：同样三条平台事实，被从样本里重新推断、并且推断错，不止一次——"模块级变量能跨请求存活"、
"存在 `waitUntil` 钩子"、"日志里的内存数值属于这次请求"。每一个错误假设都产出了一个在生产上毫无作用的修复。

每条陈述都标**证据等级**。一条陈述只能被新的测量或新的官方文档改变，不能被单个样本的推断改变。

## 1. 调用生命周期

| 陈述                                                                                                             | 来源                 |
| ---------------------------------------------------------------------------------------------------------------- | -------------------- |
| 每次调用运行在**全新 isolate** 里：40 多条观测到的请求行中 `instance.seq` 恒为 1，跨 `uptime_s` 1210–3731 的容器 | 实测                 |
| **容器会被复用**约 40–60 分钟；`uptime_s` 在彼此独立的请求之间持续增长                                           | 实测                 |
| 因此模块级变量在实践中**不会**跨请求存活                                                                         | 实测（由上两条推出） |
| **没有**文档化的实例复用保证、预留实例或预置并发                                                                 | 官方（缺失）         |
| 本产物的冷启动约 **2–5 秒**；热容器 `/health` 约 25 毫秒                                                         | 实测                 |

**后果。** 任何跨请求的缓存、熔断器或计数器，在这个平台上都是每请求构造物。依赖它的代码在 isolate 恰好被复用时
仍必须正确——复用窗口是未文档化，而不是被禁止。

## 2. 并发

| 陈述                                                                                          | 来源                    |
| --------------------------------------------------------------------------------------------- | ----------------------- |
| 同一容器上的请求被**串行化**：突发分散到少数实例，单实例时延随并发增长（实测 1 → 2 → 4 → 16） | 实测，`postmortem/0006` |
| 由此产生的运行决定：评测以并发 1 运行                                                         | 决策                    |
| 一个实例上的慢请求会拉长同实例的其他请求                                                      | 实测                    |

**后果。** "我们的单请求时延"只在声明并发数时才有意义。两个构建在不同并发下的时延对比不是对比。

## 3. 硬上限

| 上限        | 值                       | 来源         |
| ----------- | ------------------------ | ------------ |
| 调用时长    | **120 秒**（默认 30 秒） | 官方         |
| 请求/响应体 | 6 MB                     | 官方         |
| 代码包      | 128 MB                   | 官方         |
| 内存        | **未文档化**             | 官方（缺失） |
| 运行时      | Node 20.x                | 官方         |

**后果。** 在 120 秒被掐断的请求是平台掐的，不是我们；在 30–60 秒返回的请求不是。两者是不同的故障类，不能合并统计。

## 4. 处理函数上下文

Node.js 运行时页把处理函数上下文文档化为 `uuid`、`params`、`env`、`clientIp`、`server`（`region`、
`requestId`、`geo`）——一个不含 `waitUntil` 的封闭枚举。而 `waitUntil` 被**明确**文档化在 **Edge Functions**
的 `EventContext` 上，其字段是 `params`、`env`、`waitUntil`。所以这个钩子存在于本产品族，属于另一个运行时，不属于云函数。

| 陈述                                                                  | 来源 |
| --------------------------------------------------------------------- | ---- |
| `waitUntil` 属于 Pages Edge Functions（`FetchEvent`），不属于本运行时 | 官方 |
| 生产环境每一条请求行都报告 `execution: "inline"`                      | 实测 |
| 代码不依赖 `waitUntil`；该分支留给提供了它的运行时                    | 代码 |

**后果。** 这个运行时没有"响应之后"的工作。每个截止时间都必须在调用内部，这正是"在 X 之前开始"式预算被换成真正
截止时间的原因。

## 5. 平台日志列的含义

| 列           | 含义                               | 陷阱                                                                                                           |
| ------------ | ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 耗时         | 平台自己的计时                     | 某些记录类被报成 **0 ms**，其中包括状态为超时的记录——一行 `超时 / 0 ms / 0.0000 MB` 是字段未上报，不是请求很快 |
| 内存         | 采样时刻的**容器** RSS，不是每请求 | 这解释了一个稳定的 500–800 MB 数值为何不随流量增长                                                             |
| 域名 / 路径  | 某些记录为空                       | 没有路径的记录表示处理函数没有完成，不能当作某条路由的证据                                                     |
| 请求 ID 尾段 | 多行共尾段暗示同一容器             | 只是暗示，不是证明                                                                                             |

**后果。** 耗时与内存都为 0 的一行，无法支撑关于速度或内存的任何结论。两行 RSS 相同只是"同一容器"的弱证据。

## 6. 部署行为

| 陈述                                     | 来源                                   |
| ---------------------------------------- | -------------------------------------- |
| 部署原子切换版本：没有请求由混合版本服务 | 实测                                   |

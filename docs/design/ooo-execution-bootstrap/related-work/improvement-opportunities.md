## Improvement opportunities and recorded status

1. S2 should use a log-and-replay round record, recording model calls as nondeterministic activities so restart can recover rather than relying on one report. **Done for replay only, not model reruns:** `src/integration/ooo-round-log.ts` represents a round as a JSONL event stream (plan / check issuance and terminal outcome / claim / artifact or worker failure / dispatch / decision / destination of each mutant / reopen / terminal state); `recordedWorker()` substitutes recorded answers for model calls, and `compareTerminal()` compares terminal outcomes. The first replay **falsified orchestration determinism**: A's frozen instructions embedded a randomly generated `checkId` on every run, so each round digest differed and the host correctly rejected the recorded artifact as `stale patch digest`. The coordinator fix derived check identity from round state (`digest([taskId, attempt])`, scoped to the store; `runId` remains the discriminator). Replay does **not** rerun the model; it reruns host checks, so artifact acceptance can be revalidated without worker tokens. **Replay bound to round identity (2026-09-12):** every claim in the log carries that task's frozen digest (baseline files, instruction, declared failure, budget, and limits); the plan event also carries the recorded revision and **verifier-rule digest** (check command/arguments/label, which is not part of any task's frozen work). Replay compares all three first. A mismatch receives a **named refusal** (`replay refused: the frozen work differs from the log`), rather than producing a result that merely looks reproduced; only after matching does it check out the candidate worktree at the **recorded revision**. Measurement exposed this gap: after promoting round 7's artifact, replaying the same log rejected A/B/C (baseline changed → digests changed → all recorded artifacts were stale). Comparing terminal outcomes alone hid that the run was not the same; a test then showed that changing the check command left both digest and terminal result unchanged, which is why verifier rules must be part of identity. Still missing: logs are not tamper-evident (no hash chain; trusting them is trusting an ordinary file), and replay uses recorded artifacts, not “the model's best answer at the time.”
2. Audit every write path for token checks at the commit point. `submit()` already did this; equivalence for `cancel`/`issue`/accepted results still needed item-by-item confirmation. **Recorded as done:** `submit()` rechecks `bound()` inside the commit transaction; new `cancel()` fences the whole round by advancing attempt numbers, making late artifacts `stale` rather than accepted; `abandonCheck()` accepts only an issued ticket, so forged tickets are invalid.
3. Add an explicit round-cancel path to prevent orphan workers or check processes. **Mechanism done:** `cancel(reason)` advances each task's attempt, revokes pending handoffs, marks checks terminal, and makes `next()`, `claim()`, `issueCheck()`, and `externalReady()` refuse; the cancellation reason survives restart. **Orphan-process evidence added (2026-09-12):** `runCycle` accepts an operator `AbortSignal`; cancellation (a) calls coordinator `cancel(reason)` (advancing attempts so late artifacts are `stale`), (b) kills in-flight check **process trees** (`candidate.ts` uses `spawn` + `detached` on POSIX / `taskkill /T` on Windows), and (c) stops dispatch and composition verification, recording terminal outcome `cancelled`. Two observations were recorded: `cancellation.test.ts` used real child processes and a real worktree to show check processes and descendants no longer alive, no leaked worktree, and no accepted artifact; the multiprocess case used real worker processes to show in-flight delivery became `stale`, dependencies did not unlock, and the reason survived daemon restart. Two limits were called out: on Windows, libuv's job object already reaps non-detached children (the test still passed after replacing tree-kill with `child.kill()`, which was measured), so explicit tree-kill is redundant protection there; process-group killing on POSIX is the step that establishes the property. The test's grandchild was not detached, so deliberately detached grandchildren were outside the assertion.
4. **Premises before dispatch.** A task instruction might assert “the host has proved these mutants survive”; that assertion is a dependency of the task. In an earlier matrix, B's model call ran in parallel, spending 204,164 tokens on a premise that was already false. Now proof precedes claim, so a worker for a false premise costs zero. When dispatch is refused, withdraw any handoff already published (`withdrawHandoff`): the board serializes pending entries, so an unclaimable handoff blocks every later claim in the round.
5. **Unmeasured is not measured-and-clean.** Premise matrices have three outcomes (`survived` / `killed` / `unmeasured`). If concurrent `git worktree add` fails, the check measured nothing. Earlier code classified `undecidable` as “detected,” and a round reported a surviving mutant killed in 76 ms. Now `unmeasured` ends the round as `premise-unmeasured` (not `premise-invalid`); candidate worktrees use bounded retry.
6. **One standard artifact channel.** Text answers from patch attempts used to be recorded verbatim, then the host rejected them as `invalid patch structure` after the cost was paid. Now text answers must pass the same envelope validation as tool submissions; invalid text is a failed attempt with its reason. The system prompt no longer describes a text channel; patch attempts are explicitly required to use the artifact tool.
7. S4 comparisons must answer “could this design be slower?” Mutant rechecks and candidate directories add host overhead; report that cost, not just benefits.

At the main integration snapshot, `evals/ooo-execution/recovery.test.ts` declares nine named local SQLite scenarios: no successor claim theft; duplicate submission without double dependency release; stale artifacts from revoked claims; a new generation on lease expiry; undecidable termination for an unreported check; refusal of forged tickets; preservation of the first cancellation reason; cancellation fencing late artifacts across reopen; and claim/ticket identity preserved when reopening the same database. Patch artifacts bind `BoardTicket.declaration.digest`; refusing a wrong digest does not prevent a correct artifact on that same live claim. These scenarios close and reopen coordinators: they do not construct old schemas, prove arbitrary legacy upgrades or simulate process kills. See the [frozen-declaration decision](../../../decisions/implemented/2026-10-13-recovery-tests-use-frozen-declarations.md). This states declared coverage, not a fresh execution of that suite. Two separate real-process cancellation records cover tree termination, no ghost completion, no dependency unlock and persisted reasons; named replay refusals remain separate evidence.

A terminology note from the source record: coordinator = retire/commit stage; acceptance = commit; rejection = squash; attempt digest = fencing token. The distributed-systems analogy is explanatory, not evidence that every product write path implements the same contract.

## 可执行 v1 规格与决策闸门

本节与[低算力、仅路由的候选方案](harness-formalization/low-compute-router-candidate.zh-CN.md#低算力仅路由的候选方案)覆盖与之不兼容的早期理论主张。目标是按端到端资源预算衡量的**经核验任务效用**，而不是拟合生命周期标签。规格可修订；未能击败固定规则本身就是一个有效的实验结果，并默认阻断额外架构。

### 运行时归属与数据流

```text
RCP / board / bookmark / harness event (source-owned identity and version)
  -> session/task-frame observation (bounded, temporary, replay-idempotent)
  -> pre-action feature snapshot + permission/budget mask
  -> fixed fallback OR explicitly authorized experimental router
  -> decision journal (must succeed before any side effect)
  -> fixed action executor -> host model exposure
  -> fixed-window external verifier + measured costs
  -> outcome journal -> admission -> grouped offline dataset
  -> train / validation selection / untouched test -> reviewed policy artifact
```

不需要新的权威全局事件服务。生产者保留各自的事实，并通过适配器提供引用。harness 拥有连接与有序日志；AG 拥有临时工作状态，不拥有任务验收。看板 resolve 是自报事件，commit 是版本事件，SimHash 是文本变更事件。它们可以触发注意，但永不自动成为任务奖励。RCP 只验证它声明的 contract。失败的 receipt 是有用的反馈，既不是整任务失败的证据，也不是扩大范围的许可。

### 确切的特性契约

`context-features-v1` 有 16 个值，随后 16 个缺失指示器。缺失是 `(0,1)`；观察到的零是 `(0,0)`。比率为 `[0,1]`，上一次经核验的奖励在 `[-1,1]`。三个计数在 32 处饱和并除以 32。

| 索引 | 特征 | 编码 |
| --- | --- | --- |
| 0 | contextOccupancy | 已用 / 硬性上下文容量 |
| 1 | remainingTokenRatio | 剩余 / 初始 token 预算 |
| 2 | remainingToolRatio | 剩余 / 初始工具调用预算 |
| 3 | topCandidateScore | 版本化检索过程下的有界分数 |
| 4 | candidateScoreGap | 第一有界分数减第二有界分数 |
| 5 | candidateCount | 计数 / 32，饱和 |
| 6 | candidateRedundancy | 固定身份规则下的重复占比 |
| 7 | candidateFreshness | 源版本仍为当前的占比 |
| 8 | stepsSinceVerification | 计数 / 32，饱和 |
| 9 | consecutiveFailures | 计数 / 32，饱和 |
| 10 | returnedFromInterruption | 观察到的 0 或 1 |
| 11–14 | previousNone/Cue/Resurface/Retrieve | 上一次已执行动作的 one-hot |
| 15 | previousReward | 仅在更早独立核验的窗口内 |

无法获得的测量保持缺失，绝不由 LLM 猜测。空或零的初始预算产生缺失比率加上硬性动作拒绝，而不是除零。所有特征必须在选择之前可得。历史以任务/帧为界，在验收版本变化时清除，并且不能读取未来结果。无历史消融把索引 8–15 连同其缺失指示器一起掩码。

### 动作、日志与失败处理

`none` 不返回额外内容；它不取消强制性的安全反馈。`cue` 使用固定的版本化提醒。`resurface` 按调用方提供的顺序选择整段既有片段。`retrieve` 调用一个固定过程，带中止信号与上下文上限。宿主必须在调用前与暴露前检查授权。当前适配器只向宿主返回有界内容，本身不负责把内容暴露给主模型；模型暴露集成仍未完成（见验收表）。上下文按完整片段边界裁剪，以保留源身份；过大的片段被省略，而不是被悄悄改写。所有动作共享同一个硬包络。成本扣减永不抬高该包络。

日志记录不可变的决策、执行与结果修订。未被写下的决策不能执行。执行之后的写失败留下未知结果，并禁止自动重复执行；先以外部工具的幂等身份进行 reconcile。完全相同的重复投递被去重；同一 ID 下的决策变更属于错误。错误或重新打开的修订会在数据集重建时撤回该标签。包含已撤回标签的既有训练产物必须在提升之前作废/重训，不得通过把重新打开当作又一个独立负例来悄悄打补丁。

`runContextTrial` 等待每个汇聚屏障，包括异步屏障。其执行修订对生成内容与来源 ID 取指纹，并记录实际执行器的工具调用。评测收到一份副本；独立验证者收到单独的、真实结果的快照，而不是被评测器改动过的对象。即使是在数据集重放中，结果侧工具调用总数低于执行器计数也会被拒绝。Token、奖励、模型暴露与更宽窗口的成本仍需来源支撑的核验；摘要或 `() => true` 都不能认证它们。超时中止信号与其他执行器取消被区分对待。

`ContextTrialJournal` 是可选的本地持久汇聚点，不是分布式事件服务。它持有独占的生存期锁、对每条记录做 append/fsync、检查身份/阶段转换、拒绝重复的决策预留、保留重新打开并重放最新状态。损坏/撕裂的尾部或过期锁会失败即关闭；不确定的写入会毒化该实例。容量上限会停止后续写入，而不是悄悄轮转掉幂等证据。操作员必须在解锁/轮转之前检查崩溃状态。跨日志/跨任务串行化、安全恢复、模型暴露与外部证据核验仍是宿主职责；本地 fsync 不是可移植的第三方证明，也不是分布式事务。

### 学习器与低维历史决策

初始架构仍为 `32 -> 4`、132 个参数、使用既有自动微分底座的已观察动作平方误差回归。选择是在允许动作上做成本调整的 epsilon-greedy；倾向是采样概率，不是标定后的置信度。不要在影子选择上训练。快照分支只为每个分支中实际被执行的动作打标签。

首先比较固定规则、无历史的线性头，以及带实测历史特征的同一个头。只有当留出的顺序任务显示出未解决的、依赖历史的错误时，下一次比较才应加入 8 维循环状态或有界因果历史节点注意力。此类节点属于 Agent 决策步，而不是不可访问的主 LLM 隐层。它们的参数、状态重置规则、梯度测试、算力与内存上限必须在该实验拟合之前规定。目前没有任何理由仅仅为了填满一张图而实现这个网络或可选的 596 参数 MLP。

### 标定与启用

benchmark 数据可用于训练与标定；自然数据量不是离线实验的前提。保留源数据集哈希、对话/任务组、执行器/特征/验收版本、策略身份、实际执行、结果窗口、来源与成本度量方法。合成 fixture 只确立机制。独立训练/验证/测试分区由来源组定义，而不是由相邻行或改写定义。只在验证集上选择超参数；在查看测试结果之后，后续改动需要新的独立评测或显式的探索性标签。

LoCoMo 组件探针是自定义的词法证据打分，不是产品检索 benchmark。它无法检验 cue 效用、顺序历史或主模型成功。官方答案流水线仍归 OmniMemEval 所有；集成必须保留官方打分，并在相同主模型设置下比较匹配的上下文干预。端到端窗口包括后续模型/工具成本、返工与最终验收，而不仅仅是插入的字符数。

提升要求预先声明的任务指标、非劣性边际、预算与失败阈值；留出的独立组；不确定性估计；无安全违规；以及相对于固定回退没有不可接受的质量/成本回退。在这些条件被提供之前，闸门是关闭的，而不是在看到结果之后另造阈值。策略制品绑定数据/代码/特征哈希、训练设置与批准范围。宿主可以在不改变记忆内容的情况下回退到固定规则。仅凭良好的离线分数永不全局启用该策略。

### 其余集成验收

| 集成 | 称为完成之前所需的验收 |
| --- | --- |
| 生命周期生产者 | 来源 ID、重放去重、任务/帧隔离与失败 receipt 到达 AG 而不变成奖励 |
| 带定位书签的片段 | 确切的来源/版本检查、外部文本被当作数据处理、总 AG 预算被强制执行、过期/缺失来源保持显式 |
| 长期任务 | 既有受治理的记忆存储保存经外部批准的目标/版本/证据；恢复时重新核验它，而不是相信看板 resolve |
| 模型暴露 | 捕获的投影与实际注入的上下文一致；被取消/未暴露的动作不能成为已执行模型样本 |
| 生产日志 | 存在本地重复/重放保护；跨日志恢复、任务串行化与依赖的已部署制品在晚期重新打开时的作废仍属必需 |
| 结果准入 | 独立的来源适配器核验分数、身份、窗口与成本；未核验的自报仍被排除 |
| 效力 | 匹配的留出主模型任务达到或超过预先声明的回退质量/成本闸门；组件测试不能替代 |

这些闸门区分"已规定的设计"与"已实现的系统"，以及"已实现的系统"与"经验上有用的默认"。在这些集成仍然开放期间，不授权任何整体完成主张。

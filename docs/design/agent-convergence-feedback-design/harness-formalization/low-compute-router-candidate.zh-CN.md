## 低算力、仅路由的候选方案

**范围与优先级：** 本小节规定一个受限算力预算下的候选策略，而不是一个已启用的产品控制器。仓库目前已有 132 参数 `ContextRouter`、`context-features-v1` 与四动作 `context-executor` 研究原语；这些原语的存在并不等于候选策略已组装或启用，也不证明任务效用或授权生产使用。对本候选而言，下述证据与预算边界优先于[上层设计 §§3.5–3.11 中的 Harness 主张](../../agent-convergence-feedback-design.md#35-what-quests-are-in-this-system)，尤其是更强的梯度、生命周期标签、影子探索与软预算主张。那些假设不是本实验的前提条件，也不是它的保证。

借用混合专家（MoE）路由中开销很小的门控结构，而不是它的预训练权重或神经专家。预训练的 MoE 门控把某一模型层的 token 隐状态映射到该层的专家身份；那些表示、输出与训练目标都不匹配 Harness 的状态特征与干预动作。维度匹配并不能确立语义兼容性。

```text
quest / event / context / intervention history / resource features
                  ↓
          deterministic allowed-action rules
                  ↓
             small action-value router
                  ↓
     none / cue / resurface / retrieve
                  ↓
      existing operations through fixed executors
                  ↓
             frozen main LLM
```

该候选包装既有操作，而不训练专家：`none` 保持上下文不变；`cue` 使用固定的焦点提醒模板；`resurface` 重新呈现被选中的既有证据；`retrieve` 调用一个固定的检索过程。现在已有四动作有界适配器 `src/lab/context-executor.ts`：它向宿主返回内容，而 `retrieve` 委托给一个由调用方提供的过程。它不会把内容暴露给主模型，也不提供生产集成。在首次比较中固定模板、候选选择、检索设置与逐动作上限。不要联合学习查询生成、压缩、删除或任务验收标准。

学习者之外的规则决定权限、证据资格、上下文容量与硬预算。路由只在允许的动作中选择；`none` 始终可用，但不能压制强制性的验证或安全反馈。成本惩罚从不授权超出硬上限。

#### 架构与参数预算

| 候选 | 映射（含偏置） | 可训练参数 |
| --- | --- | ---: |
| 初始基线 | `Q(x) = Wx + b`，`32 → 4` | `4×32 + 4 = 132` |
| 可选非线性对照 | `Q(x) = W2 sigmoid(W1 x + b1) + b2`，`32 → 16 → 4` | `16×32 + 16 + 4×16 + 4 = 596` |

这些是起始配置，不是经验最优规模。输出是四个动作价值，不是概率；不需要 softmax 与 Top-K 专家混合。只使用干预前可观察的特征：事件类型、上下文占用、距上次验证的时间、从中断返回、重复错误、既往干预、候选新鲜度/冗余度，以及剩余资源。当前 32 输入契约已版本化为 `context-features-v1`，并由 `src/lab/context-features.ts` 实现；见[确切的特征契约](../executable-v1-specification-and-decision-gates.md#exact-feature-contract)。未来如要改变特征含义，必须在收集数据前使用新版本。归一化数值输入并显式编码缺失值。不要仅仅为了运行这个小路由而获取新的 LLM 生成特征。

`src/lab/autodiff.ts` 是当前 132 参数 `ContextRouter` 原型所用的底座；该原语并不证明候选策略已完整集成、运行很快或有效。组件测试 `tests/core/context-router.test.ts` 检查了已观察动作更新，以及在不同样本和动作下的有限差分梯度，但不确立端到端策略效力。在把该头部用于训练之前，仍应针对确切网络与已观察动作损失检查前向值与有限差分梯度；若使用编译执行，则应在不同样本与动作选择上与未编译路径比较。`ContextRouter.update()` 当前一次更新一个状态/动作/结果；不要假定批广播或 softmax 轴语义。仅有权重存储还不包括梯度、计算图与临时缓冲区。自动微分降低梯度计算的工作量，不降低获得可信干预结果的成本；此处不主张性能或策略效力。

#### 已观察动作的学习与评估

从动作价值回归模型做起，并把探索放在网络之外：

```text
h* = argmax_{h in allowed(x)} [Q_phi(x,h) - lambda K_hat(x,h)]
L_sample = (Q_phi(x,h_executed) - r_observed)^2
```

这里的 `r_observed` 是固定评估窗口下有范围界定的结果，不是对生命周期状态转换的自动奖励。只有被执行动作的输出获得结果标签；未执行的动作不是失败。`K_hat` 度量同一窗口内的期望总成本，包括后续主模型调用、工具与延迟，而不仅仅是插入的 token。初期使用固定成本估计；单独的成本头会改变参数数量，超出上面两种配置。普通的观察性回归估计的是关联，不是因果动作价值。

记录任务与验收条件版本、动作前特征、允许集合、被选中与实际执行的动作、选择概率、策略版本、证据引用、结果窗口与成本。显式记录取消、超时、缺失证据以及之后的重新打开；缺失证据不是成功标签。测试只验证被演练到的条件，reconcile 只核对其声明的 contract，commit 只提交一个版本边界，定位书签/SimHash 只检查位置或文本漂移。看板 resolve 仍是自报。外部计算与实测的假完成率都不会自动使某个奖励或其梯度无偏。把之后的返工与最终验收作为分离的结果保留；局部完成不必改善整条轨迹。

先使用被动/影子日志来检查埋点与策略差异。它无法识别从未被执行的动作的收益。要比较干预，就要在获授权的实验任务中真正执行随机化的允许动作（例如记录在案的 epsilon-greedy 指派），或在匹配预算下从可复现的状态快照分支。单决策窗口只有在忽略或有界化下游效应时才近似为一个上下文赌博机；它不证明各任务彼此是独立回合。

在留出的完整任务上比较固定事件规则、132 参数基线，然后才比较可选的 596 参数 MLP。使用独立核查的完成状态、返工、最终成功与端到端成本；按任务切分而不是按相邻日志行切分，以减少泄漏。在证据支持启用之前保留固定规则回退。本候选文档不包含神经专家训练、预训练路由移植、更大的语言模型管理器、实时 benchmark 运行，也不包含生产策略变更。

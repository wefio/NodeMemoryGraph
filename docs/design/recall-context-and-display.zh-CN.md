# Recall 临近上下文与显示模式

**Status:** current
**Related:** [InformationView](state-spaces.zh-CN.md)、[自动召回预算](session-memory-lifecycle-hooks-2026-08-10/automatic-recall-budget.zh-CN.md)

## 查询准备

统一引擎的本地自动召回在检索前使用临近上下文处理已准入的短追问。
查询最多带上一条同会话、同项目的实质用户消息。调用方已补全的查询直接使用，
Active Graph 记录原始请求。

## 候选排序

SQLite 混合检索为显式搜索和两种自动召回模式使用同一套校准分数融合。引擎从每路最多
100 条候选中融合 BM25 和向量余弦分数，再读取选中候选的原始证据。共享 daemon 沿用融合顺序选择候选和装包。
跨库组装沿用状态对账，跨查询组装沿用主查询优先。
[融合决策](../decisions/implemented/2026-11-20-local-log-odds-fusion.zh-CN.md) 记录权重和校准方法。

会话关联结果在未采用校准混合排序或注入证据排序时使用临近上下文排序。这一步在反馈暂存前重排候选页，
保留候选成员和分数。两种自动召回模式都使用临近上下文准备查询。

原生回合准入只提供用户消息和项目身份。daemon 为各会话保存有界的临近消息窗口，
助手回复、工具结果和黑板状态不进入该窗口。项目改变时丢弃旧项目消息。
释放会话、缓存淘汰和 daemon 重启会丢弃上下文；显示设置使用独立的 daemon 内存生命周期。

最新请求提供主要词面信号。简短延续请求或与近期主题重叠的请求，可以利用最近的实质用户内容。
无关的新话题不继承旧主题的重叠信号。有界分词忽略纯数字词和长十六进制标识符。
原排名提供稳定先验与同分顺序。词面重叠只是弱排序信号，不是相关性标签或真实性证据。
没有词面重叠的语义匹配仍保留在候选页中，可以按需精确获取。

## 呈现与披露

自动 Recall 使用会话级 `compact` 或 `full` 显示模式。精简模式提供简短的正文预览，
日常默认使用 5 条经济档。共享准备 API 的 `economyLimit` 支持 3、5、10 条，
分别使用最多 1,000、1,500 和 2,500 个 UTF-16 单元的可用空间。
经济档保留记忆 ID、日期、状态标记和最多 160 个码点的正文预览。get 的结构化结果提供节点和记忆类型。
全文模式为每条已准入候选展示完整正文。两种模式都遮蔽已遗忘内容。

紧凑投影携带显示模式。共享候选准备在形成 InformationView 条目前按 Unicode 码点缩短精简预览，
保留引用 ID、图范围、时间标签和预览状态。经济档把相同的预览说明和图范围显示一次，
每条视图和收据仍保留各自的来源范围。共享上下文渲染器以 UTF-16 单元计算标签、外层标记、分隔符和省略提示，逐档加入完整候选条目。
经济档按候选排序装包。全文模式对超过 400 个 UTF-16 单元的长条目施加下限保护的长度密度排序
（$k=40, F=400, \alpha=0.5$），既保持短记录间的原始排名，也避免单条超长记录挤占多条简洁候选。
全文模式剩余预算为 2,500、4,000 和 6,000 单元时，分别最多准入 20、32 和 48 条。组合上下文先准入状态等优先级更高的视图，留给召回的
预算可能更少。候选与前置内容相同时，在这些固定档位间升档会保留已加入的条目及其来源标记。
两种模式输出的都是候选预览。精确记录与原始证据通过 get 及其收据路径获取。

Pi 在组合上下文中复用同一候选视图，OpenCode、DSH 和 WorkBuddy 使用共享自动 Recall 准备。
适配层不裁剪最终准备片段，也不将未展示候选计为送达。
界面历史召回与本轮可注入代际分离；缺少新结果不能成为重新注入旧快照的理由。

## 显式搜索与精确证据

显式搜索展示候选预览及有含义的非默认类型，省略节点名与默认记忆类型。
页面时间链集中展示事件时间，并通过本地标签关联候选。相同时间合并，
已知时间按先后排序，无法解析的时间保留原文字样单独列出。候选保留检索顺序及可读取的记忆引用。
来源正文和外部出处通过精确读取呈现。

get 文本展示完整正文、记忆 ID、节点名、范围、有含义的类型、原始事件时间及非默认可信度。
外部出处与选中记录不重复的完整来源正文一并展示。有逻辑链时显示其结构。
一次显式读取的记录范围相同时，只展示一次。get 的结构化结果保留默认值等底层元数据。
能单独组合的证据视图逐条携带范围和事件时间，并使用有界的主来源摘录。
Active Graph 按这种可组合视图估算 token。

本地普通检索默认最多 20 条，单条预览最多 240 个码点。候选按排序前缀装入 5,500 个 UTF-16
单元，剩余预算可容纳书签。显式请求超过 20 条时，字符预算按比例增加。Active Graph 用实际入选
的预览记录和标题开销记账。渐进检索和自动召回使用各自的准入规则。

普通混合检索可用末尾最多两个位置补充与查询词匹配的来源相邻回合。以最前两条直接命中为锚点，
候选沿用原查询的作用域、会话和时间过滤，其余直接命中保持排序。
[预算实验](../experiments/retrieval/explicit-search-budget-2026-11-21.zh-CN.md)记录了同预算对照。

### 浏览记忆临域

本地显式 search 的查询只含完整记忆 ID 时，可以浏览该记录的临域。使用展示的完整 `ref:`
短引用时，传入原来的 `activeGraphId`，并使用原会话与项目。结果给出邻居、它与锚点的关系和
可展开的引用。可用普通检索筛选和条数上限缩小范围。

引擎先在同一来源会话查相邻回合，再走指定跳数的图边。还有空位时，补同来源组和同节点的记录。
回合邻接依赖原始数字回合标识，候选受锚点作用域约束。经济档的预算用于初次召回页，Agent 可拿
可见引用发起独立的临域搜索。

## 会话控制与验证边界

`sessionActiveGraph action=recallDisplay` 读取模式，提供 `mode=compact|full` 时设置模式。
设置只影响指定会话；重启或显式释放会话后恢复默认精简模式。
近期上下文缓存淘汰不会重置显式选择的模式。普通显式搜索保留既有呈现，get 继续获取选定精确记录。

CLI 用法由[记忆操作参考](../../skills/nmg-memory/references/recall.zh-CN.md)维护。
初始数值与取舍见[决策](../decisions/implemented/2026-10-07-shared-information-output.zh-CN.md#临近上下文与显示模式)。
测试覆盖候选页保留、主题隔离、模式分离、遗忘遮蔽与共享服务接线，
不证明自然对话相关性收益或最终答题质量；后两者需要留出对话评测。

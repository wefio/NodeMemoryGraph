## 渐进检索

渐进检索构建并扩展 Active Graph；它与存储层级以及 STG/LTG 生命周期都是分开的：

1. **常驻层：** 一个极小的、与查询无关的种子，由关键约束与稳定画像信息组成，被放入每个相关 AG。
2. **自动召回层：** 基于当前查询、任务、作用域、时间与可用预算，从 STG 与 LTG 做有界动态选择。宿主侧的记忆门首先选择 `retrieve`、`cue` 或 `none`；`none` 必须不检索也不注入动态长期记忆。因此普通代码检查、测试、计算、格式化以及其他自足 turn 保持无记忆。显式中文时间召回线索同时包含 `之前` 与 `先前`；等价的过去状态问题使用同一次检索决策。中文回忆问句还包括带疑问标记的 `你记得` / `您记得`，以及 `来着？` 疑问形式；单纯提醒或 `用来着色` 一类说法不算回忆请求。该门可以保留有界的任务锚点，使简短的续接能够召回紧邻的前一个任务，而不会把每个实质性 prompt 都当作历史查询。
3. **Agent 主导召回层：** 紧凑的 header／线索，使模型可以调用 `nmg_search`、查看成本，并通过 `nmg_get` 用精确细节扩展 AG。

入口词表是数据而不是代码。每条词条声明自己的词组、它选择 `retrieve` 还是 `cue`，以及可选的意图边界——间隔内前置或后随的词、句内作用域、查询开头或后接名字——因此新增或退役触发词只需编辑 `src/core/recall-vocabulary.ts`，不必写正则表达式。两者都命中时 `retrieve` 词条优先于 `cue` 词条，而学到的词组始终以 `cue` 进入，不能降级明确的回忆提问。没有 Lab 租约时，判定对该词表保持无状态。

实验性 `recall_gate` 能力是默认关闭、按会话租用的自动召回层试点。它保存助手提出的意图提词，而不是记忆、相关性判断或 claim 结果；主模型的补充检索可以携带当前输入中的字面提词。准入要求本来会被跳过的一条记录，以及当前 session/project 代际与提案围栏。原生 Pi 在模型参数之外捕获该观察，显式客户端提供准备修订号。无效、过期或已禁用的提案不会让普通检索失败或改变它，被消费的围栏也不证明意图或检索成功。只有本来会被跳过的查询才复用一个提词：静态与任务锚点召回优先，命中后仍走普通 `cue` 决策，并受宿主配置、检索过滤与输出预算约束。置信常数仍是启发式，不是标定概率。

服务最多持有 32 个会话条目。每个会话拥有一个由词表播种的词池，上限 128 条，其中最多 64 条处于受保护段。学到的词组竞争同一容量，因此没有独立提词缓存，也没有种子豁免。保留是由原始用户输入驱动的分段 LRU：在不同用户回合命中算一次使用，第二个不同回合把该词晋级，同一回合内的重复命中不再计次。受保护段溢出时降级最久未用的受保护词；容量压力下淘汰最久未用的非受保护词。自动召回、注入内容、回答与工具输出都不更新新旧顺序。词组为 3–80 个 UTF-16 单元，理由最多 240，来源摘录最多 320，查询捕获／匹配最多 4,096。共享的高置信秘密边界拒绝携带秘密的查询捕获与理由；它不是通用隐私分类器。租约生效时以会话词池为准，`none` 亦然：被淘汰或被移除的词不会从磁盘回填，匹配既不延长租约，也不跨项目变更存续；remove/clear、禁用、租约到期或续租、会话释放与 daemon 替换都会阻止复用。不定义跨会话或永久晋级。按需读取的事件环每个会话最多保留 16 条准入／移除／淘汰事件，所以"重新出现"只表示某次退役仍在该环内，不是经独立验证的需求或完整重学历史。[召回提词决策](../../decisions/implemented/2026-10-15-session-recall-cues.zh-CN.md)与[统一词表决策](../../decisions/implemented/2026-10-20-unified-recall-vocabulary.zh-CN.md)拥有这些协议。

自动召回与 Agent 主导召回共享同一批已索引记录。显式召回触发可以改善任一层中的候选提名，但它们不绕过记忆门、Active Graph 预算、QPP 折叠、作用域或真值过滤，也不绕过「在依赖某个细节之前必须加载精确证据」这一要求。

第三层还作为一个工具过程被额外设界，而不仅仅是对返回信息设界。重复的候选集合计入无进展，一次精确 `get` 只有加载了此前未见证据时才解锁进一步 search，而每 turn 的硬性 search／工具上限即使 QPP 持续建议扩展也会终止循环。因此渐进披露同时统治内容量与披露动作的数量。

候选生成应当组合彼此独立的信号：

```text
Inbox/Delta + surface anchors + fine-grained record semantics
  -> word-level FTS only as a zero-configuration/degraded fallback
  -> optional node/leaf semantic routing at measured large scale
  -> optional graph expansion
  -> scope/time/truth filtering
  -> type-aware reranking and diversity
  -> bounded Active Graph projection
  -> compact headers and selected exact evidence
```

实现让这些阶段保持可检视，而不是把 `searchContext` 当作一个排序公式：AG 硬预算选择、主候选排序、活动图投影选择与重复标记都是纯函数。存储读取与可选图／语义扩展仍是编排步骤。自动微分仍是受支持的控制器机制，因为它是一层小的、已实现的 DAG 原生长计算层；它不是普通检索的强制运行时依赖。

检索信号按用途分离：

- 语义／向量检索用于含义；
- 无内容的 trigram surface-anchor 检索用于显式引号短语、路径、版本、ID、错误码、类代码标识符与已配置的召回触发；NFKC 归一化保留等价表面形式，同时标点仍可被检索；
- 结构化过滤用于日期与作用域；
- 词级 FTS5 作为零配置或降级兜底，而不是语义检索的替代，也不是英文 benchmark 策略；
- 正则表达式仅作为在有界候选集合或原始会话子集之上的高级／调试兜底。

结构化 scope 的合取与含端点的 event-time 边界，在评分及 limit 之前约束 SQL 候选池；缺少 event time 的记录不满足已提供的时间边界。hybrid lexical priority 也不豁免这些过滤；重复 `ORDER BY` 记忆 ID 按 SQL 占位符顺序绑定在全部 `WHERE` 值之后、`LIMIT` 之前。强制候选与无 FTS 命中的向量兜底使用同一过滤契约。

仅 FTS5 路径在直接结果上限与 Active Graph 预算选出证据之前，对 `combinedScore` 完全相同的相邻候选，按 statement 与前 500 个证据字符中的查询词 IDF 加权覆盖率排序。该规则不改变候选成员、QPP 扩展或 hybrid 检索；非并列顺序与分数保持原样，但已选前缀与 QPP 观察可能变化，因为预算看到的是已解并列的顺序。开放附件保留其预留位置，语义检索与强制 surface-anchor 补充不使用该规则。作用域、评测与被否决的神经排序臂见[词法并列排序](../../decisions/implemented/2026-09-30-lexical-tie-ranking.zh-CN.md)。

任意模型生成的正则不是相关性排序器，默认不得扫描整个 store。Surface anchor 在共享 AG 预算与投影之前、与语义候选一起被准入。纯散文不会仅因词重叠而产生 surface anchor，从而防止一个英文 benchmark 重新定义产品排序。任意字面扫描仍被禁止，因为 trigram 索引提供了有界精确路径，且没有正则转义或灾难性回溯风险。

离线学习相关性使用 [relevance-training.md](../relevance-training.md) 中的来源与评测边界。其产物仍是候选；跨语料测量不授予运行时准入。

### 时间证据展示

[历史时间、写入时间与有效期](core-data-model.zh-CN.md#核心数据模型)保持分离。共享 Agent Surface 在精简检索与精确证据元数据中保留 `eventTime`，本地 OmniMemEval 桥使用同一界面。纯文本协议可以在选出结果后调用 [`renderTemporalEvidence`](../../../src/integration/temporal-evidence.ts)：识别到时间查询时，为每条具有有效时间的记录加标签；否则只为含已识别相对时间表达的记录加标签。未知或无效时间不产生标签，已有时间戳前缀不重复添加。ISO 日期和时间戳保留完整精度与原始时区偏移，不截断为日历日期。

中英文识别模式只有一份[产品层策略](../../../src/integration/temporal-evidence-policy.json)，由 TypeScript 渲染器消费，并由 Python 适配器安装器复制。这是确定性的展示启发式，不是完整时间推理或召回门；它不读取数据集类别或金标答案，不改变存储文本、embedding、候选成员、分数、排序或预算。结构化元数据不因是否展示标签而丢失。协议字段别名属于 [AML 边界](../../../evals/omnimemeval/README.zh-CN.md#集成边界)，不属于存储层。[决策记录](../../decisions/implemented/2026-10-22-shared-temporal-evidence.zh-CN.md)说明复用与兼容性的理由。

### 查询构造与路由融合边界

NMG 接受一个主查询加上可选的调用方生成的 `queries[]`。调用方可以通过查询分解、替换措辞、领域知识或假设答案（HyDE）产生这些子句。因此 HyDE 不是 NMG 的子系统：由 Agent 或另一种面向 LLM 的宿主方法来生成假设文本，NMG 只检索所提供的子句。

检索边界拥有稳定 ID 去重、主查询优先与共享记录／token 预算。已验证的 Lite 路径当前把去重后的次查询结果追加在主排序之后。加权倒数排名融合作为一个确定性 Lab 原语可用，反向检索仍是离线候选生成探针。在一次共享的有界实现与匹配的产品测试显示其收益超出单一 benchmark 分布之前，二者都不改变 Lite 默认值。

Benchmark 自有的答案与 judge prompt 仍是上游协议。它们可以原样使用以保持可比性，但它们不定义 NMG 的查询生成、排序或产品 prompt 策略。

### QPP 执行与渐进披露

QPP 是同一 Active Graph 检索路径之上的可选控制平面，而不是独立存储或检索引擎。它的三个动作可以独立配置，因为它们的成本与失败模式不同：

1. **QPP1** 预测首个候选池应有多宽。它可以只观察不动作，或分配一个有界的初始 Fibonacci 层级。
2. **QPP2** 只在候选池内部运作。它可以继续渐进检视，并决定哪些 header 单独可见、哪些被折叠。
3. **检索建议**把不充分的自动召回转换为给模型的建议信号。它自身从不调用工具。

NMG 的责任止于产生可审计分数并测量各模块的质量与成本。是否激活某个模块、组合哪些模块，属于运营者策略而非 NMG 的学习决策。项目不需要优化或背书某种组合式配置。

QPP2 执行的是渐进披露而不是删除。让控制器产生 listwise 必要性分数 `s_i`；把它们转换为相对几率与归一化局部质量：

```text
o_i = clamp(s_i) / (1 - clamp(s_i))
p_i = o_i / sum_j(o_j)
```

可见目录是按分数排序的、其累计局部质量达到配置保留目标（当前由 `NMG_QPP2_RETAINED_MASS` 配置，默认值为 `0.98`；见 [Pi QPP 控制](../../../README.zh-CN.md#无头-pi-控制)）的最小集合。Retrieval Top-1 是唯一固定的安全锚点。因此平坦分布保持宽，而陡峭分布折叠更多候选。被折叠的候选仍留在 Active Graph 与检索 trace 中，并且必须保持可显式展开。

该质量是查询局部的相对分配，不是「某条记录必要」的校准绝对概率。因此 QPP2 仍为可选启用，直到匹配测试显示模型能在不丢失答案证据的情况下使用被折叠目录。具体的 Pi 设置、默认值、兼容变量与运营者说明属于 README，而不属于这份架构契约。

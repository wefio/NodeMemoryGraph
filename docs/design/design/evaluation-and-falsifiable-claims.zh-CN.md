## 评测与可证伪的主张

NMG 必须在相同的基础模型、提示词、历史与预算下、按以下对照来评测：

1. 无长期记忆；
2. 带 FTS/精确检索的原始会话搜索；
3. 扁平 FTS + 向量混合检索；
4. NMG Lite 渐进披露；
5. 带自适应节点、关系与可选学习型路由的 NMG Graph。

核心假设：

- **分层编码：** 节点/叶子头部在不降低证据召回的前提下减少 token 或延迟。
- **自适应粒度：** 实测的细化降低语义路由错误。
- **关系性旁信息：** 图扩展改善时序、作用域、冲突或多跳问题，足以支付其成本。
- **学习：** 学习型路由相对余弦、词法与简单混合对照改善召回/成本。
- **主动投影：** 显式的受预算约束的 AG 相对普通 Top-K 上下文注入，改善每 token 的证据覆盖。
- **巩固：** 以稳定性为闸门的结构提升，在不增加错误关系或过期记忆错误的前提下改善未来多跳检索。

如果 Lite 没有击败扁平混合对照，其层级就未展示产品价值。如果 Graph 没有击败 Lite，图自适应仍属 Lab 特性。如果学习型路由没有击败确定性路由，它保持可选。

开发证据快照（更新于 2026-08-24）：

- 953 个自动化测试覆盖 UOp 自动微分、可微控制器、分层激活、保留的记忆图推理器原型、推理工作区持久化与检查点注入、P3 生命周期、预算执行、披露/已核验证据分离、独立任务去重、可逆巩固、写策略审计、Active Graph 轨迹、官方 benchmark 适配器与 schema 迁移。测试文件位于 `tests/core/`、`tests/evals/` 与 `tests/extensions/nmg/`。
- 一个干净的 DeepSeek V4 Flash Pi 进程写入了唯一的 LTG 事实，第二个进程通过 `nmg_search -> activeGraphId -> nmg_get` 恢复它，store 记录了一次选择与一次精确披露；隔离测试数据随后被删除，`PRAGMA foreign_key_check` 保持干净；
- 严格的三种臂 LongMemEval 开发闸门，覆盖七个类别各一道固定问题，用钉住的官方协议分别打分：无记忆 1/7、确定性 NMG 2/7、带非排序影子日志的同一确定性 NMG 3/7。未启用任何外部 embedding provider。确定性检索在 2/7 的情况下足够，且两个答案都正确；全部五次检索未命中都是错误答案。影子决策无法影响排序。现有记录无法解释观察到的 2/7 与 3/7 分数差异；其原因可能包括模型/裁判或其他运行变化，不能据此确立影子日志的效果；
- 历史闸门前 LongMemEval 诊断，七个类别各一道固定用例：无记忆 1/7、原始会话 1/7、扁平混合 5/7、Lite 5/7、Graph 6/7；
- 历史闸门前 LongMemEval 诊断，七个类别各两道固定用例：无记忆 2/14、原始会话 4/14、扁平混合 8/14、Lite 10/14、Graph 9/14；
- 受控的 30 用例拓扑消融：扁平 0%、固定无连接图 0%、被接受的、有证据支撑的连接按构造成立 100% 召回；
- 受控的带标签路由：启发式 0%、在线路由在三次显式有用节点标签之后按构造成立 100%；
- 10K 近重复层级负载：节点+叶子精确扫描 100% 准确率、10.6 ms P50，叶子 ANN 87.5%、8.1 ms P50，完整记录扫描 75%、779 ms P50。
- 使用本地 `BAAI/bge-small-en-v1.5` 的完整 1,540 题 LoCoMo K=20 检索消融：FTS5 精确证据召回 45.1%、节点/叶子摘要 18.0%、记录向量 52.9%、节点/叶子+记录并集 17.7%。记录向量还使平均延迟与上下文大小接近词法基线。这否决了把压缩层级作为唯一证据索引，也否决了当前的并集排序器；节点/叶子路由仍是目录/规模优化，不能替代细粒度证据候选。本文报告的 1,540 题总数与 [LoCoMo relevance-gate 报告](../../experiments/retrieval-quality/relevance-gate-calibration-2026-09-09.md)中的 1,532 道计分题分母尚未对账；本文不能确立这两个分母指的是同一计分集合。
- 完整 20 段对话、400 题 BEAM 100K K=20 检索消融：FTS5 精确带标签证据召回为 26.2%，BGE 记录向量达到 32.9%，返回文本略少。增量写入时索引保持 32.8% 召回，同时把平均首查询延迟从 2,102 降到 193 ms，把 add-plus-search 总时间从 73.0 降到 68.9 秒。共享全参与者排序与固定参与者配额被否决，因为它们增加了上下文与延迟而没有改善召回。
- 同一 20 段对话与 400 题上的完整 OmniMemEval BEAM 100K 回答与裁判运行：使用 BGE 记录向量的 NMG、K=20、QPP2 关闭、DeepSeek V4 Flash 同时作为 reader 与 judge，得分 `0.6422 ± 0.3974`。搜索延迟为 40.9 ms P50 与 185.1 ms P95；全部 400 条搜索、回答与裁判记录完成且未被跳过。使用相同问题、提示词、reader 与 judge 的匹配空检索上下文对照得分 `0.2724 ± 0.4086`；配对增益为 `+0.3698`（20,000 次抽样的描述性配对 bootstrap 95% 区间 `[+0.3205, +0.4183]`；251 胜、123 平、26 负）。弃答回退 `-0.3875`，因此这是数据集特定效用的证据，不是笼统的安全性主张或泛化主张。完整参数、逐维度分数、记账注意事项、计时与 runner 校正在 [BEAM 100K 评测报告](../../experiments/benchmarks/beam-100k-evaluation-2026-08-13.zh-CN.md) 中记录。
- 推理工作区开发 benchmark，三个任务、每个条件三次重复，使用 DeepSeek V4 Flash：全上下文基线与工作区都达到 100% 精确任务成功，而平均延迟从 5.79 s 升到 15.15 s；在普通 Pi 压缩之后，基线达到 88.9%、工作区 100%，而延迟从 9.83 s 升到 23.41 s。九次压缩后工作区试验中有一次留存了一个不受支持的假设标记。
  拓扑与路由用例只隔离这些机制能否学习并应用一个缺失的关系；它们不是自然分布上的质量估计。
  规模结果说明为什么叶子粒度重要，以及为什么当前 ANN 配置还不能替代本地精确扫描。

14 题配对结果对产品闸门而言比受控拓扑结果更重要：Lite 独胜五题而扁平胜三题，Graph 独胜一题而 Lite 胜两题。样本仍太小，不足以支撑能力主张，并且它明确把图扩展保留在 Lab。

追踪证据 Recall@K、过期记忆错误、错误作用域错误、假记忆注入、答案准确率、无关任务回退、注入 token、最深层级、索引/维护成本，以及包含查询 embedding 的端到端 P50/P95 延迟。对 STG/LTG/AG 实验还要追踪 STG 驻留时间、原子提升延迟、关系精确率、假巩固率、已巩固子图复用、AG 节点/边/证据计数、预算利用率、扩展步数，以及每增加一个 token 的边际证据增益。

## 修订后的实现顺序

### P0：让记忆插件小而且真实

1. 增加 Pi 包清单与稳定可安装的扩展入口。
2. 把面向模型的默认 API 收敛为 search、get 与 remember。
3. 保留 SQLite surface-anchor 检索与词级 FTS 作为零配置/降级路径。
4. **在 benchmark 与 Pi 边界上完成：** 把可选的细粒度记录 embedding 接在同一 SQLite 存储之后，只在 add/turn 边界同步缺失的记录，并保留 surface anchors 与 FTS 作为零配置与尚未就绪时的回退。纯节点/叶子方案与当前的并集排序器在 LoCoMo 消融之后被显式闸门关闭。
5. **完成：** 通过与 agent 无关的 `nmg` CLI 与跨平台 JSON-RPC-over-HTTP daemon 暴露应用边界。本文计划中的 `nmg.v7` 标签是历史版本；当前协议版本为 `nmg.v9`。Pi 扩展通过持久 HTTP 客户端与感知归属的生命周期使用同一个 daemon。

### P1：增量正确性与公平评测

1. **完成：** Inbox/Delta 检索与脏节点局部重建调度。
2. **完成：** 稳定的叶子身份、Float32 二进制向量存储，以及可丢弃的连续可追加内存缓存。
3. **在因果 runner 层面完成：** 严格的 LongMemEval 匹配闸门比较无记忆、确定性 NMG、以及带一个显式冻结训练控制器的 NMG，使用完全相同的提示词与同一 seed 语料的独立副本。运行时动作、候选哈希/配置与污染被审计。更大的重复能力运行仍属进行中的 benchmark 工作。
4. **完成：** 确定性的时序、聚合、冲突、多跳、精确细节、隐私与记忆污染用例。
5. **在适配器层面完成：** LongMemEval、PersonaMem、LoCoMo 与 BEAM 具备官方格式加载器、分层验证、共享匹配实验臂、被忽略的本地数据/结果，以及 fixture 覆盖。更大的重复能力运行仍属 benchmark 工作，而非实现工作。

### P2：自适应语义图实验

1. **完成：** 记录歧义、回退、矛盾、有用性与共检索信号。
2. **完成：** 带证据、阈值、冷却滞后与显式评审的延迟连接与作用域细化提案。
3. **作为受控机制消融完成：** 在 30 个确定性用例上比较自适应拓扑与固定节点及扁平检索。
4. **作为受控标签测试完成：** 与框架无关的在线路由只依据显式的有用节点标签更新。

### P3：运行时记忆模型与巩固

1. **完成：** 增加显式的 STG/LTG 生命周期状态、保留来源的提升、过期与降级；对受治理的事实、偏好、约束与可替换状态保留即时原子 LTG 提升。
2. **目标已被取代，机制可复用部分已完成：** 当前查询作用域的 `ActiveGraph` 提供选中节点、关系、局部证据、临时跨图边与统一预算账本。复用这些机制，同时把其 trace 形状的身份替换为可变的会话 AG 加不可变 `ProjectionRevision`。
3. **未完成的破坏性运行时工作：** 实现会话/分支归属、有界任务帧、工具观察摄入、披露账本、类型化语义/激活/推理层、确定性清理，以及 `agId`/`taskFrameId`/`projectionId`/`boardChannelId` 身份拆分。
4. **未完成的集成工作：** 把 HA 快速状态绑定到会话 AG，并让显式启用的 MGR 只消费有界选中的子图。两者都保持可选并服从确定性的硬预算与受治理的持久化。
5. **以保守归因完成：** 从检索轨迹与 agent 主导的精确记忆使用记录带分数的节点与边激活，附持久的选择理由、扩展路径与预算记账；仅凭检索频率不能确立有用性。
6. **完成：** 从独立任务、证据覆盖、已核验有用性、矛盾与时间衰减估计边稳定性，同时防止自我强化的检索回路。
7. **对成对局部子图完成：** 把带最少证据、滞后、冷却与显式评测闸门的、可审计可逆的局部子图巩固加入 LTG。Pi 在完成的轮次之后自动运行这一保守维护策略。
8. **自动微分与有界驱动作为 Lite 基础设施完成；提升另行闸门控制：** 实现 tinygrad 启发的 UOp 引擎，以及用于节点、边、STOP/EXPAND 与预算决策的可序列化多头控制器。数值底座随 Lite 发布；训练好的 rerank/allocation/fold 驱动被接在显式模式之后，而默认启用仍以固定特征契约与匹配的证据召回/成本评测为闸门。
9. **机制完成，效用评测未完成：** 可独立选择的 QPP1 分配、QPP2 渐进折叠与搜索建议已通过 Pi 适配器接线。QPP2 在当前查询作用域投影中保留被折叠的候选；目标是把它们存进投影修订。标定与匹配的答案质量/成本评测尚未完成；启用与组合仍属用户/操作员策略。

### P4：选择性推理工作区

1. **作为 Lab 原型完成：** 类型化会话推理节点与边、原子本地持久化、有界检查点、Pi 压缩生命周期集成，以及一个匹配的全量/压缩后开发 benchmark。
2. **实验后否决：** 自动捕获用户输入与普通轮次的检查点注入。它增加了延迟并回退了压缩后任务的准确率。不要在没有新 benchmark 与实质性不同设计的情况下恢复它。
3. **在结构来源边界上完成：** 证据节点要求稳定引用；被支持的结论/决策要求直接或传递锚定的支持；环不能制造证据；移除引用不能使被支持的后代成为孤儿；检查点显式标记不受支持的假设。外部来源真值仍属 harness/工具的责任。
4. **对有界 Lab 生命周期完成：** 精确的 add 重试幂等，显式 `clear` 只重置所属会话，进程重启恢复该会话，30 天闲置 TTL 删除废弃的草稿文件。逐节点的过期退役通过显式状态与检查点优先级表达。任务完成归档、跨会话恢复与提升被有意留空，而不是作为隐式默认。
5. 继续在具有真实中断或压缩风险的任务上度量该显式工作区；不要把合成成功当作默认启用的理由。
6. 只有到那时才定义对受支持结论与决策的、经评审的 STG/LTG 提升。

### P5：可选平台能力

1. 在考虑自动物理清除之前，度量从已索引冷存储进入已实现的 L4 Dormant/Unindexed 与 L5 Quarantine 状态的留存转换。CLI 通过常驻服务暴露 dry-run 候选与显式 archive/quarantine/restore 操作。
2. CLI 暴露带依赖索引清理的语义记忆删除，同时保留不可变来源历史。完整隐私擦除/导出（包括原始历史与学习信号擦除）仍是独立工作。
3. 只有在本地协议与多设备冲突语义被规定之后，才增加可选的加密云同步。

### 立即验证顺序

接下来的工作应降低不确定性，而不是再加一个子系统：

1. 针对同一固定基线分别评测 QPP1、QPP2 与搜索建议。报告每个模块的分数变化、证据召回、工具调用数、注入 token 与端到端延迟。不要把穷举的模块组合变成项目要求。
2. 以 oracle 证据深度标定 QPP1，以证据保留标定 QPP2。不要仅仅因为更大的池提高了原始召回就称某模块有用。
3. 测试模型在有用时是否遵循一条搜索建议、在不需要时是否忽略它、以及在一次无产出的搜索之后是否停止。
4. **机制完成；证据收集未完成：** claim 结果后验、来源谱系、语义任务去重、保守界与可逆 STG 物化已存在。在标定或启用无人值守巩固之前，先积累独立的自然已核验证据结果。
5. **完成：** 用可安装的 Pi 包清单、经校验的 Pi 会话入口 schema、显式的 daemon 并发契约与面向用户的 delete/export 加固插件边界。
6. 把启用与模块组合留给显式的用户/操作员策略。
7. 让 ANN、无人值守的拓扑变更、云同步与自动推理工作区启用保持推迟，直到其被度量的前提出现。

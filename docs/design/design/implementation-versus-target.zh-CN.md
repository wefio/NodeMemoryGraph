## 当前实现与目标之差

会话 Active Graph 决策有意把当前的查询作用域图与现有 Pi 运行时都视为迁移**输入**，而不是最终架构。下面的清单记录今天已存在的东西；不得把它读成"可变会话 AG、任务帧、投影身份拆分或 HA/MGR 运行时回路已经实现"的证据。

在当前原型中已实现并验证：

- 常规 Pi 包清单、稳定的扩展入口、三个持久记忆工具加上 Lab 能力入口与统一的 `nmg_state` 工具；
- 渐进式 `nmg_search` headers 之后用精确的 `nmg_get` 加载证据；
- 一条持久的 Inbox/Delta 路径：跨重启存活、在压缩之前参与层级检索，并且只在外部的叶子 embedding 完成之后才被确认；
- 脏节点阈值调度与节点内叶子重建，使用稳定的、由内容派生的块 ID，从而保留未变化 embedding 的缓存条目；
- Float32 BLOB 持久化，带向后兼容的 JSON 迁移，以及可丢弃的连续向量缓存，支持几何式追加/更新；
- 本地 SQLite 选择性历史证据、语义记忆、类型化关系、证据链接与来源消息身份；
- 状态取代、事件时间、行动者/真值状态、作用域、合并/拆分与重定向；
- 基于可复用记录 ID 的静态时序/逻辑记忆链，带重检索之后的有界扩展、活的后继指针、无环顺序边、完整的 daemon/CLI 管理、会话自有 STG 隔离、精确 get 水合，以及被 Pi、Claude MCP 与 CLI 搜索元数据消费的共享面向 agent 的逻辑 DAG 投影（不重复 statement）；
- 常驻/自动/cue 执行层；
- 一个仅 Lab、基于文件的会话推理工作区，带有界压缩检查点与显式的假设/证据状态；
- 一个任务作用域的共享协调看板，带归因条目、TTL、游标读取、显式 resolve、始终可用的 CLI/RPC 访问、可选适配器访问、系统层在线 agent 注册表、能力发现与稳定名称定向投递，且不进入 LTG/FTS 索引；
- 一个有界的 `searchContext` 结果，通过组合常驻召回、自动召回与 agent 主导召回，近似早期的 Active Graph；
- memory 与节点上显式的 STG/LTG 驻留、受治理的即时原子 LTG 写入、保留 ID 的提升/降级、STG 过期，以及只追加的生命周期审计事件；
- 一个由 `searchContext` 返回的一等查询作用域 `ActiveGraph`，带持久与临时边，以及共享的节点/边/证据/token/跳数/层级/延迟预算与逐维度实测使用账本；
- 持久的逐 memory 选择解释、分数组成、估计 token 成本与关系扩展路径，全部可从一条检索轨迹中恢复；
- Pi 把当前 Active Graph/trace ID 从 `nmg_search` 传播到 `nmg_get`，使精确扩展成为"某条被召回的 memory 确实被选中使用"的当前运行信号；
- 按查询/任务去重的边观察、分离的选择/使用/矛盾/拒绝激活统计、时间衰减的边稳定性，以及防止仅凭检索就提高稳定性；
- 可审计的稳定性驱动关系巩固与滞后降级，显式关系受保护、不被自动降级；
- Pi harness 中的自动轮末维护：STG 过期、到期节点批量重平衡，以及保守的稳定性驱动巩固/降级；
- 被接受与被拒绝的写策略审计事件，包含持久写理由与来源，同时有意排除被拒绝的 statement/证据内容；
- FTS5、哈希评测向量、带显式查询/文档 profile 的模型中立外部 embedding、节点/叶子索引，以及可重建的 USearch 实验；
- L0-L3 本地层级、累积访问统计与批量重平衡；
- 仅 LTG 的 L4 Dormant/Unindexed 与 L5 Quarantine 生命周期状态、显式恢复与保守的 dry-run 留存报告（不含自动物理清除）；
- 持久化的歧义、回退、矛盾、有用性与节点对共检索遥测；
- 带观察阈值、增益阈值、冷却滞后、持久评审状态与显式 accept/reject 应用的延迟证据支撑连接/拆分提案；
- 可独立选择的 QPP1 分配、QPP2 渐进局部折叠与面向模型的搜索建议，被折叠的候选保留在 Active Graph 中而不是丢弃；
- Pi RPC 回归测试、初步的 LongMemEval 开发运行与规模实验。
- 类型检查、ESLint、Prettier 校验、Node 测试执行与 C8 覆盖率的本地质量自动化，以及与之匹配的 GitHub Actions 工作流。

原型与目标插件之间的重要缺口：

- 推理工作区是已实现的 Opt-in Lab 能力，但不是 Lite 默认功能，也没有学习型自动激活闸门。这是明确的产品边界：除非启用 Lab 模式，否则该工具不存在；由模型决定是否写入；NMG 只在 Pi 压缩之后注入一次；
- 推理节点区分类型、生命周期状态与结构支持。证据节点要求稳定引用；被支持的节点要求直接或传递锚定的支持；不受支持的假设在每次检查点都被标记，且不能进入巩固。引用的存在性/真值仍由调用方负责，而不是独立核验的主张；
- 推理检查点是有界的、会话持久的，并可在同一 Pi 会话内恢复，但草稿过期、归档策略、跨会话任务延续与显式提升到 STG/LTG 仍未被设计或仍是手工操作；
- 工作区在核心代码中暴露巩固候选，但 Pi 不会自动评审或提升它们；在来源与假提升评测更强之前，这是有意的；
- `MemoryGraphReasoner` 仍是数值 Lab 原型，它对全局未访问候选集打分，而不是沿图边走；
- QPP1、QPP2 与搜索建议在 Pi 边界被独立接线。QPP1 的 `active` 执行一次不持久的规划探针，并且只在可归因的控制器训练之后应用学习得到的硬有界 AG 预算；QPP2 的 `active` 启用 Fibonacci 扩展，并可能折叠学习得到的低质量尾部而不从其 AG 中移除这些 ID；显式的调用方限制会关闭该折叠。搜索建议仍是一条尾随的、可选的模型轻推。它们的效用与成本尚未被充分刻画。在完整的 LoCoMo 审计中，QPP1 的预算预测与 oracle Fibonacci 层级相关性很差；QPP2 的分数是 listwise 的而不是绝对标定的；而让模型再次搜索的成本/收益尚未被度量。Active 行为仍是显式的操作员选择，而不是由 NMG 选出的默认；
- QPP2 的折叠在 store/Active-Graph 层是无损的，但对模型不一定无损：一个需要的候选可能保持折叠，除非模型显式展开目录。匹配的端到端测试必须度量答案质量、证据使用、额外工具调用、token 与延迟。激活闸门现在已有针对这些成对产品测量的类型化输入与失败即关闭检查，但当前没有自然运行提供那两个匹配臂，因此这属于评测工作，而不是启用的授权；
- [后验置信回路](core-data-model.md#confidence-as-a-posterior-the-outcome-feedback-loop)现在已有影子模式的存储与 RPC 路径：不可变的抽取置信度播种一个弱 Beta 先验，可归因的 supported/contradicted 事件按语义任务去重，store 暴露后验均值外加一个保守下界。它不改变抽取置信度或检索排序。可信任务结果的自动收集与真实使用标定仍未完成；
- ANN 实验在近重复负载上的召回不可接受；
- 自动抽取评测与匹配的全历史样本还不够大，无法作出产品级质量主张；
- 四个官方 benchmark 适配器会校验并使用官方格式解析。一次完整的匹配 BEAM 100K 运行现在确立了相对空检索上下文的数据集特定能力增益，但一般能力主张仍需重复运行与跨套件证据；
- HaluMem 操作级适配器现在用官方裁判度量抽取记录、干扰拒绝与更新检索。其首个自然切片暴露了原始消息入口污染（干扰拒绝 0/1，全候选加权准确率 0.683）。在同一切片上，一个执行当前持久写策略的 Agent 拒绝了该干扰，产出 12 个而不是 30 个候选，达到 1.0 候选准确率与 4/4 更新，但只保留了 1/2 普通 gold 点。这支持把语义准入留在 harness 中，同时要求召回审计。第二个匹配切片把 52 轮缩减为 8 个准确候选，保留 7/8 普通 gold 点，并更新 1/1 目标。其 benchmark 干扰汇总还说明了为什么闸门必须检查可归因的逐记录结果：官方裁判可能接受一条带标签的干扰推断，即使被注入的措辞从未被存储。随后一次真实 STG 后验审计从会话 5–6 准入 17 个可归因候选并观察会话 7–11，但没有找到之后的精确独立确认，因此合格数为零。第二个会话 1–2 / 观察 3–11 的窗口同样合格数为零。这表明 HaluMem 既缺乏产品式的结果标签，也说明一些抽取记录仍然过于复合；它不授权放宽后验闸门或启用无人值守巩固；
- 被接受的拓扑提案是离线/Lab 维护操作，不是无人值守的生产变更策略；
- Pi/CLI 的逻辑撤回与带版本的用户记忆导出已经存在；对每一份来源副本与学习聚合的物理隐私擦除仍是被闸门约束的未来工作；
- 自动召回暴露被记录为"选择"，Pi 在 `agent_end` 执行一次偏向精确率的答案到证据归因。匹配与空重叠观察只属诊断：它们既不训练影子控制器，也不改变稳定性。精确 `get` 记录的是披露，不是使用。稳定性与证据排序监督需要显式用户结果、工具验证或官方 benchmark 证据；
- 稳定性目前把成对局部子图巩固为一条类型化 `related_to` 关系。更大的多边模体巩固仍是实验，而不是 P3 要求。
- 可选的加密同步与多设备冲突处理仅有设计；Cloudflare 不是运行时依赖。

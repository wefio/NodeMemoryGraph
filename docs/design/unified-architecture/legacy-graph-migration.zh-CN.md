## 行为与格式对照

旧实现通过 `NmgService` 调用 `NmgStore` 及其写入、检索、图与维护 mixin。统一路径由 `MemoryEngine` 通过 `MemoryBackend` 使用 SQLite 或 LanceDB。

| 职责 | 既有路径 | 统一引擎与剩余差异 |
| --- | --- | --- |
| 写入准入与默认值 | 服务执行准入，登记拒绝和显式绕过，补齐真实性默认值。Store 规范化标记并推导临时驻留。 | 共用准入、标记和默认驻留规则。接受事件与记忆一起提交，拒绝事件只存元数据。SQLite 完整快照导入原审计记录。 |
| 证据 | History 表按会话和来源消息去重，记忆有主证据和附加关联。 | 保留引用的证据 ID，新写入按会话和来源消息复用证据，发现内容或角色冲突时拒绝写入。 |
| 去重与状态 | 按范围做 SQL 精确去重和近期规范化匹配，支持可选裁决、近似建议、状态键别名和替换。 | 规范化精确去重、按范围替换、更新证据角色、应用迁入的别名。别名推断、候选策略和时间边界仍有差异。 |

| 检索 | SQLite 查询和索引提供候选，支持范围／来源角色和时间过滤、向量／FTS、会话 AG 和历史。 | 词法、向量和 hybrid 检索、精确读取、事件时间窗和项目自动召回。沿替换链排序和旧链扩展启发式仍有差异。 |

## 图数据演练

用当前旧版 SQLite 文件的可丢弃副本，调用 `src/core/store/legacy-memory-snapshot.ts` 的 `readLegacyMemorySnapshot(path)`。它在只读事务中读取一致快照，无需升级数据表。把返回的实体交给 `src/core/memory/graph-import.ts` 的 `importMemoryGraph(backend, entities)`，目标可选 SQLite 或 LanceDB 的空命名空间。使用 SQLite 时，演练可以沿用含源数据和 Task Board 的副本文件。

演练在一次提交中原子发布，最多 512 个实体。它保留 ID、节点和边字段、主证据和附加证据、时间字段、状态、替换链以及图内引用。遇到悬空引用、跨会话的私有证据或记忆引用、休眠／隔离记录、节点重定向或已使用的目标，会拒绝导入。重试同一快照返回已有凭据。演练只处理可信的领域数据，协作表和附属表留在源端。

[迁移契约测试](../../../tests/core/legacy-memory-migration.test.ts)在两个后端读回实体，验证当前状态与会话可见性、沿原有边扩展，以及在原节点续写状态替换链。导入后继续读取原 Task Board，且源图数据保持一致。迁移测试使用 Lance 原生本地对象，S3 协议由独立后端夹具覆盖。

## SQLite 完整副本与恢复

读取本地副本时传入 `{ fullSqlite: true }`，并调用 `SqliteMemoryBackend.installLegacySnapshot(entities)`。SQLite 在空命名空间的一次事务中提交图、别名、审计和文件引用。旧证据与替换引用保留 ID 和来源会话。读取检查记忆的会话可见性，新关联执行引擎的访问校验。悬空图引用会拒绝安装。休眠与隔离状态随记忆迁入，按 ID 可以读取，普通检索会排除这些记录。节点重定向历史、协作表及派生索引随源 SQLite 保留。

2026-11-15 用主库与项目 STG 的在线备份逐条对照 1,249 条和 3 条记忆 ID。两条路径的 982 条可见结果及主证据一致。主库导入 4,582 个实体，其中有 1,326 条审计事件和 46 条文件引用。精确读取返回活动记忆的 45 条文件引用，另 1 条属于已删除记忆。演练核对导入载荷，验证新写入后重启、凭据重试、恢复新写入后的备份，以及从恢复文件访问 Task Board。契约测试另外在导入中途注入失败，确认实体和索引均回滚后再重试。

## 启用后的本地默认入口

本地 daemon 在公布服务地址前打开统一引擎。新库直接启用统一引擎。已有旧库先在原文件旁创建 SQLite 备份，再在同一事务导入记忆、隔离旧表写入并发布命名空间标记。本地 CLI 直接执行记忆操作时使用相同的转换。主库继续承载 Task Board 和本地运行数据。

需要一次预迁移主库和若干已知项目时，先停止对应 daemon，再运行以下命令。

```sh
nmg daemon migrate --db FILE --project-dir PROJECT_A --project-dir PROJECT_B --json
```

每个文件独立提交并返回备份路径。重跑使用已启用的命名空间。其余已有项目 STG 在首次访问时迁移。项目文件不存在时，读取使用主库。

导出、按 ID 归档及恢复由统一引擎处理。旧链编辑、拓扑变换、保留候选和 STG 缓存同步没有在统一接口注册。

已启用的项目 SQLite 文件提供自己的命名空间。项目文件首次启用且尚无标记时，继承主库命名空间。

本地启用会在事务中导入历史声明结果和后验统计。迁移凭据在升级和重启后保留原来的投票去重键。
已经启用的本地命名空间首次打开时也会导入这些数据。

Codex hook 通过共享会话 Active Graph 读取状态并开始披露回合，通过统一引擎检索项目与共享记忆。精确读取和带版本的答案归因沿用会话隔离。真实副本演练覆盖提示词提交、答案归因、拦截旧写入，以及从同一个 SQLite 备份恢复新记忆和看板条目。

启用[本地统一配置](native-backends.zh-CN.md)时，SQLite 在同一事务按原模型标识导入记录向量。SQLite 继续使用既有节点和叶块向量作为层级信号，新记忆通过记录索引参与检索。配置的 provider 在事务之外分批填充缺失向量。provider 失败后，待填记录可重试，检索会报告降级到词法模式。daemon 公布支持的方法和检索参数。

主库副本演练核对了 1,249 条既有 Gemini 记录向量，并用当前 provider 验证了纯向量、层级 hybrid 和联合 hybrid。新写入的 3,072 维向量在恢复写入后的备份后仍可检索。

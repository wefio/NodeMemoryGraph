# 本地宿主、pi durable 与 Magpie 的 Harness 集成

**Status:** draft
**Authority:** [统一架构](../unified-architecture.zh-CN.md#共享-harness-集成层)

## 职责与所有权

NMG 共享集成层负责召回、披露、反馈和会话隔离。宿主 Harness 拥有 Agent／模型／工具循环及执行生命周期。pi durable 是选定的云端宿主，其 NMG 扩展是宿主绑定。选定宿主不构成集成或部署证据。

组合既有[共享会话流程](../../decisions/implemented/2026-10-16-shared-session-flows.zh-CN.md)、[Agent Surface](../../../src/integration/agent-surface.ts)、[状态接口](../../../src/integration/state.ts)和传输实现，不创建另一套工具 schema 或调度器。共享代码接收端点、身份、能力、截止时间及宿主拥有的集成状态接口。绑定负责翻译原生事件、按共享工具定义注册原生 schema、注入上下文及呈现宿主 UI，不打开记忆 Store。

| 所有者 | 状态与操作 |
| --- | --- |
| Harness | 对话历史、Agent 执行、工具、执行检查点、重试、取消和持久唤醒调度 |
| NMG 共享集成层 | 召回流程、有界回合／任务窗口、披露／反馈记录、会话绑定、截止时间传播、连接复用与清理 |
| 记忆应用服务 | 准入、记忆操作、会话 Active Graph，以及可信租户／会话绑定下的授权披露和归因 |
| 记忆后端 | 存储合同下的持久领域记录、图结构、索引与提交回执 |
| 本地协作服务 | NMG 黑板／任务／运行状态与投递协议；云端记忆接口不提供 |

Harness 的对话／检查点存储与 NMG 记忆存储各有所有者和事务。pi durable 可以用 SQLite 保存执行状态，同时 NMG 选择任一记忆后端。宿主的持久任务或子 Agent 不等同于 NMG Task Board 条目。保持 Agent 执行与图组织的区别。

## 宿主能力与端点选择

能力描述实际行为：回合前拦截、上下文注入、工具结果观察、空闲唤醒及交互命令。不支持的能力必须明确。被动 hook 可以只提供注入，MCP 无须虚构回合前事件。入队回执表示宿主已接受，不代表 Agent 已理解。

本地绑定使用本地 daemon 合同。pi durable 绑定使用配置的认证云端记忆端点，保持相同记忆语义与模型侧工具界面。凭证和租户身份由宿主控制，不是模型填写的参数。端点在解析任何 ID 前检查租户／会话所有权。云端故障不回退到无关本地数据库或另一租户。

保留[适配器指南](../../../skills/nmg-memory/references/harness-adapters.zh-CN.md)的共享 daemon 非所有权、会话状态 fence 与允许的回退规则。仅云端绑定不发现或启动本地 daemon，不宣告 NMG 黑板／运行或本地唤醒能力。只有云端服务实现所有权与隔离合同时，才能开放私有会话 AG 操作。宿主自身的 pi durable 调度独立可用。

[能力矩阵](../harness-capability-matrix.zh-CN.md)拥有已交付覆盖情况。只有适配器实现且具备有范围的证据后，才增加 pi durable 或 Magpie 列；目标设计不表示已发货能力。

## Magpie 网关绑定

[Magpie 集成设计](magpie-integration.zh-CN.md)在原生 Harness 绑定之外增加一个网关候选，区分请求 hook 召回、尽力完成观察及明确连接的记忆工具。Magpie 仍是网关，其客户端拥有 Agent 执行。启用此路径前，身份、协议覆盖和与原生 NMG 插件共存的行为需要验证。

## 组合各接入点的能力

将客户端已配置的原生适配器、MCP 连接、被动 hook、CLI／Skill 访问和其他受支持绑定视为一个可用能力集合，Magpie 向该集合贡献能力。按能力和操作选择提供方，不为整个会话只选一个适配器。客户端可以组合网关回合准备与投递、MCP 精确读取和写入、原生工具见证及共享 AG 状态承载。MCP 和 Magpie 都不必独自提供完整流程。

以 NMG 功能对齐衡量组合：搜索／精确证据、受治理的记忆生命周期动作、召回、维护状态承载、披露／预算接续、受支持的归因／反馈与黑板协作。各提供方使用同一组端到端合同用例。GUI、用量与传输追踪属于独立增强，不计入这些功能缺口的补齐；对齐操作语义和证据质量，不要求界面形式相同。

目标是连接集合能提供的最大已验证覆盖，保留更强的原生能力，明确剩余缺口。CLI／Skill 指令可以支持显式动作，但不能凭空生成自动事件。两个部分实现只有在交接受支持且经过测试后，才构成组合能力。[MCP 与 Magpie 组合草案](magpie-capabilities.zh-CN.md#mcp-与-magpie-组成同一会话)给出一条无需原生插件的交接路径。

每项已启用能力明确提供方、触发点、作用域、证据强度和回退方式。共享集成层按操作选择一个副作用所有者，允许其他来源观察。召回准备、投递、显式工具和可选采集可以由不同接入点承担。断连或重连后切换所有者时，先核对已接受的效果，再决定是否重做。缺少投递证据时保持未知。

组合需要可信映射到相同端点、租户、记忆作用域、对话代次及适用的操作／披露身份，传输连接可以独立。AG 访问和写者 fence 继续由服务控制，模型可见的记忆引用不构成借用其他连接 AG 的权限。具体绑定握手留待实现，不能靠 prompt 文本、目录、模型或显示名匹配建立可信映射。本地黑板等授权边界仍约束所有参与来源。

组合后的能力描述属于绑定会话，适配器矩阵继续描述各提供方。既验证单个适配器，也验证组合及其缺口。表达这种组合不需要增加调度器或第二份记忆／状态存储。

## 云端记忆 API

云端应用边界通过认证 HTTP 提供共享记忆 DTO 与 Agent Surface。必要接口包括检索、精确 get／证据、受治理的 remember／batch／resolution，以及已启用召回功能所需的会话披露／归因操作。写入执行[存储合同](../unified-architecture.zh-CN.md#存储合同)，只宣告已经实现的能力。本地与远程路由不同时，工具名称与字段仍保持共享。

既有 [AML 服务](../../../onlion/backend/memory-service.ts)提供导入／检索应用配置，其 Add/Search 外壳本身不构成完整交互记忆接口。AML 的导入语义继续归自身边界所有；交互接口与 AML 使用同一引擎，不把导入历史当成 Agent 确认陈述。

云端会话所有者可以跨越单次 HTTP 调用。其生命周期必须保留或明确失效 AG／披露句柄及租约；不能每次请求都打开无关的新会话来实现会话状态写入。服务重启可以使句柄过期并返回有类型的拒绝。绑定重建授权会话并重新读取，不借用新写者的 fence 重放旧变更。

## pi durable 绑定

[pi durable 上游合同](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)提供含工具、section、hook 和 task 的扩展。NMG 工具注册与上下文投递使用这些机制，执行器仍是 pi durable。每次宿主打开时重新注册 NMG 扩展，因为保存的扩展名称不能重建进程 registry。固定包版本，在实现映射前验证所选 hook，不假定与 Pi 终端扩展兼容。

把已认证租户、稳定对话身份、分支／reset 代次、获准回合及工具调用绑定到 NMG 会话。同一对话重开保留绑定；fork 和 reset 按会话合同建立不同代次。进程 ID、临时请求 ID 或重连次数不是对话身份。只持久化归因所需的最小映射，不复制另一份对话历史。

通过宿主拥有的接口保存 NMG 集成状态。本地宿主可以使用合适的会话状态；pi durable 使用已提交的对话 document 或任务检查点。保存恢复所需的已完成披露／反馈状态与待处理操作身份。不把凭证或后端读取句柄存进模型可见状态。普通连接缓存可以丢弃。恢复后不能因进程内缓存为空，就认定召回、注入或反馈没有发生。

召回与上下文投递组成可恢复序列：识别回合、取得有界记忆、准备宿主上下文，然后在宿主支持的同一提交中保存上下文投递与集成标记。如果所选 hook 无法原子执行两者，必须定义宿主接受的幂等投递键，并测试崩溃窗口。不能把外部效果完成后独立写入的标记当成无重复注入保证。重放观察到更新记忆版本时，要么在当前授权下复用已持久化的准备上下文，要么明确开始新的披露代次，不静默混合两次观察。过期或撤回的记忆必须在任何新披露前重新校验。

## 外部效果与恢复

pi durable 的恢复不会使远程 NMG 写入与 Harness 检查点成为原子事务。阶段可能在崩溃后重复执行。绑定与云端服务通过以下协议处理，不引入分布式事务：

1. 在发送前，依据可信对话代次、调用及操作槽位生成并保存稳定操作 ID。规范化请求内容在重试间保持一致；相同 ID 携带不同内容必须失败。
2. 将 ID 经云端应用传至存储提交／回执路径。服务端验证并限定其命名空间，不接受模型选择其他租户或任意幂等身份。
3. 记忆服务返回已提交回执后，在宿主提交中保存回执与工具结果。远端提交后、宿主提交前崩溃时，重试相同操作并取回已有回执。
4. 超时或取消表示远端结果尚不明确，直到查询回执或幂等重试确认。客户端停止等待不代表回滚；宿主提交不将尚未确认的远程记忆写入报告为成功。

读取重试可以按读取合同再次执行。写入、归因／反馈及状态变更各自需要明确去重策略；准入 `requestId` 本身不证明每个嵌套外部效果只执行一次。幂等回执保留窗口必须覆盖受支持的持久重放期限。窗口过期时，停止尚未解决的重放并对账，不能换操作 ID 再次冒险写入。

截止时间和 abort 信号传播到远程调用。pi durable 拥有休眠、alarm 和恢复；NMG 召回或轮询循环不能让休眠宿主持续存活。取消、会话变化或宿主重启时丢弃过期进程内工作。关闭绑定只释放自身连接和读取资源，不关闭共享服务。版本升级必须保留或迁移持久集成状态与稳定操作键；没有迁移决策时，不按改变后的语义重放旧工作。

## 启用绑定前的验证

先用确定性模型桩运行合同测试，无须在线模型或供应商费用。固定 pi durable 和端点版本，然后证明：

- 工具注册、有界召回／上下文注入和证据披露使用与本地宿主相同的共享界面。
- 重开、fork、reset 和租户隔离，包括过期 AG 句柄、旧写者 fence 和已撤回证据。
- 远端提交后、宿主检查点前终止进程，以及响应丢失、同 ID 内容冲突和幂等窗口过期。
- 上下文注入和反馈投递前后崩溃，在选定投递协议下只接受一次效果。
- 取消、截止时间到期、不支持能力、registry 重建及持久集成状态迁移。
- 实际目标部署启动、记忆 API 认证与原生后端运行位置；宿主能在 Worker 运行，不证明原生检索库也能在其中运行。

只有这些有范围的结果才能建立适配器能力覆盖。本文件不交付 pi durable 适配器、云端交互 API、崩溃测试或部署。

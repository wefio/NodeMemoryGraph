# 工作状态维护

[English](SKILL.md) · [使用的术语](SKILL.terms.yaml)

保留最小的临时快照，让具备能力的读者根据现有证据选择下一项获授权的操作。工作状态不是日志、第二份任务契约，也不是完成证明。无需阅读 task-semantics 设计文档即可执行本流程。

## 维护当前快照

1. 根据最新用户请求和已完成的工具结果校准可见状态。复用已有信息；只有为解决缺失或冲突事实时才读取 owner 或证据引用。请求变化时替换旧任务；不要把旧任务的待办带入新任务，也不要编造语义任务 ID。新请求也可能结束此前等待用户输入的状态。
2. 根据实际结果检查任何新的完成声明：退出状态、断言、验证范围和相关 owner。工具调用返回、进程仍在运行或产物已写入，都不等于检查通过。区分 planned、attempted、implemented、verified 和 unresolved。未知就保持未知；不要把定向通过扩展成完整验证声明。
3. 只有在删除后可能改变下一步操作、丢失未完成义务、违反约束或隐藏恢复所需证据时，才保留该条目。保留必要的精确值、权限边界、未决假设和可访问的证据引用。详细日志和已完成任务历史属于各自 owner，不属于此快照。
4. 重写完整的当前快照，不要追加进度条目。移除已被取代的观察、已解决的阻碍和无关运行时细节；证据尚未解决时，保留未解决阻碍。只有当当前决策依赖 PID 或测试数量时，才将其放在这里。不要为了达到行数目标删掉必要条件。
5. 只使用任务需要的字段：goal、相关已验证进展、当前步骤、下一步、阻碍、约束或证据。省略空字段和重复的常驻指令。小任务可以只写一句；没有固定模板、字段数或长度能单独证明内容充分。
6. 写入前，检查读者能否不依赖原 Agent 的私有推理，识别下一步操作及其边界。只有当前状态发生实质变化时才写。任务完成后留下简短结果、剩余限制和证据入口，而不是部署叙事。

对 NMG，使用现有的 `nmg_state` AG writer 和完整文本替换。共享的 `memory_policy` 拥有启用、完成和恢复规则。只有在操作、绑定或生命周期需要澄清时，才阅读[工作状态操作说明](../nmg-memory/references/optional-capabilities.zh-CN.md)。不要把秘密或隐藏的思维链写入状态，也不要另建状态存储。

## 现有任务契约

任务具有 contract 或受治理的生命周期时，由其 owner 决定允许的操作和权威事实。引用这些事实；一条状态描述不能批准 deliverable、授予 lease、撤销 cancellation 或解锁依赖。不要仅为了维护单 Agent 快照而创建 run、Task IR 或 board entry。缺少必需证据是一个缺口，不是“什么都没发生”的证据。

[Task-unit semantics](../../docs/design/task-unit-semantics.zh-CN.md) 是了解 NMG 受治理协作的可选背景，不是前置条件、必读文件或本流程依赖的定义。只有实际 managed task 需要解释其 contract 时，才查阅相关的当前 owner。本流程不要求沿用那篇长文的章节布局或 task-schema 字段。

## 小型审查案例

- 定向 check 退出码为 0；完整验证尚未运行。保留定向范围和剩余必需验证，不要写“所有检查都通过”。
- Probe 退出码为 1，但产生了输出。保留失败或不确定性；不要仅因存在产物或工具响应就写“verified”。
- 阻碍已解决，用户又切换任务。删除旧阻碍和待办；只保留与新任务相关的约束和证据。
- 长快照以必要的权限限制结尾。移除无关历史时仍须保留该限制；直接截掉末尾来缩短内容是不安全的。

这些是审查示例，不是已执行的评估，也不是节省 tokens 的证据。

# 记忆质量不变量套件

[English](README.md) | [简体中文](README.zh-CN.md) · [术语](README.terms.yaml)

用以下命令运行：

```powershell
npm run eval:quality
```

这个确定性开发套件覆盖十一个 P1 失败类别：时态状态、多记录聚合、冲突证据、多跳图可达性、精确冷细节、密钥拒绝、瞬时记忆污染、写入门禁边界漂移、为事后“存储缺失”保留的拒绝证据、细化粒度，以及 legacy 候选并集缺失。它在没有 LLM 的情况下测试机制与不变量，因此补充而不是替代 LongMemEval 与 Pi 端到端 agent case。

后四类属于写入侧与检索窗口侧。它们把 NMG 目前无法观测的两个判断——“这条本该被记下来”和“这条记录太模糊”——钉在使其可断言的具体机制上：门禁在两个方向上的边界、每次拒绝都留下会话锚定的事件、细化后仍可读的模糊前身，以及浅层何时开始遮蔽深层的那个边界。

其中两个用例是**预期失败**（已知缺口）：它们断言的是我们想要的行为，而不是代码当前的行为，因此只在缺陷存在时保持绿色。缺陷修好后用例开始通过，整轮变红，必须移除标记。已知缺口单独统计，永远不会被当作普通通过。

# 分层向量粒度评测

[English](README.md) | [简体中文](README.zh-CN.md) · [术语](README.terms.yaml)

在同一份宽节点工作负载上，比较全 MemoryRecord 向量扫描、仅节点路由、节点加
叶子/块路由，以及记录级 USearch ANN。

```powershell
npm run eval:hierarchy
$env:NMG_HIERARCHY_SIZES = "100,1000"
$env:NMG_ANN_CANDIDATES = "64"
$env:NMG_BLOCK_LIMIT = "8"
```

确定性哈希嵌入器是系统基线，不是语义质量主张。在本地嵌入端点可用之后，用 Qwen3
重跑。

## 初始本地结果（哈希基线）

| memories | vectors: records / nodes / leaves | full scan P50 | node+leaf scan P50 | leaf ANN P50 |
|---:|---:|---:|---:|---:|
| 1,000 | 1,000 / 16 / 40 | ~21 ms | ~2 ms | not measured |
| 10,000 | 10,000 / 16 / 328 | ~524 ms | ~9–10 ms | ~5 ms |
| 100,000 | 100,000 / 16 / 3,144 | ~9.1 s | ~80–88 ms | ~12–18 ms |

在 100K 时，节点加叶子头使用的向量约为按记录向量化的 31.6 分之一。哈希召回不稳定：
仅节点达到 37.5%；节点加叶子扫描达到约 62.5–75%；叶子 ANN 从 Top-64 的 25% 到
Top-512 的 50%。记录 ANN 在近似重复的干扰项中也严重退化。这些是有用的负结果：
分层索引解决了扩展成本，但无法补偿弱的语义表示。在选择生产候选预算或选择性记录
回退策略之前，必须先测试 Qwen3。

## Qwen3 结果

通过本地 vLLM 使用 `Qwen/Qwen3-Embedding-0.6B`，精确的节点加叶子检索在 100、1K
与 10K 记忆上对同样八个用例达到 100%。在 10K 时它使用 16 个节点向量加 328 个
叶子向量，而不是 10,000 个记录向量。这支持把节点加叶子头作为默认语义索引。

当前的 USearch 叶子 ANN 没有保住那个召回：在近似重复工作负载上 Top-64/128/256
在 62.5% 到 75% 之间，而近乎穷举的 Top-512 恢复到 100%。在 ANN 构建/搜索被单独
标定之前，NMG 在此规模下应精确扫描一份缓存叶子向量矩阵，并把记录向量保留给选择性
回退。不要把当前的 ANN 结果当作 Qwen 嵌入失败。

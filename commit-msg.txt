fix(pi): register the round tool by default

The environment gate was wrong, and the review called it correctly: a consumer that has to be
switched on is not a consumer, and I had effectively kept the tool out of my own sessions while
describing it as the thing that makes the shared layer reachable.

The tool is now registered unconditionally, like `nmg_search`, `nmg_remember` and `nmg_board`. The
real cost boundary stays where it belongs, per call: `live` is the switch that spends tokens, and it
is absent unless asked for, so the default replays recorded answers and spends nothing.

Two mechanical consequences, both of which would have caught the mistake:

- The extension suite asserts the exact tool inventory twice, and both assertions now have to name
  `ooo_round`; they failed until they did. The inventory test is the reason this change is provable
  rather than asserted.
- The registry entry for the round entry point no longer claims a session-surface gate. The `evals/`
  CLI row stays registered as a non-default capability, because that is still true of the CLI.

Evidence: extension suite 47/47, adapter tests 3/3 (the gate test is gone with the gate), `tsc
--noEmit` clean, ESLint clean, LSP 0 diagnostics, `docs:check` clean.
